PHASE 12 — 수정 runtime의 실제 Inspector 입력·종료 반복 (2026-10-10)

게시 직전 원본 비교 보강 이후의 Debug/Release runtime에서 실제 숫자 입력과 저장 대기 중 외부 설정 변경·종료를 각각3회, 총6개의 독립 Editor 프로세스로 검증했다. 이번 실행에는 제품 소스 변경이나 추가 빌드가 없으며 직전 빌드 산출물을 사용했다.

§00

방법과 범위

start-texture-auto-ui.ps1로 격리된 Tiny4/SavedFixture 프로젝트를 매번 새로 만들었다. 씬을 열고 UnsavedT0Texture를 생성한 뒤 실제 Windows UI로 fixture.png를 선택하고 Maximum Dimension의0을 선택한 화면을 확인했다. 매회 실제 숫자 키2를 입력했다.

assets.texture.pendingprobe conflictshutdown은 입력을 생성하지 않는다. 실제 입력으로 생긴 저장 대기를 관찰한 뒤 400ms 전에 외부 maxDimension1을 쓰고 RequestQuit을 호출한다. Editor의 종료 flush·Finalize를 거쳐 프로세스가 종료될 때까지 기다렸다. 종료 요청은 이 관찰기의 API 호출이며 네이티브 닫기 버튼 반복 검증은 아니다. 이번 외부 변경은 최초 큐 비교 전에 주입되므로 게시 직전 비교 이후 경합의 증거가 아니다.

매회 종료 코드0, 외부 maxDimension1/GUID 보존, 원본 PNG·저장 씬 보존, flush 이후 Finalize와 DX12 pending task/batch/retirement0/0/0, 실행 전후 runtime hash 일치를 확인했다. 화면에는 종료 직전까지 미저장 객체가 있었으며 종료 후 그 객체를 저장했다고 주장하지 않는다. 입력4파일의 전후 hash를 대조해 sourceDrift0을 확인했다.

§02

수용과 잔여

최신 runtime의 실제 숫자 입력과 제어된 유효 외부 설정 충돌·종료를 구성당3회로 한정 수용한다. 다른 실패 유형·붙여넣기·네이티브 닫기 버튼의 반복, 다중 창/배율, 장시간·성능/누수와 전체 소비자/GPU는 추가 범위다. 마지막 디스크 비교 이후 동시 쓰기도 미해결이다. 12-0-D 후속 검증으로 추가 공수를 중복 계상하지 않으며66.25%(표시66%)를 유지한다.
