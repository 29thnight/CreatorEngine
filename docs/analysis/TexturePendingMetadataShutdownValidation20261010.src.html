이전 근거의 유효 범위

기존 세부 계약은 위 현행 구현과 모순되지 않는 범위에서 유지한다. 과거 수치·실행 통과·해시·장치 조건은 당시 기록이다. 로컬 산출물이 사라진 항목은 링크 대신 경로와 미보존 상태를 표시하며, 현재 master의 재실행 통과로 승격하지 않는다.

세부 계약·원래 분석과 당시 측정 기록

실제 Inspector에서 Maximum Dimension을0→2로 입력한 뒤, 저장 대기400ms 전에 격리 metadata를 삭제/손상시키고 같은 owner-thread 관찰에서 RequestQuit을 요청했다. deleteshutdown/corruptshutdown 검증 모드와 도우미 선택지를 추가했으며 제품의 자동 저장/종료 구현은 변경하지 않았다. 미검증이던 Debug 유효 외부 설정 변경·종료도 기존 conflictshutdown 모드로 확인했다. 각 모드는 한 번의 제어된 실행이다.

구성 모드 요청 age 종료 flush age 종료 후 외부 상태 종료 코드
Debug 삭제+종료 10ms 41ms metadata 없음, 재생성 금지 0
Debug 손상+종료 4ms 28ms 주입한 손상 bytes 그대로 0
Debug 유효 변경+종료 3ms 36ms 외부 maxDimension1/GUID 유지 0
Release 삭제+종료 7ms 27ms metadata 없음, 재생성 금지 0
Release 손상+종료 8ms 29ms 주입한 손상 bytes 그대로 0

다섯 실행 모두 해당 metadata에 대한 AUTOSAVE_FLUSH 다음 AUTOSAVE_CONFLICT를 기록해 대기 편집2를 쓰지 않았다. 정상 Finalize와 DX12 shutdown pending task/batch/retirement0/0/0을 확인했다. 원본 PNG 및 저장 씬 bytes가 유지됐고 runtime SHA-256이 실행 전후 일치했다. 종료 전 실제 화면에 미저장 UnsavedT0Texture 객체가 있는 상태에서 입력했다. 미저장 객체의 종료 후 재실행 복구 수용은 아니다. 종료 뒤 UI 오류 표시·Reload는 이 실행에서 확인하지 않으며 일반 저장 대기의 기존 복구 수용과 구분한다.

verify-texture-auto-ui-shutdown.ps1은 실행 root의 launch/command/exit receipt와 로그를 읽어 종료 코드, 요청 age400ms 미만, 해당 파일의 flush/충돌 및 최종 외부 상태, PNG/저장 씬/runtime 보존과 종료 큐를 검증한다. 실제 입력을 생성하는 스크립트는 아니다. exit.json은 실행 중 해당 프로세스 handle을 열어 WaitForExit 후 기록한 종료 결과다. Build 증거는 로컬 산출물이며 청소 시 제거될 수 있다.

12-0-D 후속 보강으로 추가 가중치를 계상하지 않는다. 진행률13.25/20일 = 66.25% (표시66%) 및 T1b 대기·T3 중단을 유지한다. 최종 디스크 비교 이후 동시 쓰기, 반복/장시간·다중 창/배율 및 전체 소비자/GPU/품질은 잔여다. 이 제어된 실행은 실제 OS 창 닫기/강제 종료, 임의 타이밍의 스트레스나 성능 수용으로 확대하지 않는다.
