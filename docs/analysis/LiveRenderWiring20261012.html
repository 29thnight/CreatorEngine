이전 단계: A2 전체 메시 교체 계층 쿠킹 + GPU LOD (2026-10-15)

모든 쿠킹 LOD의 메시렛을 같은 봉인된 기하·포즈·프레임 조회 테이블에 담는다. CPU 카메라 LOD 선택기와 그림자 전용 LOD0 준비를 제거했다. GPU 컬링이 투영 오차·월드 스케일·교체 계층을 읽어 한 LOD의 메시렛만 최종 목록에 발행한다. 카메라 첫 목록과 복구 목록은 같은 선택 계약을 사용하며, 그림자는 실제 캐스케이드 해상도와 light projection으로 독립 선택한다. 해상도를 제공하지 않은 검사 입력은 오차 예산 0(원본 상세도)을 명시한다.

03METEOR 단계 객체와 실제 내부 패스

각 단계 Declare는 봉인된 FrameInput과 명시된 생산자 값을 받는다. 다른 단계 객체를 통해 결과를 조회하지 않는다. LayerStage가 레이어 명령·타깃·래스터, VolumeStage가 볼륨 합성과 매질 바인딩을 수행한다. EffectStage는 Color와 효과의 의미상 순서를 조립하며 Runtime/Decal/Lookup 상태를 분리해 소유한다. 실제 리소스 의존성은 RenderPassGraph에 남는다.

Geometry 내부의 버퍼 소유권과 인스턴스 입력

아래는 추가 노드가 아닌 기존 GeometryStage 내부의 자원 관계다. 동일 기하·포즈·파이프라인의 인스턴스는 생산자 하나의 버퍼와 동일한 그래프 버전을 읽는다. 다른 포즈는 별도 출력을 갖는다. 인스턴스별 frame record와 현재/이전 월드 상수는 합치지 않는다. 완료 출력 재사용 프레임에는 첫 뷰가 import를 소유하며 나머지 뷰가 그 버전을 공유한다.

05해결한 문제와 남은 문제

  • 해결 1 — PostChain 병렬 기록과 GPU 기반 validation. GPU 기반 validation(CREATOR_DX12_VALIDATION=gpu)에서 PostChain.ToneMapped가 COMMON 레이아웃 그대로 UAV로 디스패치된다는 오류가 간헐적으로 났다(약 7회에 1회). 포인터 단위 로그로 보니 그래프 계획과 기록된 배리어는 정상이었다. 오류는 transient pool 없이 매 프레임 RT+UAV 텍스처를 새로 만드는 RG5 final 테스트에서만 났다. 테스트에 RGTransientPool을 붙이자 25/25 통과했다. DeclareRecordingIndependent를 빼서 고쳐진 것처럼 보였던 한 번의 결과는 간헐성 때문이었고, 그 변경은 되돌렸다. 수정: EnhancedFinalRg5Tests.h.
  • 해결 2 — DirectionalLightGizmo 첫 드로우의 COPY_DEST 레이아웃. 테스트 뒤 라이브 장면까지 도는 전체 Debug 검증에서 약 2회에 1회, 갓 업로드한 기즈모 텍스처의 첫 드로우가 LEGACY_COPY_DEST 레이아웃으로 보고됐다. 업로드는 같은 큐에서 먼저 제출됐고(fence 16 → 17), 오류는 첫 사용 때 한 번만 났다. 이후 약 1000프레임은 깨끗했다. DX12TextureCache가 업로드 텍스처를 COPY_DEST 대신 COMMON으로 만들게 바꿨다. 복사가 일어나면 COPY_DEST로 자동 전환되고, 그 뒤 배리어는 그대로다. 수정 후 전체 Debug 검증 4회와 Release 1회에서 오류 0건이었다. 원인은 GBV가 새 리소스를 생성 시 상태로 추적하는 방식으로 추정하며, 증명하지는 못했다. 엔진은 Agility SDK 없이 OS 기본 런타임을 쓴다.
  • 해결 3 — 머티리얼 프로브(b13695122). 프로브는 컷오버 이전 구조를 전제했다. 합성 메시에는 쿠킹된 메시렛이 없었고, Scene 테스트는 호스트가 더 이상 런타임에 컴파일하지 않는 surface product를 넣었다.
    • Tools/regression/support/CookedMeshFixture.h가 합성 메시를 메시렛이 있는 granular payload로 쿠킹하고 Scene seal의 pin 테이블을 만든다. GraphSceneFixture도 이 헬퍼를 쓴다.
    • Scene 테스트의 머티리얼은 AssetCooker와 같은 CompileSceneProduct로 쿠킹한다. 리로드는 재쿠킹이고, 잘못된 셰이더는 쿠커 단계에서 거부된다.
    • transform 셰이더(MaterialGraphMeshSurface.slang)의 불필요한 NonUniformResourceIndex를 지웠다(SPIR-V spirv_1_3 초과). 샘플 출력도 u4096으로 옮겨 transform 출력 테이블(u0..u4095)과 겹치지 않게 했다.
    • 모드별 게이트 verify-material-scene-probes.ps1를 추가했다. 기본 모드와 12개 모드가 Debug·Release에서 통과하고, scene-cook, matched 이미지, shadermeta 게이트도 통과한다.
  • 해결 4 — 저작 머티리얼 캐시(fd2875b77). 저작 컴파일은 격리된 임시 디렉터리에서 돈다. 그런데 검증된 product 캐시가 그 안에 쓰였고, 의존 목록에는 지워질 생성 소스가 들어갔다. 그래서 머티리얼을 다시 열 때마다 Scene 24단계를 전부 다시 컴파일했다. 이제 캐시는 고정된 Lattice 디렉터리에 남고 생성 소스는 의존 목록에서 빠진다. 다시 열 때 재컴파일은 0회다.
