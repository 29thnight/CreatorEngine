그림자 2단계 컬링과 정적 깊이 캐시

방향광 3개 캐스케이드마다 완료된 이전 HZB로 1차 판정하고, 정적 깊이와 1차 동적 캐스터로 현재 HZB를 만든다. 현재 HZB로 제외 후보를 복구해 1차 생존 목록과 합친다. 최종 맵은 정적 깊이를 depth-Less로 합성한 뒤 동적 캐스터를 그리며, 다음 프레임 이력은 최종 깊이에서 생성한다.

04큐 작업 수 완료 관리와 뷰 간 공유 ring

각 기하 인스턴스 bin을 16개 논리 분할로 배정하고, 활성 lane마다 메시릿 하나를 ring에 넣고 회수한다. CPU는 bin별 범위·입력·PSO만 준비한다. Reset은 목록과 ring을 초기화한다. 같은 Cull dispatch에서 wave가 초기 분할을 가져오고 lane별 생산·소비를 반복한다. 준비된 여러 뷰가 같은 ring의 job을 생산·소비하며 결과는 해당 뷰의 목록으로 보낸다.

RE 원문과의 대응 범위

RE 발표의 16분할 코드는 초기 고정 분배 방식이고, 후반 ring 방식은 이를 개선한 비교 대상이다. 공개 자료만으로 최신 RE 내부가 두 방식을 그대로 결합한다고 단정할 수 없다. 현재 구현은 공개된 16분할 공식과 lane별 CAS/atomic ring 연산을 기존 기하 bin 인터페이스에 결합했다. JOB_COUNT 게시 증가·회수 감소는 공개 ring 코드에 대응한다. 생산 소진·처리 중 작업 확인은 현재의 유한 입력에 맞춘 종료 프로토콜이다. 뷰 간 공유는 사용자 요청으로 추가한 확장이며 발표에서 RE가 같은 공유 범위를 사용한다고 확인된 것은 아니다. bin은 월드·기하·청크를 가진 GPU 인스턴스 단위이며 여러 bin을 가진 GameObject 전체를 하나로 합치지는 않는다.

경계구현 계약
초기 배정bounded CAS의 초기 cursor는 bin × 16 범위에서 멈춘다. partition / 16이 bin, partition % 16이 분할 번호 s다. 16은 논리 분할 수이며 실제 하드웨어 wave 폭·전체 dispatch 크기와 구별한다. 생산 dispatch는 min(bin × 16, 128) threadgroup이다.
분할 공식메시릿 수 M, 활성 폭 W에 대해 M ≥ 16W이면 기본 길이 floor(M/16), 시작은 기본 길이 × s이고 마지막 분할은 나머지를 포함한다. M < 16W이면 시작 W × s, 길이 min(max(M − 시작, 0), W)다. 작은 입력·빈 bin·마지막 나머지를 누락 없이 처리한다. 부분 wave는 활성 lane 순위·개수를 사용한다.
lane별 생산분할을 받은 wave가 최대 W개의 메시릿을 각 lane에 하나씩 배정한다. pending이 있는 lane만 WaveActiveCountBits·WavePrefixCountBits에 참여한다. leader가 참여 lane 수만큼 tail을 한 번 예약하고 각 lane이 자기 슬롯에 CAS로 게시한다. 삽입 실패는 해당 lane이 pending을 유지한다. 기존 pending이 모두 게시된 뒤 다음 source 묶음을 배정한다.
lane별 소비leader가 활성 lane 수만큼 head를 예약하고 각 lane이 prefix 위치의 슬롯을 atomic min(0)으로 회수·반환한다. 하나의 job은 메시릿 하나다. 공유 큐에서는 전체 bin의 누적 메시릿 번호를 nonzero 32비트 값으로 인코딩하고 소비 시 bin·view·로컬 출력 위치를 복원한다. 단일 뷰 경로는 기존 public ID 주소 인코딩을 유지한다. 소비 lane마다 서로 다른 bin을 선택할 수 있어 모든 기하 descriptor 접근에 NonUniformResourceIndex를 사용한다. 큐는 FIFO 출력 순서를 보장하지 않는다.
진행·완료각 resident wave가 생산과 소비를 모두 시도한다. 가득 찬 슬롯의 CAS 실패도 소비를 막지 않으며 빈 회수도 종료로 간주하지 않는다. 성공한 게시 lane 수만큼 JOB_COUNT를 더하고 실제 회수한 job 수만큼 뺀다. 초기 bin × 16 분할 소진, JOB_COUNT=0, 생산 lease=0을 함께 확인한다. 각 wave는 자신이 회수한 작업을 완료한 뒤에만 다음 종료 검사로 들어가며 로컬 pending·분할도 비어야 한다. 소비 중 수는 종료 후 0을 검사하는 진단값이다. 모든 wave가 동시에 소비 유휴 상태가 되기를 기다리지 않는다. 전체 메시릿 수·완료 누계는 진단용이며 종료 조건이 아니다. 빈 회수 한 번으로 완료를 판정하지 않는다.
동기화·출력게시 데이터는 atomic 슬롯 하나에 완결되며 원본 범위·기하는 dispatch 전에 밀봉한다. atomic을 별도 payload의 메모리 배리어로 간주하지 않는다. Reset → Cull → Finalize는 기존 RenderGraph 버전·UAV 배리어를 사용한다. 불투명 결과는 ID 집합·간접 인자를 유지하고 정렬 결과는 Finalize에서 원본 순서로 압축한다. LayerWork는 결과 소비자다.
저장소·소유권header 16워드 + ring 256워드 = 1,088바이트다. 공유 묶음은 별도 UAV 한 개를 사용하고, 단일 뷰는 기존 ID UAV 뒤쪽을 사용한다. 공개 ID slice에는 ring을 노출하지 않는다. 묶음의 Frame들과 graph callback·upload transaction이 완료/거절까지 수명을 유지한다. 각 준비의 기존 32 MiB 예산을 유지하며 공유 묶음의 추가 ring·입력 upload는 별도다.
적용·범위카메라+그림자 3개 뷰의 1차, 그림자 3개 복구, 정적 캐시 miss 3개를 각각 준비 완료 묶음으로 공유한다. 묶음별 Reset/Cull/Finalize 각각 한 dispatch이며 lane이 서로 다른 뷰의 작업을 처리할 수 있다. 카메라 현재 깊이 복구와 정렬 반투명은 별도다. 최대 8뷰/4096 bin을 넘으면 여러 묶음으로 분할한다. 서로 다른 graph·upload recording을 공유하지 않는다. Core 35 + Editor 4 = 39 상위 노드는 유지한다. 128 group·256슬롯은 성능 측정으로 선택한 최적값이 아니다.

고정 64개 범위 경로는 원시 셰이더 회귀 기준으로만 유지한다. 근거: REAC 2025 발표의 초기 16분할 코드와 개선 ring 코드, HLSL CAS. 초기 분할·lane별 ring 원리를 대응시켰으며 RE 최신 스케줄러 전체의 복제·동등 성능·비동기 중첩을 입증한 것은 아니다.

클러스터 스트리밍·속성별 양자화·GPU 직접 소비

QMC1은 메시릿마다 독립 속성 패킷을 저장하고 내부 CGQ1이 상수·고정소수점·raw32를 선택한다. 위치·UV·가중치는 최대 16비트, 법선·접선은 최대 10비트, 색은 최대 8비트를 시도한다. 성분별 허용 오차는 위치/UV 0.0001, 법선/접선/색 0.002, 가중치 0.00001이다. 본 인덱스는 정확히 보존한다. UV1·색의 저장과 원시 GPU 접근을 지원하며 기존 머티리얼 입력 의미는 유지한다. 범위·오차 조건에 맞지 않는 성분은 Float32로 유지한다. 법선은 성분 양자화다. 스칼라별 메타데이터를 쓰는 QMC1/CGQ1 형식은 RE의 속성 플래그 패킹이나 비공개 법선 인코딩과 같은 바이너리 형식이 아니다.

공유 정점은 메시 전체에서 같은 양자화 격자를 사용하므로 메시릿 경계의 복제 정점이 같은 비트로 복원된다. GPU 계층 경계·오차에는 위치 양자화 오차를 보수적으로 더한다. 현재 .cege 버전 9는 CPU 전용 파일의 크기·SHA-256을 인증하며, 인증된 thin metadata → QMC2 페이지 순서다. 전체 원본 기하 본문은 저장하지 않는다. 스트리밍 GPU 토폴로지는 schema 6/112바이트 헤더와 페이지 주소 테이블을 사용하고, 기존 raw 경로는 schema 5를 유지한다. SceneHost shader identity 39는 유지하며 CEGE9 스키마로 재쿠킹한다. Editor는 기하 배열을 제외한 metadata.cemc를 읽고, 전체 model.cemc는 더 이상 게시하지 않는다.

런타임은 캡처한 loose/pak 파일 소유권을 유지하고 페이지 범위를 읽어 SHA-256을 확인한다. 루트는 먼저 상주시켜 대체 출력을 보장하며 하위 페이지는 제한된 비동기 읽기 큐로 요청한다. 교체 그룹의 마지막 페이지가 준비된 뒤에만 그룹을 공개한다. 지연·실패·퇴거 중에는 GPU LOD가 상위의 완성된 그룹을 선택한다. 같은 recording의 뷰는 불변 상주 스냅샷을 공유하고 제출된 버퍼의 소유권은 GPU 완료/거절까지 유지한다.

상주 압축 페이지와 작은 포즈 패킷을 업로드한다. 카메라/그림자 컬링, HW/SW 가시성, 표면 복원과 Temporal의 공통 접근 함수가 필요한 속성을 GPU에서 복원하고 스키닝한다. Scene 경로에서는 정점당 80바이트의 전체 SurfacePoint 버퍼를 미리 펼치지 않는다. 기존 독립 변환 경로는 호환용으로 남는다. 상위 노드는 유지하며 내부에 ClusterPoseUpload → ClusterGeometryReady를 연결한다.

후속 SceneHost 37: DX12의 지원 장치에서는 chunk의 가상 버퍼 주소와 메타데이터/패킷 주소를 고정하고 64 KiB 물리 타일을 매핑·해제한다. 큐 매핑은 RHI 제출 FIFO를 따르며 매핑 완료 fence까지 리소스·heap·예산 소유권을 유지한다. 재사용 후 접근에는 aliasing barrier를 둔다. 현재는 패킷을 16바이트 정렬로 packing하고 별도 전역 물리 타일 예산을 적용한다. GPU가 상주 여부와 독립적으로 원하는 LOD cut의 요구 비트를 기록하고, 완료된 뷰의 readback을 다음 recording의 CPU 거리 prefetch보다 우선 처리한다. 화면 밖 요구도 포함하는 보수적 LOD 피드백이며 GPU page-fault 처리와 같지 않다.

물리 heap 생성은 장치 공통 VRAM coordinator의 성장 예약·확정·해제에 참여한다. 현재는 장치별 64 MiB 공유 heap과 자산별 Reserved Resource를 사용한다. 완료·비참조 자산의 페이지를 선택/루트/메타데이터 우선순위와 최근 사용 순서로 재분배한다. 실제 GPU 사용 중인 자산은 퇴거하지 않는다. 압력 시 idle 캐시를 정리하고 CPU 상주 선택도 루트로 줄인다. 작은 압축 패킷은 16바이트 정렬로 모으며, 고정 메타데이터 구간과 마지막 타일의 여유 공간은 남는다. 동적 heap 성장·축소와 활성 작업 집합의 예산 초과 시 자동 LOD 하향은 별도다.

현재 한계: CEGE9의 정본 m<메타데이터 SHA-256> 경로에서는 최초 헤더·thin descriptor/DAG 테이블만 읽는다. 정점·인덱스·연결정보는 초기 CPU descriptor에 보관하지 않는다. QMC2 페이지는 QMC1 속성과 연결정보를 함께 담고 페이지별 해시·범위·속성·본·경계를 검증한 뒤 GPU가 직접 소비한다. collider는 별도 CECP 파일의 정확한 위치·인덱스만 읽는다. 전체 원본 본문과 QMC2 tail의 중복 저장은 제거했다. 명시적 CPU 확장 요청은 현재 페이지를 복원하며 정확한 원본 속성 API가 아니다. 기본 1 MiB는 recording당 새 페이지 수용 예산으로 전체 실제 전송량 상한이 아니다. 상주 revision 갱신은 변경 메타데이터와 신규·재매핑 패킷만 전송한다. 루트 최초 수용은 새 페이지 예산을 초과할 수 있다. 미지원 백엔드는 기존 불변 버퍼 경로를 사용한다. 지원 DX12에서는 작은 패킷 예산도 공유 sparse 경로를 사용한다. 새 Editor GLB 임포트는 메타데이터 envelope와 CEGE9를 게시한다. 구형 CEGE·generation과 메타데이터 해시 경로가 없는 입력은 거부한다. 현재 SceneHost 39의 D/R 및 Editor 수용 범위는 위 검증 표를 따른다. 대규모 패키지·Vulkan·성능 수용도 별도다.
