PHASE 12 — 저장 대기 중 metadata 삭제·손상 UI 검증 (2026-10-10)

§00

검증 방법과 범위

실제 Inspector의 Maximum Dimension 숫자 입력으로 자동 저장을 대기시킨 뒤, assets.texture.pendingprobe가 owner thread에서 400ms 전에 외부 삭제 또는 손상을 주입했다. 숫자 편집과 Reload는 실제 Editor UI 조작이고, 파일 실패 주입은 .texture-auto-ui-race 표시가 있는 격리 프로젝트의 fixture.png.meta에 한정한다. 검증 모드 delete/corrupt와 실행 도우미의 해당 선택지를 추가했다. 제품 저장 경로의 구현은 이번 검증에서 변경하지 않았다.

대기 항목이 소진된 후 750ms 동안 외부 상태를 확인한다. 삭제는 파일이 없는 상태, 손상은 주입한 bytes 그대로여야 하며 자동 저장 오류가 있어야 성공이다. 각 모드는 구성별 한 번의 제어된 경합이다. 반복/장시간, 최종 디스크 비교 이후 쓰기, 삭제·손상과 동시에 종료하는 경합, 다중 창/배율, GPU pixel oracle은 포함하지 않는다.

§01

Debug 결과

모드대기 중 주입 시점결과
delete9ms삭제 상태 유지, 암묵적 재생성 없음, 자동 저장 거부
corrupt3ms손상 bytes 유지, 자동 저장 거부

두 경우 Inspector가 The source changed on disk; pending edits were not written.를 표시하고 draft 값2와 미저장 UnsavedT0Texture 객체를 유지했다. 정상 baseline metadata를 복원한 뒤 실제 Reload로 디스크 값0을 읽고 오류를 해제했다. 새 숫자2 입력의 자동 저장을 확인했고 PNG/GUID 및 저장 씬은 유지됐다. 정상 Finalize와 DX12 shutdown pending task/batch/retirement 0/0/0을 확인했다. 삭제·손상 거부 직후의 기존 렌더링 유지 여부는 별도 GPU 판정으로 계상하지 않는다.

Debug Editor 라이브러리/runtime/launcher 빌드는 통과했다. 두 UI 실행의 runtime SHA-256은 D84ED3C42CDF5762F6D9CD77D18FDF0398D9F4C1AE69FA2CA3F234DD88BB1C56이며 실행 전후 동일했다.

  • 삭제 오류, draft 유지
  • 삭제 복구 Reload, 새 편집
  • 손상 경합 명령 receipt

§02

Release 결과

모드대기 중 주입 시점결과
delete7ms삭제 상태 유지, 암묵적 재생성 없음, 자동 저장 거부

Debug와 같은 실제 UI 절차로 오류 표시·draft2·미저장 객체 보존, baseline 복원 후 Reload0/오류 해제 및 새 편집 자동 저장2를 확인했다. PNG/GUID·저장 씬을 유지하고 정상 Finalize 및 DX12 pending0/0/0으로 종료했다. Release Editor 라이브러리/runtime/launcher 빌드는 통과했으며 최종 연결은 다른 LTCG 연결과 겹치지 않게 진행했다. 두 실행 runtime SHA-256은 C7A889DA079940476467389CBCCA8E3DA4D2109205E9C21DA63ED5F00C4C11EC이며 실행 전후 동일했다.

  • Release receipt
  • 삭제 경합 명령 receipt
  • 삭제 오류, draft 유지
  • 삭제 복구 Reload, 새 편집
  • 손상 경합 명령 receipt
  • 손상 오류, draft 유지
  • 손상 복구 Reload, 새 편집

Build 아래 receipt와 화면은 로컬 검증 산출물이며 청소 시 제거될 수 있다. 이번 증거는 12-0-D 파일 실패·복구 UI 수용의 후속 보강이다. 별도 가중치를 중복 계상하지 않고 13.25/20일 = 66.25% (표시66%)를 유지한다.
