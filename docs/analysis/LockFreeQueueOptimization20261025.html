분석

락 프리 큐 병목 분리·최적화 수용 (2026-10-25)

독립 성능 게이트: PASS. 기본 push/try_pop API의 6개 조건을 비교했다. 프로세스 5회 각각의 전송 중앙값과 큐 소멸 포함 중앙값이 모두 PPL의 1.10배 이내인지 판정한다. 토큰 전용 경로나 할당을 뺀 공개 경로의 수치로 대체하지 않았다. 엔진의 기존 PPL 별칭은 바꾸지 않았다.

§00

원인을 실제로 분리한 방법

이전 MS 연결 큐의 소스·실행 파일은 baseline/20261025-before-profile에 보존했다. 같은 계측 코드에서 할당, 레코드 확보, 두 hazard 경로, 공개/제거/퇴역 CAS, 회수 전체, 개별 해제를 기록했다. 스레드별 64회당 1회만 RDTSCP로 표본을 취하고 컴파일러 장벽·LFENCE로 경계를 고정했다. 계측은 별도 바이너리에서 수행하고 최종 성능은 계측을 끈 실행 파일로 비교했다.

아래는 생산자당 100,000개, 총 400,000개를 전달한 별도의 8B·4생산자·1소비자 진단 실행이다.

타이머 쌍 평균은 이전 42.82 cycles, 최종 43.98 cycles다. scope 평균은 이 비용을 포함한 원시 관측치다. 중첩·병렬 구간이 있으므로 합산해 벽시계 기여율로 만들지 않는다. 공개 CAS는 이전의 노드 연결과 최종 슬롯 공개이며, 세그먼트 연결 CAS 재시도는 이 항목에 포함하지 않았다. 이전 할당 scope에는 작은 노드와 T 생성, 최종에는 슬랩/세그먼트 생성이 들어가므로 평균 1회 비용을 동일한 단위 작업으로 해석하지 않는다. 회수는 배치 CAS와 세그먼트 해제를 여전히 포함한다. PMU 캐시 미스는 측정하지 않았다.

관측 결과를 반영한 변경:

  • 원소별 heap 할당/해제를 값 크기에 따른 슬롯 묶음의 슬랩과 재사용으로 바꿨다. pop은 값 이동과 T 소멸을 즉시 끝내며 저장 공간만 재사용한다.
  • 반복되는 전역 노드 연결 CAS를 FAA 배열 세그먼트로 바꿨다. 생산자가 예약 뒤 멈추면 소비자는 빈 슬롯을 taken으로 표시하고 진행한다. 늦은 생산자는 공개에 실패해 다른 슬롯에서 재시도한다. 새 세그먼트에는 첫 값을 미리 준비하여 빈 예약을 서로 건너뛰는 상황에서도 진행하도록 한다.
  • 슬롯에서 포인터를 가져간 소비자만 값 저장소를 소유하므로 두 번째 hazard를 없앴다. hazard는 세그먼트 수명에 사용하며 검증 없이 해제하지 않는다.
  • 호출마다 레코드를 CAS로 확보하는 대신 스레드별 등록을 쓴다. TLS에 큐 주소가 없으므로 큐가 먼저 파괴돼도 종료 콜백이 그 큐를 만지지 않는다. 보호 대상 변경·회수 때 조회 경계도 초기화한다.
  • 재사용 목록 전체를 atomic exchange로 넘겨 소유권을 분리한다. live/slab 표시는 정렬된 포인터 하위 비트의 사유 메타데이터이며 ABA 세대 번호가 아니다.
  • 소멸 때 슬랩이 이미 소유한 캐시 노드 목록을 다시 걷던 중복 비용도 없앴다. 독립 prepared 노드가 섞인 경우에는 보수적인 정리 경로를 유지한다.

§01

같은 조건의 PPL 수용 측정

Windows 11 Pro 10.0.26300, i7-8700K 6C/12T, MSVC 19.50.35730 / STL 145, x64 Release /O2 /Ob3 /MD, iterator debug 0, C++23 요청. 이전 구현도 같은 옵션으로 재컴파일했고, 각 실행 파일 안의 자체 큐와 PPL에 동일한 옵션을 적용했다.

생산자당 65,536개, 워밍업 2회, 표본 15개, A/B 순서 교대, 독립 프로세스 5회다. 이전/최종 프로세스 순서도 교대했다. 값 생성과 모든 payload 워드의 체크섬을 양쪽에 동일하게 넣었다. 기본 push/pop과 성공 pop 64회마다 수행하는 회수를 포함한다. 토큰, 사전 원소 할당, 메모리 풀 예열을 사용하지 않았다. 최초 스레드 등록과 종료도 데이터 전송·join 측정에 포함된다.

단위는 원소당 ns. 비율은 프로세스별 중앙값 비율 5개의 중앙값이며 범위는 그 5개 비율의 최소~최대다. 8/4/1은 8B 값·4생산자·1소비자다. 1 미만이면 자체 큐가 빠르다.

큐 생성과 스레드 생성은 타이머 밖이며 전송에는 시작 신호·데이터 전달·join을 포함한다. 큐 객체까지 실제로 파괴하는 비용을 별도로 재서 합쳤다. 소멸 포함 열은 정리 작업을 측정 밖으로 옮긴 효과도 점검한다. 콜드 캐시·p99·다른 PC의 절대 성능 보장은 아니다. 다른 프로그램, 전원 정책, affinity는 바꾸지 않았다. Linux 검증과 Windows 성능 측정은 동시에 실행하지 않았다.

§02

메모리 정책

8B 값 슬롯은 실제 16B, 256개 슬롯 블록은 4104B, 세그먼트는 2240B, 기본 큐 객체는 4480B다. 다음은 진단 실행에서 센 생성·해제와 sizeof로 계산한 종료 직전 요청 바이트다. 최초 세그먼트 1개를 포함하며 CRT 관리 정보·RSS·실행 중 최대치는 포함하지 않는다.

슬랩은 고수위에 맞춰 늘고 clear/소멸까지 유지된다. reclaim은 값 공간을 재사용 목록으로 돌리고 안전한 세그먼트를 해제한다. release_retired도 슬랩 일부를 개별 해제하지 않는다. 별도로 준비한 독립 값 노드는 안전한 시점에 개별 해제할 수 있다. 잔존 원소의 clear/소멸 순서는 보장하지 않으므로 처리 순서가 필요하면 명시적으로 FIFO drain한다. PPL과 동일 메모리 예산을 맞춘 비교는 아니다.

§03

락 프리 보장 경계

  • 다른 특정 생산자의 예약 완료를 기다리지 않는다. 회수자는 보호 중인 세그먼트를 보류 목록에 넣고 돌아온다. 사용 중인 등록 슬롯을 기다리며 빼앗지 않는다.
  • 기본 MaxParticipants=64는 T/한도/Hook 특수화별로 등록되어 살아 있는 스레드 수다. 종료 시 해제되며 한도 초과는 queue_operation_limit다. 초기 구현의 활성 호출 한도와 다르므로 엔진의 참여 스레드 수를 통합 전에 확인한다.
  • register_current_thread()로 초기 TLS 등록을 작업자 준비 단계에 둘 수 있다. 콜드 등록의 C++ 런타임, 큐 생성, 슬랩/세그먼트 캐시 미스의 CRT 할당, 사용자 T 연산까지 포함해 모든 호출이 무조건 락 프리라고 주장하지 않는다.
  • prepare는 값과 세그먼트 경계용 예비 공간을 마련한다. 등록이 끝난 스레드의 publish는 경계에서도 추가 할당·해제 없이 공개하며 try_pop도 정상 경로에서 할당·회수하지 않는다. 미사용 예비 공간은 호출자의 prepared handle 소멸 때 정리한다.
  • T 이동 대입/소멸은 noexcept, 동일 큐 재진입은 금지다. 선택적 access_token은 생성 스레드·큐에 묶인다. 수용 표는 토큰을 쓰지 않는다. clear/소멸은 모든 참여 작업이 끝난 뒤에만 한다.

공개 헤더는 STL 컨테이너·std::atomic·std::mutex·PPL 없이 컴파일러 원자 primitive와 C/C++ 언어 런타임을 사용한다. 알고리즘의 진행 논거에 중단 회귀를 더했으며 테스트를 모든 인터리빙의 형식 증명으로 표현하지 않는다.

§04

정확성·경쟁 검사

  • Windows MSVC Release CTest 6/6, 핵심 전체 20회 반복 통과.
  • MSVC AddressSanitizer 10회 반복, ClangCL 20.1.8 Release 및 공개 헤더 독립 실행 통과.
  • WSL Ubuntu x86_64 Clang 18.1.3 GNU 원자 백엔드 Release 2/2, ThreadSanitizer 5회 반복 통과. Linux 성능 수용을 대신하지 않는다.
  • 1P1C/4P1C/4P4C의 ID별 정확히 한 번 소비·생산자별 FIFO, 추가 8P8C, 이동 전용 소유권 40,000개, 3스레드×4연산 이력 100개를 검사했다.
  • 예약 직후 중단을 빈 큐와 256슬롯 경계에서 만들고 다른 참여자가 3,000회 전송·회수 후 재개했다. 공개 직후 중단, 소비자 보호 직후 중단과 10,000회 회수 진행도 검사했다.
  • 등록 한도를 채운 채 작업자가 멈춰 있어도 회수자는 대기하지 않는다. TLS보다 짧은 큐 수명 200회, 예비 세그먼트 공개의 무할당, 예외 뒤 소유권 보존, 128B 정렬, 실제 파일 경로, clear·재사용을 검사했다.

검사에서 데이터 레이스나 메모리 오류가 검출되지 않았다는 범위다. 모든 스케줄·ARM64/macOS·엔진 ABI/모듈/씬 전환/종료·프레임 성능은 미검증이다. 독립 성능 수용과 엔진 통합 수용을 구분한다.
