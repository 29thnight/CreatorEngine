# 전체 컨테이너 전환 진행 기록

> 2026-10-27 전체 모듈 재수용: 일반 **78/82**, MPSC 주 수용 **3/4**, PPL 확장 큐 **5/6**으로 전체 미통과다. 새 엔진 정본으로 측정한 결과와 잔여 STL 사용처는 [재수용 보고서](EngineContainersReacceptance20261027.html)에 기록했다.

> 2026-10-27 문자열 갱신: `ce::string`/`string_view`는 UTF-16 기본 타입으로 구현했고 UTF-8·ImGui 캐시/입력, 실제 한글 IME와 Editor Debug 실행 검증을 통과했다. 후속 문자열 성능은 기존 기준으로 **57/57**이며 UTF-8 2KB 추가 미달을 해소했다. [추가 원인 분리·최종 재수용](Utf8AppendOptimization20261027.html), [초기 구현·측정 상세](Utf16StringIntegration20261027.md). 기존 STL 문자열 전체 전환 완료를 뜻하지 않는다.

2026년 10월 27일 추가 최적화 후 노드 맵 정본은 성능 수용 54/54를 통과했다. [노드 맵 추가 분리·최종 수용](NodeMapOptimizationAcceptance20261027.md)에 최신 결과를 기록했다. 아래의 과거 노드 맵 미달 수치는 당시 검사 기록이다.

노드 맵의 중복 탐색·키 삭제 경로를 각각 분리한 후속 실측은 [노드 맵 변경별 계측](NodeMapAblation20261026.md)에 기록했다. 두 변경을 합쳐도 전체 성능 수용에는 미달했다.

이 문서는 초기 통합 이후의 전체 STL 저장소 교체 작업을 기록한다. 전체 교체는 진행 중이며 완료 판정이 아니다. 구현 정본은 계속 `Engine/Containers`이고 외부 `CreatorContainers`는 이 소스를 직접 빌드한다.

## 검사 범위

Engine, Editor, Lattice, Player, HeadlessHost의 추적 C++ 소스를 검사한다. 주석과 문자열 리터럴을 토큰 단위로 제외하며 컨테이너 저장소, 함수 인수, 반환 타입과 정적 호출을 포함한다. ThirdParty와 Tools의 비교용 STL 사용, 빌드 산출물은 집계 밖이다.

전환 전 코드 참조 14,489건 중 vector 교체 후에는 10,468건이 남았다. 후자는 1,017개 파일의 참조 수이며 객체 개수가 아니다. 원시는 `Build/Verification/ContainerMigration/baseline-lexical-20261026.json`과 `current-full.json`에 보존했다. 문자열 8,073건, 고정 배열 1,168건, unordered_map 212건 등은 아직 남아 있다. vector 2건은 reflgen SDK가 요구하는 반환 타입과 해당 반환 버퍼다.

## 적용한 배열 전환

688개 파일의 vector 참조를 엔진 소유 `ce::dynamic_array`로 변경했다. 주석·리터럴·파일 인코딩을 보존하는 전환 도구와 회귀 검사를 추가했다. 재귀 JSON, 문서 노드와 명령 결과 트리는 불완전 타입을 지원하는 `ce::recursive_array`를 사용한다. 일반 배열은 이동 전용 타입의 복사 불가 특성을 유지한다.

프로파일 캡처 배열은 기존 전용 힙의 수명을 유지하는 `capture_byte_allocator`를 사용한다. `arena_vector`도 내부 배열로 교체했으며, 중첩 할당자 전달·다른 영역으로의 이동 대입·복사 시 원본 arena에서 분리되는 규칙을 유지한다. GPU 프로파일러의 이동 불가능한 원자 객체는 개수 지정 생성 경로에서 이동 코드를 생성하지 않는다.

컨테이너 파티션은 25개로 확장했다. `fixed_array`는 집합 초기화·구조적 바인딩·연속 반복자·비교와 `to_array` 생성을 제공한다. `node_hash_map`은 재해시 중에도 키와 값 주소를 보존하며, 삽입 준비 단계의 할당·생성 실패 시 기존 인덱스를 보존한다. `fixed_bitset`도 추가했지만 기존 bitset 사용처 전환은 아직 하지 않았다. 새 구현의 존재가 모든 사용처 전환 또는 성능 수용 완료를 뜻하지 않는다.

고정 배열은 MSVC STL 비교에서 9조건 × 3프로세스 27/27을 통과했다(`20261026-fixed-array-accept1`). 이후 310개 파일의 명시적 배열 타입과 3개 파일의 `to_array` 생성 경로를 내부 구현으로 전환했다. 고정 길이 span 경계 3곳은 직접 생성으로 길이 제약을 유지한다. Clang의 import 전용 구조적 바인딩은 특수화뿐 아니라 tuple 프로토콜의 원래 이름도 재수출해야 함을 재현 코드로 확인하고 수정했다.

이 단계의 명시적 코드 참조는 엔진 본체 9,300건, 빌드에 연결되는 Tools/ProfilerViewer와 Tools/runtime 70건이 남았다. 해당 도구의 vector 소비자 7개 파일도 함께 전환했다. 원시는 `after-fixed-array-pass.json`과 `production-tool-remaining.json`이다. 문자열, 맵, 집합, deque, 복사 가능한 함수 객체 등이 다음 전환 범위다. 명시적 타입 검색만으로 자동 추론된 외부 라이브러리 소유 반환값까지 모두 제거했다고 판정하지 않는다.

## 실측과 현재 검증 경계

배열 확장 API 측정에서 fill 루프가 매 원소마다 객체의 길이를 갱신하는 비용을 어셈블리로 확인했다. 길이를 한 번 갱신하도록 수정한 뒤 count_construct 비율은 64원소 1.620292에서 0.890916, 4,096원소 2.987234에서 0.523080으로 바뀌었다. 이후 복사 편차는 16/32바이트 정렬 대조군으로 분리했다. 큰 기본 힙 블록의 정렬을 조정한 `20261026-array-api-accept2`는 12조건 × 3프로세스, 36/36을 통과했고 최대 비율은 1.054487이었다.

이 성능 결과는 해당 시점 입력 스냅샷의 결과다. 이후 추가한 중첩 할당자·이동 불가능 타입 지원까지 포함한 전체 모듈 성능 재수용은 별도로 필요하다. 기존 82조건 수용 결과를 현재 전체 전환의 성능 증거로 대체하지 않는다.

최신 `20261026-array-factory-asan`은 MSVC named module 메모리 검사 12/12를 통과했다. `20261026-array-factory-tsan`은 Linux Clang 18에서 25개 파티션과 주 모듈, 실행 검사 10건을 통과했다. `Build/container-arrays-rhi-debug1.log`의 소프트웨어 RHI 검사는 39개 encoder 메서드, 중첩 allocator, 소유 payload, 다른 스레드 해제와 arena 수명 검사를 통과했다. 이 검사는 native GPU 명령 실행 수용을 뜻하지 않는다.

배열 전환 후 Editor Debug 전체 빌드(`Build/container-arrays-debug3.log`)와 새 exe/runtime DLL의 실제 실행이 통과했다. `AllArraysDebug1/acceptance.json`은 17개 명령, 새 GPU 프레임 완료, 2회 × 8,192개 정확히 한 번 전달, 물리 저장소, 지오메트리 발행 롤백, Play/Stop 장면 복원과 정상 종료를 확인한다. 별도의 실제 엔진 모듈 소유권 검사도 23건 통과했다(`Build/container-arrays-ownership-debug.log`).

런처는 자신의 static CRT로 동일한 컨테이너 소스를 컴파일한다. HostAbi만 소비하고 반영 타입을 사용하지 않는 런처에 공통 reflection 주입이 걸려 컨테이너 파티션이 주 모듈을 다시 import하는 순환을 실제 모듈 의존 파일에서 확인했다. 런처를 해당 reflection 주입 대상에서 제외한 뒤 각 파티션의 정상 의존성 및 새 런처 실행을 확인했다. 엔진의 반영 타입 소비자는 기존 주입을 유지한다.

Editor Release 빌드와 새 바이너리의 동일한 17개 실행 검사도 통과했다(`Build/container-arrays-editor-release.log`, `AllArraysRelease1/acceptance.json`). Player Debug와 Release 빌드도 통과했다(`Build/container-arrays-player-debug.log`, `Build/container-arrays-player-release.log`). Player는 빌드 검증 범위이며 패키징된 게임 실행을 수용한 것은 아니다.

## 현재 바이너리의 추가 성능 검사

확장 동적 배열 API는 `20261026-engine-array-api1`에서 12조건 × 3프로세스 36/36을 통과했다. 모든 15개 원시 샘플을 유지하며, 매 반복 비율 ≤ 1.10 및 양쪽 시간 편차 x[13]/x[1] ≤ 1.30을 적용했다. 최대 비율은 1.077361이다.

고정 배열의 `20261026-engine-fixed-array1`은 26/27이다. 4,096원소 transform의 비율은 1.007145였지만 custom 편차가 1.556168이었다. 해당 조건의 두 샘플은 약 17~18ms의 추가 경과 시간에 해당한다. 당시 CPU 시간 자료가 없어 이 두 지연의 원인은 확정하지 않는다. 실패 원시 자료와 소스·바이너리를 `20261026-engine-fixed-array1-snapshot`에 보존했다.

스레드 CPU 시간 및 실행 사이클을 함께 기록한 `20261026-fixed-cpu-30ms2`와 `20261026-fixed-cpu-100ms2`는 각각 27/27을 통과했다. 최대 비율은 각각 1.039648과 1.040592이며 같은 임계값과 전체 샘플을 유지했다. 이전 지연은 이 수집에서 재현되지 않았다. 100ms는 기존 전체 모듈 수용과 동일한 측정 배치 길이다. CPU 계측을 추가한 사실과 배치 길이 변경을 구분하며 이전 실패를 삭제하거나 통과로 바꾸지 않는다.

새 `node_hash_map`은 `20261026-engine-node-map1`에서 15/36만 통과했다. 따라서 기존 unordered_map 사용처의 일괄 전환에는 아직 적용하지 않았다. 실패·생성·재해시 롤백과 참조 안정성의 기능 검사 통과가 성능 통과를 뜻하지 않는다.

`20261026-node-map-controls1`은 같은 실행 파일로 기본 해시와 identity 해시를 3회씩 비교한다. 4,096개 키의 실패 조회 비율 중앙값은 각각 1.207498과 1.403115였다. 이 대조는 해시 연산뿐 아니라 버킷 분포도 바꾸므로 순수 해시 계산 비용으로 해석할 수 없다. 현재 키 패턴에서 혼합 해시 제거가 미달을 해결하지 않고 악화시킨다는 결과다. 인덱스 탐색·노드 할당 비용 분리 및 최적화가 추가로 필요하다. 해당 대조군을 기본 구현의 성능 수용으로 취급하지 않는다.

측정은 엔진 빌드와 실제 실행 검사를 종료한 뒤 따로 수행했다. 기존 환경에서 사용하던 CPU4 측정 스레드와 CPU5 SMT helper를 사용했으며 helper 생존 기간과 정상 종료를 각각 guard 영수증에 남겼다. 다른 프로그램의 우선순위·affinity나 OS 설정을 변경하지 않았다.

당시에는 82조건 및 전체 큐 성능 재수용이 남아 있었다. 현재 결과는 문서 상단의 후속 보고서를 따른다. 초기 통합 문서의 기존 PASS는 초기 통합 당시의 범위이며 현재 전체 컨테이너 교체 완료 판정은 아니다. 남은 문자열·맵·집합·deque·함수 객체 등의 9,370개 명시적 참조와 자동 추론된 외부 API 반환 경계까지 후속 전환해야 한다.
