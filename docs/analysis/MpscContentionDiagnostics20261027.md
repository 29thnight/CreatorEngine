# MPSC 경합과 STL 측정 편차 추가 분석

> 후속 결과: [작은 MPSC 탐색 힌트와 성능 재수용](MpscTailHintAcceptance20261027.html)에서 엔진 정본의 기존 기준 전체 통과와 최신 제품 검증을 확인할 수 있다. 아래 내용은 이전 실행의 진단·실패 기록이다.

이전 전체 수용 `20261027-four-full1`은 일반 81/82, MPSC 단일 전송 2/4로 실패했다. 실패 표본과 기존 기준은 [이전 보고서](FourContainerOptimization20261027.html)에 보존한다. 본 문서는 추가 진단과 후속 재수용을 구분한다.

## MPSC 슬롯 경쟁

64칸, 생산자 4, 소비자 1, 생산자별 262,144개 값의 별도 계측 시제품은 성공 전송 총 1,048,576건에 대해 슬롯 소유 확인 200만~349만 회, 소유권 CAS 시도 133만~148만 회(각 프로세스의 15표본 중앙값)를 기록했다. 해당 계측은 스레드별 카운터를 추가하므로 절대 시간이나 성능 합격 판정에 사용하지 않는다. 시도 횟수는 슬롯 획득 경합을 나타내지만 최종 지연의 단일 원인으로 확정하지 않는다. 원시 표본과 계측 바이너리 해시는 외부 `CreatorContainers/results/20261027-mpsc-probe-*`에 있다.

슬롯 64바이트 정렬 시제품과 원본을 5회 순서를 교차해 비교했다. 시제품은 일부 중앙값이 낮았으나 두 실행에서 편차가 1.30을 초과해 채택하지 않았다. 탐색 시작점을 17칸씩 이동한 시제품은 7회 비교에서 원본보다 일관되게 느려 채택하지 않았다. 원시 표본은 `20261027-mpsc-align64-*`, `20261027-mpsc-stride17-*`이다. 두 시제품 모두 엔진 정본과 수용 실행의 바이너리에 반영되지 않았다.

## STL 편차

이전 `map_miss/65536` 실패의 STL 단일 원시 호출 시간은 약 44.9~67.9ms였으며, 같은 실패 실행에서 STL 배치의 스레드 실행 사이클도 약 6.63억~9.71억으로 늘어났다. 단순한 스레드 미실행만으로 설명하기 어렵지만, 캐시·메모리·인터럽트 중 어떤 요소가 원인인지 확정할 수 없다. 원래 실행 파일과 CPU guard, 웜업, 표본 수, 비교 순서 교차를 유지해 별도 5회를 측정한 결과 STL 편차는 1.0622~1.0983으로 모두 기존 1.30 한도 이내였다. 5회만으로 기존 일시적 편차가 해결됐다고 판단하지 않는다. 원시 자료는 `20261027-four-full1-cases/3-core-map_miss-65536.csv` 및 `20261027-map-miss-probe-*`이다.

## 엔진 사용처와 검증

효과 정의의 내부 숫자 성분 임시 배열 2개 표기를 `ce::dynamic_array<double>`로 교체했다. 공용 효과 정의 API와 요소의 순서는 유지한다. 비유한 Float3의 중간 성분, 비유한 Color4 알파 및 Float3 구간 순서를 추가 검증했고 효과 정의 CPU 테스트는 Debug·Release 각각 54건 통과했다. 이는 효과 시뮬레이션·렌더링 검증을 의미하지 않는다. Windows 일반·ASan 모듈 각 16/16, Linux 26개 모듈과 ThreadSanitizer 13 실행이 통과했다. 변경된 Debug Editor 빌드와 실제 17명령 실행도 통과했다. 직전 완료된 전체 성능 수용은 미통과이며 추가 원인 분리와 재수용을 진행한다.

## 슬롯 배치 변경과 추가 대조

순차 탐색을 단일 원자 비트맵으로 대체한 별도 시제품은 생산자 4명 조건의 다섯 실행 모두 PPL 대비 1.3583~1.4821배로 느려 채택하지 않았다. 32바이트 정렬 시제품은 같은 4생산자 조건 7회에서 0.7554~0.8401배, 자체 편차 1.0567~1.2352였다. 원본은 같은 교차 측정의 7회 중 한 번 자체 편차가 1.3318이었다. 단일 생산자 조건의 10회에서 정렬 시제품은 0.6498~0.7561배, 자체 편차 1.0642~1.1504였고 원본의 한 회차 편차는 1.6768이었다. 이 표본은 제한된 조건의 대조이므로 모든 하드웨어에서의 우위를 의미하지 않는다. 원시 파일과 실행 파일 해시는 `20261027-mpsc-bitmap64-*`, `20261027-mpsc-align32-*`, `20261027-mpsc-align32-one-*`이다.

정본은 크기 64바이트 이상의 값 슬롯만 최소 32바이트 정렬하며 더 강한 값 정렬을 보존한다. 128바이트 시험 값의 슬롯은 136바이트에서 160바이트로 증가하여 64칸에서 약 1,536바이트, 1,024칸에서 약 24,576바이트의 저장 공간이 추가된다. 원자 연산, 큐 게시·취소·회수 절차 및 동적 할당 없는 고정 용량 설계는 변하지 않는다. 캐시 경합이 개선의 유일한 원인이라는 직접 증거는 없다. 정본 바이너리 MPSC 단일 전송의 별도 세 반복은 네 조건의 비율과 편차 기준을 모두 통과했다(`20261027-align32-mpsc-*`).

단일 생산자 계측 시제품 7회는 중앙값 기준 전송 262,144건마다 소유 CAS가 정확히 262,144회였다. 실패 재시도와 풀 탐색은 관측됐으나 해당 시제품에서는 이전의 큰 지연을 재현하지 못했다(`20261027-mpsc-probe-one-*`). 이전 `20261027-contention-full2` 실행은 첫 단일 전송 64/1에서 자체 편차 1.4992로 이미 수용이 불가능해 중단했으며, 부분 표본은 보존했다. 완료된 전체 결과로 취급하지 않는다.
## 재현된 STL 편차와 통제 부하

정렬 반영 후 `20261027-align32-full3` 두 번째 반복의 `map_miss/65536`에서 STL 편차가 1.5317로 다시 실패해 전체 실행을 중단했다. 자체 편차는 1.0157, 비율은 0.2707이었다. STL의 네 번 호출 배치에서 스레드 사이클은 약 6.69억~11.37억이었다. 해당 실행은 부분 결과이며 전체 합격 결과가 아니다. 첫 MPSC 단일 전송 네 조건은 모두 기준 내였다.

별도 물리 코어의 128MiB 임의 접근 부하를 켜고 끄면서 같은 정본 실행 파일과 기존 guard·샘플 조건으로 5쌍을 교차 측정했다. STL 중앙값은 무부하 약 45.3~46.3ms, 부하 약 47.1~48.6ms였고 부하 측 편차는 1.0346~1.0560이었다. 이 구체적인 부하는 STL을 느리게 했지만 1.53 편차를 재현하지 못해 이전 실패의 직접 원인을 입증하지 않는다. 원시 표본·도우미 출력·해시는 `20261027-map-memory-*`에 보존했다. 시스템 ETW 추적은 `wpr -start CPU -filemode`가 `0xc5585011` 프로파일 정책 오류로 거부되어 수집하지 못했다. 기존 수용 기준은 변경하지 않았다.

사용처 감사 `Build/Verification/ContainerMigration/inventory-20261027-align32.json`은 기존 범위의 명시적 참조 9,404건을 기록한다. 문자열 등 남은 전환은 완료되지 않았다.
## 완료된 전체 수용과 추가 실패 분석

`20261027-align32-full4`는 해시와 258개 프로세스 원시 결과를 검증했으며 **FAIL**이다. 일반 82/82, MPSC batch8 4/4, MPSC 단일 3/4, FAA/PPL 6/6, SPSC·spin MPMC 8/8이었다. 64/4 단일 전송 마지막 회차는 비율 0.8522이나 자체 편차가 1.3149로 한도 1.30을 넘었다. 느린 표본 114~120ms에서는 생산자 재시도가 약 7만~10.5만 회였고 빠른 표본 90~93ms에서는 약 1,800~6,800회였다. 재시도와 지연의 관계는 관찰됐지만 단일 원인은 확정되지 않았다.

여유 슬롯 수를 공유 원자로 추적해 실패 탐색을 줄이는 시제품은 5회 모두 PPL 대비 1.4320~1.4914배라 채택하지 않았다(`20261027-mpsc-freecount-*`). 128바이트 정렬 요구 값의 생성 위치·FIFO 값을 검증하는 회귀 테스트는 MSVC 일반 및 ASan에서 통과했다.

추가 `20261027-align32-full5`는 첫 MPSC 1024/1에서 자체와 PPL의 편차가 각각 1.7466과 1.4504로 수용이 이미 불가능해 중단했다. PPL 느린 두 표본에서 생산자 시작 지연은 각각 7.4041ms와 18.528ms였고 같은 표본의 총 시간은 44.98ms와 59.74ms였다. 시작 지연이 총 시간에 포함된 것은 직접 관측됐지만, ETW가 거부되어 실제 스케줄링 이벤트나 경쟁 프로세스는 특정하지 못했다. 기준 변경이나 표본 제거 없이 부분 원시 자료를 `20261027-align32-full5-*`에 보존한다.
풀 획득 실패 시 `spin_pause` 32회 후 재탐색하는 유한 시제품을 측정했다. 64/4만의 7회는 편차 1.0451~1.1666이었으나, 네 조건 교차 대조에서 1024/4 일부 실행은 원본 약 70~72ms 대비 시제품 약 88~90ms로 느렸다. 실패 호출의 지연도 늘어날 수 있으므로 정본에 채택하지 않았다(`20261027-mpsc-backoff32-*`).
`20261027-align32-full6`은 첫 단일 전송 64/4에서 1.1424배로 기준 1.10을 넘어서 중단했다. 느린 15표본 중 다수가 약 119~123ms, 생산자 재시도 약 10만~12.7만 회였으며 PPL은 약 105~109ms였다. 이 부분 실행은 전체 판정으로 취급하지 않는다.

32회 pause 재탐색은 꽉 찬 64칸 큐에서 실패 호출 중앙값이 원본 약 52.7~53.9ns 대비 1,244~1,250ns로 증가했다(5회, 각 15표본). 1회 pause 재탐색은 해당 중앙값이 150.26ns였고, 64/4 교차 대조 7회에서 일관된 시간 이점이 없었다. 모두 엔진 정본에 적용하지 않았다. 원시 자료는 `20261027-mpsc-full-latency-*`, `20261027-mpsc-backoff1-*`이다. 수용 기준을 완화하거나 실패 표본을 제거하지 않았다.
