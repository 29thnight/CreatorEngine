이전 근거의 유효 범위

기존 세부 계약은 위 현행 구현과 모순되지 않는 범위에서 유지한다. 과거 수치·실행 통과·해시·장치 조건은 당시 기록이다. 로컬 산출물이 사라진 항목은 링크 대신 경로와 미보존 상태를 표시하며, 현재 master의 재실행 통과로 승격하지 않는다.

세부 계약·원래 분석과 당시 측정 기록

Debug UI 배율0.8과 Release1.5에서 실제 Inspector 내부 분리·숫자 입력0→2·다른 텍스처 선택·원래 선택 복귀·제목 표시줄 X 종료를 확인했다. Debug0.8 재도킹도 확인했다. Release1.5는 여러 이동 시도 후에도 결합된 상태를 확인하지 못했으므로 재도킹 수용에서 제외한다. 제품 결함 원인은 확정하지 않았다.

기계 판정과 실행 신원

Build/TextureInspectorScale/result.json에 두 실행의 최종 editor.theme receipt, runtime SHA256, 입력4파일 전후 hash와 sourceDrift0을 저장했다. HEAD는 d3c85faf182e93842217dd46eee3d3aabf4afc13이다. 각12 checks는 exit0, theme/geometry/scale/DPI 일치, 실제 적용 배율, 종료 후 저장 배율, GUID, maxDimension2, Tiny4 PNG hash, 원래 저장 씬의 프로젝트 경로 치환 후 정확한 내용, Finalize, WM_CLOSE 수신, DX12 pending0/0/0, runtime hash 일치다. UI 조작 관찰은 기계 판정과 별도 필드다.

두 실행 모두 OS DPI1.5였다. UI 배율은0.8/1.5, renderedFontSize는19/36으로 관측됐으며 glyph 누락0, geometryMatches/clean=true였다. 실행기는 격리 프로젝트에만 선택한 imguiScale을 기록하고 두 editor.theme 스냅샷을 추가했다. 제품 코드 변경이나 추가 빌드는 없다.

Release의 최초240초 프로세스 관찰은 수동 조작 중 제한을 넘겨 exit.json에 exited=false/exitCode=null과 관찰기 오류를 남겼다. 프로세스를 강제 종료하지 않고 새 대기 핸들을 확보한 뒤 실제 X로 닫았다. exit-after-ui.json은 exited=true/exitCode0이며 이전 제한 초과를 보존한다. 최초 receipt를 정상 종료로 해석하지 않는다.

수용 경계와 잔여

ImGuiHost.cpp의 DockingEnable은 활성화돼 있지만 ViewportsEnable은 창 생성 스레드와 메시지 펌프 소유권 문제로 보류돼 있다. 이번 검증은 메인 OS 창 내부의 floating Inspector다. 별도 OS 창, 다중 모니터, 실행 중 DPI 전환, 전체 Debug/Release×0.8/1.5 조합 및 GPU pixel 결과는 수용하지 않는다. Release1.5 재도킹과 좁은 dock에서의 읽기·편집도 후속으로 남긴다.

12-0-D의 후속 범위로 기록하며 추가 가중치를 얻지 않는다. PHASE12 진행률66.25%(표시66%), T1b 대기·T3 중단을 유지한다. 400ms 안 실제 닫기 클릭, 실패 유형별 반복 확장, 전체 소비자·포맷·Shipping GPU는 기존 잔여다.
