# C++23 독립 컨테이너·문자열 측정 (2026-10-25)

독립 솔루션 초기 구현을 작성하고 MSVC STL Release와 비교했다. 배열·FIFO·정수 키 해시맵은 다수 항목에서 우위 후보지만, 문자열 일부 경로와 변동성이 큰 항목이 남아 전체 엔진 통합 게이트는 통과하지 않았다. 이 보고서는 실제 엔진 프레임 성능을 주장하지 않는다.

환경: Windows 11 Pro 10.0.26300, Intel i7-8700K 6C/12T, x64 MSVC 19.50.35730, MSVC STL 145, `/O2 /MD`, iterator debug 0, C++23 요청에 대한 MSVC `/std:c++latest`. CMake가 설치된 BuildTools 인스턴스를 선택했으며 Community의 도구 경로를 호출했다고 Community 컴파일러를 사용한 것으로 간주하지 않는다.

측정: 프로세스 3회, 각 케이스 warmup 3회 + 15개 표본, 적응 반복(약 2ms 목표), A/B 순서 교대. 아래 비율은 각 프로세스 중앙값 비율의 중앙값이다. p약90/p약10 비가 어느 쪽이든 1.25 초과인 실행이 있으면 '변동 큼'으로 보수 표기한다. 통계적 신뢰구간이나 고립된 CPU 측정은 아니다. 일부 작은 SSO 측정은 최적화 효과가 클 수 있으므로 실제 문자열 소비자 부하로 다시 검증한다.

정확성: MSVC Release, MSVC Release + AddressSanitizer, ClangCL 20.1.8 Release에서 동일 대조 검사를 실행한다. 실행 로그의 `CORRECTNESS_PASS`와 소스·바이너리 SHA-256은 독립 프로젝트 `results`에서 확인한다. ClangCL도 같은 Windows CRT/STL 환경이며 Linux/macOS 검증을 대신하지 않는다.

제약: 배열/맵은 단순 타입, 맵은 uint64 키다. 해시맵의 load factor/슬롯 메모리, 문자열의 SSO 용량, FIFO의 고정 용량 계약이 STL과 다르다. 기본 정책의 용도 비교이며 API·메모리 예산이 동일한 범용 대체 성능으로 일반화하지 않는다. 해시맵 churn/erase는 정확성 검사만 수행했고 성능은 build/hit/miss만 측정했다. 문자열 검색은 반복 문자 안의 고정 패턴이며 적대적 패턴의 worst-case 검증이 남아 있다. CPU affinity·전원 정책·백그라운드 프로그램은 변경하지 않았다. 냉 캐시·할당량·RSS·엔진 프레임·다른 OS는 미검증이다.
