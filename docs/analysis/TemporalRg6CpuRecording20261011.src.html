원인 계측

첫 가설은 동일 command target의 불필요한 wave 경계와 idle target Job이었다. 이를 줄인 v2 전체 A/B는 회귀 게이트를 통과했지만 제품 CPU 중앙값은 Debug 3.62335ms, Release 2.31115ms로 의미 있게 줄지 않았다. 실제 제품은 4 recording waves를 이미 하나의 공용 Job/worker job으로 합쳐 처리했고, legacy는 1 wave/1 dispatch/4 worker jobs였다. 따라서 Job 호출 횟수 자체를 주원인으로 판정하지 않는다.

별도 Release 진단 실행에서 normal-domain graph만 bounded 환경 계측했다. 준비 완료 프레임 1435/1499/1563/1630의 패스 기록 wall-time 합은 2.0477/2.4921/1.8359/2.0534ms, 각 4 target의 최대 합은 0.5865/0.6992/0.5059/0.6809ms였다. 패스 몸체 외 profiler/배리어 구간도 포함한다. 제품은 이 네 구간을 차례로 기록했다. 현재 파이프라인의 GPU RAW/WAR/WAW 의존성을 콜백 사이의 CPU 데이터 전달처럼 보수적으로 join하여 병렬성이 사라진 것이 주원인이다. 제품의 추가 current-depth occlusion도 비용은 있지만, 9단계 binding 생성 중앙값 합은 약 0.04ms이며 단계별 전체 callback은 대체로 0.02ms 정도다. cold PSO/transform 준비의 큰 표본은 정상 benchmark로 재사용하지 않았다.

진단 정본은 Artifacts/PR169/tr0-rg6-cpu-diagnostic-20261011/diagnosis.json과 editor.stderr.log다. 계측 소스 2개를 같은 디렉터리 instrumented-source에 보존하고 최종 제품 코드에서는 제거했다. 진단 실행 자체도 두 프로세스 정상 종료·native/픽셀/validation gate를 통과했다. 최종 성능 표본에는 계측 로그 출력/clock 구간을 섞지 않는다.

구현과 소유권

DeclareRecordingIndependent(pass)는 명시적인 저자 계약이다. unsplit callback은 준비된 불변 CPU 입력만 읽으며 다른 callback의 CPU 결과를 소비하지 않는다. 자체 관측값은 전용 저장소 또는 atomic에 쓰고 전체 recording join 이후에만 소비한다. compute queue 적합성과 별개이며, 외부 CPU side effect 또는 split callback의 선언을 거부한다. 미선언 소비자의 기존 split/cross-target CPU join, 외부 side-effect owner 경로와 예외 폐기는 유지한다.

이 계약을 확인한 current-depth pyramid/culler, SSAO/SSGI compute stages, post-chain, camera/object motion, LX GBuffer·opaque Color, Deferred, SkyBox에 각각 명시했다. 특수/블렌드/전송 경로를 묶어서 자동으로 분류하지 않는다. GPU executeOrder·barriers·연속 target 분할·list submission 순서는 그대로다. 선언된 consumer만 cross-target GPU edge의 CPU join을 생략한다. 자체 target append 순서와 활성 target만 Job으로 호출하는 v2 개선도 유지한다.

CPU 기록 snapshot에 recordingWaves/jobDispatches/workerJobs를 동일 native provenance로 발행한다. owned queue mode의 미계측 카운터 0을 실제 Job 0회로 해석하지 않는다. RG4 native 회귀는 기존 immediate/1·2·4 workers/fallback/split/CPU join 검사를 유지하고, 독립 GPU consumer의 four-target parallel recording·RAW pixel 동일 및 잘못된 side-effect/split/ compile 이후 독립 선언 거부를 추가한다. GPU retirement 이후에만 진단 assertion으로 종료한다.

보관

30GiB 하한과 bounded capture 예산을 매 실행 검사한다. 각 성공 baseline은 비교에 필요한 두 process capture-0만 잠시 pin하고 나머지 raw는 즉시 정리하며, 최종 비교 후 하나로 줄인다. 변이 payload는 거부 직후 삭제하고 로그/manifest/hash/verdict는 보존한다. v2는 첫 가설 기각 기록으로 보존하며 재검증 원본은 대표만 남긴다. 최초 실패의 3.50GiB dump 삭제는 자동 정책 검사가 차단했고 구체적인 이유가 반환되지 않아 그대로 남겼다. 텍스트 stack과 실패 원인은 보존한다.
