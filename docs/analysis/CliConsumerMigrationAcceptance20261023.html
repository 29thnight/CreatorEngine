분석

CLI 소비자 래칫 7파일 이주 수용

후속: 아래 실행 당시 남긴 애니메이션 쿠커 차단의 원인·수정과 새 제품 실행은 AnimationCookAcceptance20261023을 따른다. 이 문서의 이전 실행 결과와 동명 JSON의 신원은 당시 기록으로 보존한다.

2026-10-23 로컬 작업본 기준. cli_consumer.ratchet.json을 바꾸지 않고 상한0 / 관측0을 확인했다. 이전 종료 수용에서 관측한 7 > 0의 후속 작업이다. 전체 LC9 완료로 승격하지 않으며 일반 GUI·서비스/Shipping 잔여와 구분한다.

정확한 소스·바이너리 해시, 실행별 PID/결과/로그 경로는 동명 JSON에 기록했다. 결과 계약이 현재 생산자·소비자 경계다.

§02

기존 호출자에서 확인한 수정

  • Player 작업자 검증기는 패키지의 Resources/Environment를 빠뜨려 실제 렌더 준비가 실패했고, 현재 기본 프로젝트의 GameScripts로 fixture 스크립트를 덮었다. 전체 패키지 closure와 fixture별 Scripts를 보존한 뒤 재로드/정상 종료를 통과했다. 현재 native/common 관리 런타임 overlay는 유지하며 새 패키지 인증으로 확대하지 않는다.
  • 브라우저의 isolated A/B 프로젝트에 설정·셰이더·F# 소스 순서가 없어 프로젝트 수용이 실패했다. 각 프로젝트에 필요한 입력을 복사했다. 작은 프로젝트에서도 점진 열거를 실제 자극하도록 트리의 즉시 자식보다 한 단계 아래에 미방문 폴더를 둔다.
  • PowerShell5가 UTF-8 명령 파일에 넣은 BOM 때문에 첫 wait가 command.unknown으로 실패했다. 공통 writer로 BOM 없는 UTF-8을 만들고 행 수·명령 이름/순서를 대조한다. 자식 프로세스 핸들 캐시와 종료 코드 null 거부도 유지한다.
  • 브라우저의 Material Graph 수신부·shared texture getter·큐 기반 sprite 편집·폴리지 stable ID 보존을 현재 소스에 맞춰 검사한다. 기존 worker publication mutex를 GT 큐 mutex로 잘못 읽던 별도 텍스처 소스 검사는 admission 범위를 정확히 검사하도록 고쳤다. 제품 잠금은 제거하지 않았다.

§04

남은 제품 수용과 경계

애니메이션 소비자의 코드는 이주했지만 새 AnimationPlayer 패키지를 만드는 단계에서 automatic Scene material compilation의 Slang E41012 / spirv_1_3 capability 오류가 발생했다. 기본·명시 DX12 패키지 시도 모두 cook에서 멈췄다. 실제 애니메이션 소비자 제품 재수용은 완료로 기록하지 않는다. 이 작업에서 쿠커/셰이더의 규칙이나 실패 기준은 낮추지 않았다.

실제 Inspector 입력 뒤의 pending shutdown/native close/5분 soak는 이번에 다시 실행하지 않았다. 합성 receipt 소비자 회귀와 Editor 정상 저장 생산자 수용을 그 실행으로 대신하지 않는다. 오디오도 프로세스별 재생/완료100회이며 100회 프로세스 반복 종료 수용은 아니다. 오디오 소비자의 기본 -Cycles 100은 유지한다.

Debug/Shipping·Vulkan 제품 실행·오디오 장치/청감 품질·일반 GUI 수동 Undo/Redo·성능 개선을 새로 수용한 기록이 아니다. LC9는 이 잔여를 포함하여 progress를 유지한다. 변경은 로컬 작업본이며 커밋·푸시·공개 패키지 게시를 수행하지 않았다.
