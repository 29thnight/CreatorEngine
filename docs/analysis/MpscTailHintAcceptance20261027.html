분석

작은 MPSC 탐색 힌트와 성능 재수용

다음 사용처 전환: 임시 GPU 버퍼 풀 STL 전환과 소유권 검증. 성능 정본을 유지한 최신 전환과 명시 참조 9,400건의 집계를 확인할 수 있다.

후속 사용처 전환: 렌더 저장소 STL 사용처 전환과 제품 검증. 성능 정본을 유지한 채 맵 두 곳을 추가 교체했고, 해당 단계의 명시 참조는 9,402건이었다.

현재 정본 변경은 64칸 이하 MPSC의 슬롯 탐색 시작점을 별도 공유 증가 값에서 게시 순번의 원자적 관측값으로 바꾸는 것이다. 이 값은 힌트이며 슬롯 소유는 기존 CAS로 획득한다. 한 번의 탐색 범위, 값 수명, 게시·취소·회수 및 고정 용량 저장 규칙은 유지한다. 큰 큐는 기존 증가 커서를 사용한다. 현재 MSVC 모듈 바이너리 전체 수용은 통과했으며 과거 실패는 이전 진단에 보존한다.

§01

대조 계측

  • 소유 상태를 값 배열에서 별도 연속 배열로 분리한 시제품은 64칸·4생산자 7회 중 자체 편차 3회가 1.30을 초과했고 원본보다 대체로 느려 채택하지 않았다(20261027-mpsc-owner-array-*).
  • 모든 크기에 게시 순번 힌트를 쓴 시제품은 단일 생산자에는 빨랐으나 4생산자에서 원본보다 느렸다. 특히 1,024칸은 변화 이점이 없어 정본 적용 범위에서 제외했다(20261027-mpsc-tailhint-all-*).
  • 64칸만 바꾼 네 조건 교차 대조 5회에서 자체와 PPL 비율·편차 20개 조합이 모두 기존 기준 안이었다. 64/1 시제품 중앙값은 약 19.620.0ms, 원본은 약 21.823.7ms였다. 64/4는 시제품 약 93.397.1ms, 원본 약 79.790.4ms로 느렸으나 시제품 자체 편차는 1.02121.0658이었다. PPL 대비 시제품 비율은 0.84440.8780이었다. 최고 처리량 대신 관측된 일관성의 절충이며 어떤 환경에서도 편차가 사라진다는 증거는 아니다(20261027-mpsc-tailhint64-*).
  • 원래 주 수용의 8회 배치 비교에서도 64/4 시제품 세 실행은 PPL 대비 0.87250.8837배, 자체 편차 1.01641.0347이었다. 원본보다 약 3~4% 느렸다(20261027-mpsc-tailhint-small-batch-*).
  • 꽉 찬 64칸 큐의 실패 응답은 별도 5회에서 시제품 중앙값 약 48ns였다. 같은 방법의 이전 원본 약 53ns와 비교 가능하나 분리된 실행이다(20261027-mpsc-tailhint-latency-*).

이 대조군은 모듈을 복사한 별도 시제품이다. 최종 엔진 정본의 기능 검사와 전체 성능 수용을 대체하지 않는다. 원시 표본, 실행 파일과 소스 해시는 외부 CreatorContainers의 results에 보존한다. 기존 비율 1.10, 양측 sorted15 x[13]/x[1] 1.30 기준을 바꾸지 않는다.

§02

기능과 엔진 사용처

64칸 이하 새 경로에 대해 4칸과 64칸의 생산자 중단 네 지점에서 다른 전송이 진행되는지 검사하고 64칸 4생산자 순서·중복 검사를 추가했다. Windows 일반·ASan 모듈은 각 16/16, Linux 26개 파티션과 기본 모듈 및 ThreadSanitizer 13 실행을 통과했다. 생성 헤더 경로의 MPSC도 일반·ASan에서 통과했다. 이 실험과 테스트는 기존 락 프리 설계가 변경 없이 유지된다는 검토를 보조하지만 모든 기계의 원자 명령이나 스케줄러에 대한 수학적 증명은 아니다.

엔진의 RHIPersistentHeapPolicy::TrimEmptySegments 내부 임시 맵을 ce::node_hash_map으로 교체했다. 맵은 기존 잠금 범위 안에서 호환 키별 보존 수를 세는 데만 쓰이며, 세그먼트의 순서·핸들 수명과 회수 조건은 유지한다. 두 키에 각각 두 세그먼트가 있을 때 키별 하나를 보존하고 나머지 두 핸들을 원래 순서로 반환하는 회귀 검사를 추가했다. 실제 Editor 컨테이너 진단에서 이 계약 검사를 호출해 결과를 검증한다. 변경된 Debug Editor 빌드와 실제 17명령 실행은 통과했으며, 두 번의 8,192건 전송·렌더 준비·Play/Stop 장면 복원과 힙 정책 계약 검사를 확인했다.

§03

최종 모듈 바이너리 재수용

CreatorContainers/results/20261027-tailhint-full1-verdict.json은 PASS이며 모든 기존 기준을 유지했다.

범위결과
일반 컨테이너82/82
MPSC 단일 전송4/4
MPSC 주 기준 batch84/4
FAA/PPL 확장 큐6/6
SPSC·spin MPMC8/8

일반·MPSC는 세 독립 실행의 모든 15표본, 비율 1.10 이하 및 양측 sorted15 x[13]/x[1] 1.30 이하 조건을 유지했다. FAA는 원래 다섯 프로세스의 전송·전체 수명 비율 기준을 유지했다. 시험 258개 조건/프로세스 결과와 소스·스크립트·바이너리 해시가 일치했다. 입력 124개와 원시 증거 266개 파일은 20261027-tailhint-full1-snapshot에 보존했다. 이전 실패와 중단된 부분 실행도 그대로 보존한다.

64칸·4생산자 단일 전송 세 실행의 PPL 대비 비율은 0.8270 / 0.8238 / 0.8642, 자체 편차는 1.0240 / 1.0167 / 1.0347이었다. 같은 조건 주 배치는 비율 0.9694 / 0.9057 / 0.9374로 기준 안이었다. 대형 맵 미스의 STL 편차도 세 실행 모두 기준 안이다. 이 통과는 현재 로컬 MSVC 시험에 대한 판정이며 과거 외부 스케줄링 지연의 근본 원인을 특정하거나 모든 OS의 성능을 입증한 것은 아니다.

기능 증거는 외부 results/tailhint-normal-driver.log, tailhint-asan-driver.log, tailhint-linux-driver.log, 20261027-tailhint-headers-*-test.log이며 제품 증거는 엔진 Build/container-tailhint-editor.log와 Build/Verification/ContainerMigration/TailHintDebug1/acceptance.json이다. 별도 문자열 전용 시험 20261027-tailhint-unicode1도 최신 정본 바이너리에서 57/57 PASS이며 입력 69개의 해시를 검증했다. 스냅샷과 원시 표본은 같은 태그의 results에 보존했다.

사용처 감사 Build/Verification/ContainerMigration/inventory-20261027-tailhint.json은 971개 파일의 명시 참조 9,404건을 기록했다. unordered_map은 209에서 208건으로 줄었다. 진단 함수에 기존 엔진 계약 API의 std::string 출력 인수가 한 곳 추가되어 전체 참조 수는 직전과 같다. 외부 코드·생성물·정본 구현과 매크로 확장은 집계 대상에서 제외했다. 전체 STL 전환은 진행 중이다.
