현재 렌더 그래프 체제로 RE ENGINE식 메시렛 파이프라인을 수용할 수 있는가

선행 문서: RE ENGINE 메시렛 파이프라인 비교. 검토 대상: EnhancedRenderGraph, LivePipelineDesc/LivePassNode, RHIEncoder, RHIFormat, GpuGeometryOcclusion, GpuMeshletVisibility.

소스 검토 결론: 그래프 체제를 유지하는 설계가 가능하다.

막히는 곳은 그래프가 아니라 아래쪽 RHI(64-bit atomic, 포맷, 바인드리스)와 위쪽 머티리얼 시스템(미분, 속성 재구성)이다. 현재 검토에서 그래프 확장 후보는 아래 두 가지다. RE식 전체 파이프라인을 구현·실행해 수용한 결과는 아니다.

01RE 단계를 그래프 노드로 옮기기

RE 파이프라인도 프레임마다 패스 구조는 고정되어 있고, 각 패스의 작업량만 GPU가 indirect 인자로 정한다. 우리 그래프도 CPU가 패스를 선언하고 GPU가 indirect로 작업량을 정한다. 메시렛 컬링이 이미 이 방식이다(DispatchMeshIndirect, CPU readback 없음). 아래 노드는 모두 기존 LivePassNode의 reads/writes/modifies 블랙보드 계약으로 표현할 수 있다.

03그래프에 필요한 확장 두 가지

① 순서 무관 동시 쓰기(commutative writer) 선언

  • ExplicitVersioned는 단일 writer 버전 체인이다. Raster1-HW / Raster1-SW / Raster2-HW / Raster2-SW가 같은 가시성 버퍼에 쓰면 버전 4개로 직렬화되고 사이마다 UAV 배리어가 들어간다.
  • 정확성 문제는 없지만, SW 래스터를 async compute로 HW 래스터와 겹치는 최적화는 막힌다.
  • 해결: DeclareRecordingIndependent와 비슷한 opt-in으로 "atomic max 전용 순서 무관 쓰기 그룹"을 선언하고, 그룹 안에서는 배리어를 생략한다. 처음에는 직렬화된 상태로 시작해도 된다.

② history 리소스 도우미

  • 이전 프레임 HiZ와 그림자 맵을 SSGI history처럼 per-view로 import하고 ping-pong하는 일을 공통화한다.
  • 구조 스케줄 캐시(structuralSchedules, 크기 2)는 "주기 2" 모양을 전제로 한다. HiZ ping-pong 주기가 SSGI와 같으면 재사용이 유지되지만, 다르면 캐시 적중이 0이 된다. 정확성 문제는 아니다.

04주의할 점

  • 구조 캐시 무효화. 버킷 수(장면의 셰이더 종류)가 바뀌면 그래프 모양이 바뀌어 캐시가 무효화된다. 버킷을 "장면에 존재하는 셰이더 집합"으로 묶어 두면 프레임마다 흔들리지 않는다.
  • 현재 프레임 오클루더 방식과의 공존. 지금 방식은 history가 없어 temporal 검증(정확한 픽셀 oracle)과 잘 맞는다. 2단계 컬링은 이전 HiZ에 의존하므로 fixture·진단 캡처 경로에서는 현재 방식으로 폴백하는 스위치를 남긴다.
  • Temporal 모션 벡터. RE는 정점 사전 계산에서 이전 HPOS를 함께 출력한다. 가시성 버퍼로 가면 Temporal.Inputs(GBuffer 단계 모션)도 VB 셰이딩 쪽으로 옮겨야 하고, 앞서 지적한 소비자 목록 하드코딩 문제가 여기서 다시 드러난다.

STEP 1 · 기존 그래프 활용
  • LX 그림자 DX12 compute 생존 목록 구현·정확도·변이·반복 성능 검증 (계획)
  • 속성 압축
STEP 2 · history 도우미
  • 2단계 오클루전(카메라)
  • 2단계 오클루전(방향광 그림자)
STEP 3 · RHI 확장
  • 64-bit atomic
  • R64 · RG32Uint 포맷
  • 바인드리스
  • → 가시성 버퍼 · SW 래스터
STEP 4 · 머티리얼 VB 변형
  • 버킷 셰이딩
  • 정점 사전 계산
  • commutative writer 확장

1·2단계는 현재 그래프를 활용하는 설계 후보다. STEP 1의 표준 그림자 캐스터 확장은 폐기했고 LX만 대상으로 한다. 기존 회귀 이전·제한된 측정과 2026-10-11 DX12 D/R 회귀·backOff 제거 변이는 확인했다. 두 합성 메시·두 포즈의 3장 경로 비트 동치와 보이는 사각형 메시렛 누락 변이 거부·정상 대조군도 당시 D/R에서 확인했다. 12개 합성 장면 확대도 해당 보고서의 D/R의 72쌍 동치·독립 대조 조건·변이 거부를 통과했다. 텍스처 알파 패턴 등 일반 수용과 compute 사전 컬링 수용은 남아 있다. Vulkan 검증은 PHASE 4.9 소유이며 DX12 작업의 선행이 아니다. 3·4단계는 RHI와 머티리얼 쪽 재설계다.

2026-10-12 반복 측정에서 4096 슬롯·현재 Release 3개 합성 장면·24회 기록을 확인했다. 경계 CPU audit 거부율 C0/C1 17.45%/10.81%도 포함한다. GPU 평균합 비교의 변동성 기준 미통과로 compute 착수 근거는 충족하지 못했다. 위 동치·변이 결과는 당시 binary 증거이며 새 계측 빌드와 구분한다.

2026-10-12 사용자 지시로 DX12 compute 생존 목록을 구현했다. 최종 D/R 선택 정확도·변이·회귀는 통과했으며 Release 3장면·24회 compute 포함 성능 이득은 미수용이다. PHASE 4.9 Vulkan 이관은 유지한다. 구현과 현재 검증 기록.

2026-10-12 현재 구조 갱신: 일반 GBuffer 표면 구현·구경로 테스트·비교 토글을 삭제하고 LX 단일 배선으로 전환했다. Scene ABI 21의 강제 리임포트·재쿠킹 계약을 적용한다. 이전 동치·성능 판정은 당시 바이너리 기록이다. 실제 삭제 목록·현재 배선·검증.

메시렛 계약 후속: 현재 LX는 쿠커의 단일 클러스터·원본 삼각형 ID를 사용하며 런타임 재클러스터링을 삭제했다. Scene ABI 22 · CEMC 13 · geometry artifact 2 · meshlet profile/builder 2로 갱신했다. 이전 산출물은 강제 리임포트·재쿠킹 대상이다. 현재 데이터 계약과 검증.
