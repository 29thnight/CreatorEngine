# 문자열·배열·MPSC·FAA 미달 원인 분리와 최적화

> 후속 결과: [작은 MPSC 탐색 힌트와 성능 재수용](MpscTailHintAcceptance20261027.html)에서 엔진 정본의 기존 기준 전체 통과와 최신 제품 검증을 확인할 수 있다. 아래 내용은 이전 실행의 진단·실패 기록이다.

이 문서는 진행 중인 작업과 실제 측정 결과를 기록한다. 이 문서가 기록한 20261027-four-full1 판정은 미달이다. 기존 `20261027-engine-full-reaccept1`은 일반 78/82, 고정 MPSC 주 수용 3/4, 개별 전송 3/4, FAA/PPL 5/6이었다. 기준과 실패 원시는 [이전 재수용](EngineContainersReacceptance20261027.html)에 보존한다.

## 실제 계측으로 분리한 비용

- 8바이트 문자열 복사는 독립 시험에서 STL 대비 1.376~1.432배였고, 같은 내용의 뷰 생성은 0.587~0.594배였다. MSVC 소비자 객체 코드에서 복사 생성자가 큰 문자열 할당 분기를 함께 포함한 별도 함수로 남아 긴 함수 프롤로그를 사용하는 것을 확인했다. 큰 복사 경로를 분리한 후 원래 `string_copy,8` 조건 세 실행은 0.9091 / 0.9092 / 0.9072배였다. `string_copy,23`도 세 실행에서 0.221~0.224배였다. 15표본과 CPU4/CPU5 guard를 유지한 **대조군**이며 전체 재수용을 대체하지 않는다.
- 예약 배열의 개별 `reserve`·해제는 STL 대비 1.020~1.061배, 확보한 배열의 별도 채우기는 0.835~0.944배, 별도 합산은 0.614~0.906배였다. 이 개별 시험은 82조건의 생성·채우기·합산 조합과 다르다. 삽입값을 지역에 복사하는 시제품은 우위를 보이지 않아 채택하지 않았다.
- 동일한 배열 코드를 가진 이전/새 모듈 소비자 바이너리를 교차 측정했다. 이전 바이너리의 64·4,096·65,536원소 비율은 첫 회차 1.1185 / 1.2194 / 1.2676이고, 새 바이너리는 1.0066 / 1.0015 / 1.0351이었다. 두 번째 회차도 각각 1.1267 / 1.2088 / 1.2623과 1.0150 / 1.0026 / 1.0342였다. 해당 삽입 루프의 객체 코드 SHA256은 양쪽 모두 `e7973617b0bed8892577ef8d132415d4acdcc85f4ea76c2f63bf9e46c57ce03d`로 같았다. 실행 파일의 동일 루프 RVA는 각각 0x14650과 0x14280이며 64바이트 경계에서 16과 0만큼 떨어진다. 이 사실은 코드 배치 또는 프로세스 주소의 영향을 시사하지만 어느 하나가 원인임을 확정하지 않는다.
- 고정 MPSC 64칸·생산자 4의 기존 batch8 세 실행에서 생산자 실패 재시도 평균은 약 6,067 / 1,446 / 49,702회였고 custom 평균 전송은 약 95.25 / 84.82 / 119.98ms였다. 실패 반복의 재시도 증가와 지연은 함께 관측됐지만 인과관계는 입증되지 않았다. 생산자별 TLS 탐색 시작점 시제품은 원본 약 3,100~4,200회에 비해 약 30,000~33,000회 재시도했으며 시간 우위가 없어 적용하지 않았다. 기존 원자적 슬롯 소유·취소 프로토콜을 유지한다.
- FAA 8바이트·생산자 4·소비자 1은 기존 다섯 실행에서 전송 중앙값 약 42.4~44.7ns/원소, 소멸 중앙값 약 1.88~2.36ns/원소였다. PPL 소멸은 약 0.004~0.006ns/원소였다. 자명한 값의 소멸 검사 생략 시제품은 뚜렷한 개선이 없어 버렸다. 작은 값의 블록을 256에서 512 슬롯으로 늘린 별도 대조군은 소멸 중앙값을 약 1.28~1.59ns/원소로 줄였고 6조건 × 5회 전송·수명 기준을 충족했다. 작은 값의 블록 크기는 4,104바이트에서 8,200바이트로 증가한다. 블록 할당 횟수는 직접 계측하지 않았으므로 감소를 확정하지 않는다. 정본에는 블록 크기만 적용했고 큐의 원자 연산·슬롯 순서·위험 포인터와 회수 알고리즘은 바꾸지 않았다. 기존 구현의 냉간 블록 할당은 CRT에 의존하므로 전체 API의 무조건적인 락 프리 진행 보장으로 해석하지 않는다.

원시 표본과 해시: 외부 `CreatorContainers/results/20261027-four-baseline-*`, `20261027-string-split-control-*`, `20261027-array-codegen-*`, `20261027-array-local-copy-*`, `20261027-four-queue-raw-analysis.json`, `20261027-mpsc-cursor-ab-*`, `20261027-faa-teardown-ab-*`, `20261027-faa-block512-ab-*`. 시제품은 엔진 정본이 아니다.

## 남은 STL 전환

프로파일러 준비 창의 스레드별 타임라인 인덱스를 `ce::node_hash_map`으로 변경했다. 정렬된 깊이 배열은 그대로 유지한다. 준비된 레인 조회와 reader 초기화 후에도 기존 스냅샷이 살아 있는지 검사를 추가했고, 전체 프로파일러 본 검사 1,398건과 선택한 reader 결함 주입을 통과했다. 맵의 실제 UI 프레임 성능은 측정하지 않았다.

## 최종 재수용과 제품 검증

20261027-four-full1은 엔진 내부 정본의 소스·바이너리 해시와 258개 프로세스 측정 결과를 검증했으며 **전체 FAIL**이다. 기존 조건과 판정 기준을 유지했다. 일반 81/82, MPSC batch8 주 기준 4/4, MPSC 단일 전송 2/4, FAA/PPL 6/6, SPSC·spin MPMC 8/8이다. 별도 UTF-16/UTF-8 성능 시험은 57/57이다.

이전 미달 항목인 8바이트 문자열 복사(0.8936~0.9043), 예약 배열 64(0.9770~1.0521), 4096(0.9746~1.0006), 65536(1.0269~1.0387), MPSC batch8과 FAA/PPL 여섯 조건은 이번 실행에서 기준 내다. 그러나 MPSC 단일 전송 64/4의 3회차는 1.1165로 한도를 초과했고, 64/1의 1회차는 PPL 편차 1.3068로 1.30을 넘었다. `map_miss/65536` 3회차는 자체/STL 비율 0.3007임에도 STL 편차가 1.3988로 실패했다. STL 원시 표본은 약 44.9~67.9ms였다. MPSC 64/4 느린 회차는 생산자 재시도 약 8만~10만 회가 관찰되었으나 원인은 아직 확정되지 않았다. 기존 실패를 제거하거나 기준을 완화하지 않았다.

Windows MSVC 모듈 기능 16/16, ASan 16/16, Linux Clang 모듈 26개와 ThreadSanitizer 13 실행을 통과했다. 프로파일러 1,398 검사와 결함 주입 검증을 통과했다. 실제 Debug Editor는 빌드 후 17개 명령, 렌더, UTF-16, 2회 8192 전송, Play/Stop과 장면 복원을 통과했다. 이는 성능 전체 합격을 의미하지 않는다. 엔진·에디터 등 범위의 남은 명시적 STL 참조는 9,406건(970개 파일)이며, 외부 코드·생성물·컨테이너 구현 및 매크로 확장은 집계에서 제외했다.

원시 결과와 판정: 외부 `CreatorContainers/results/20261027-four-full1-verdict.json`, `20261027-four-full1-*`, `20261027-four-unicode1-verdict.json`. 최종 엔진 Editor 로그 `Build/container-four-final-editor.log`, `Build/Verification/ContainerMigration/FourFinalDebug1/acceptance.json`. 후속 작업은 MPSC 단일 전송의 재시도 및 스케줄링 경합을 추가 계측하고, STL 기준 측정의 편차 원인을 독립적으로 조사한 뒤 기존 기준으로 전체 재수용하는 것이다.
