한 프레임의 실행과 수명 경계

Editor와 Player가 공유하는 simulation 순서, 각 Host의 표시·구조 변경 책임, frame과 physics tick의 차이를 설명한다.

기준: master 493536e300e274cbf59989cdd62b20310c8ae64f. 현재 소스와 호출부를 대조해 다시 썼다. 이번 개정에서는 빌드·테스트·제품 실행을 수행하지 않았다.

공통 진입점재생·편집·일시정지 분기프레임 내부의 실제 소비 순서Player 책임Editor 책임파괴·이송·비동기 작업이 페이지가 보장하지 않는 것

공통 진입점

두 Host는 입력을 갱신한 뒤 Runtime::TickSimulationFrame(delta)을 호출한다. 이 함수는 Initialization → InputEvents → managed PrePhysics → Physics → GameLogic → managed PostPhysics 순서를 소유한다. 표시·렌더 frame packet·Editor 전용 상태 머신은 이 함수 밖에 있다.

ResolveFrameDelta는 game pause이면 0, 아니면 TimeSystem의 elapsed seconds를 반환한다. Editor 편집 분기는 별도로 GameLogic(0, animationDelta)를 사용하므로 “모든 delta 0 호출은 pause뿐”이라고 일반화하지 않는다.

재생·편집·일시정지 분기

Editor는 요청값 IsGameStart가 아니라 IsPlayCommitted로 실행 분기를 결정한다. snapshot과 physics start가 성공하기 전 게임 한 틱이 저작 문서에 섞이지 않게 하기 위함이다. 편집 중에는 Editor/InputEvents와 native GameLogic을 호출하지만 managed simulation 틱은 실행하지 않는다. animation delta는 preview를 위해 별도로 흐른다.

공통 simulation 함수는 Initialization/InputEvents 후 pause를 확인한다. pause면 Pausing을 호출하고 앞/뒤 관리 틱과 physics/GameLogic을 생략한다. pending scene structure change가 있으면 관리 앞/뒤 틱을 모두 생략한다. CLR가 ready가 아니어도 관리 경계를 건너뛴다.

프레임 내부의 실제 소비 순서

PrePhysicsTick은 registry membership flush, live Scope의 시간 진행, continuation drain, enabled script PrePhysics 순이다. physics는 Scene::FixedUpdate에서 layer와 transform을 commit하고 ScenePhysicsSimulation::Advance를 호출한다. 내부는 1/60초·최대 4 catch-up이다. C# PrePhysics가 각 물리 tick 앞에서 반복되는 것은 아니다.

GameLogic은 Scene::Update → YieldNull → InternalAnimationUpdateEvent → Scene::LateUpdate 순이다. Update에는 Animator/Decal/Foliage/UI/Sound/Camera/Light/PlayerInput/Tween 전용 시스템과 world-matrix sync가 있다. animation scheduler는 별도 내부 event에서 두 job group을 join하고 pose를 owner thread에 게시한다. LateUpdate는 sound, render data, AI 완료값 적용을 수행한다.

post 관리 경계는 registrations → physics events → animation events → named script messages → AI ticks를 flush한 뒤 PostPhysics를 호출한다. ContactStream span은 이 PostPhysics가 끝나면 비워진다.

Player 책임

PlayerMain::Update는 presentation의 BeginSimulationFrame과 latency marker를 다루고 Time::Tick 안에서 입력과 공통 simulation을 호출한다. 실패한 presentation 시작은 exit code/종료 요청으로 전달된다. 물리 성공과 presentation 성공은 별개의 판정이다.

공통 틱 뒤에는 ApplyPendingSceneStructureChange, OnRender yield, enable/disable, EndOfFrame, managed boundary collection이 이어진다. 전용 RenderThread는 봉인된 packet/delta를 소비하므로 live Scene 순회를 위해 새 프레임의 Scene 포인터를 빌리는 구조가 아니다.

마지막 오디오 흐름은 AudioHost::Update → PlaybackService::Update → audio profile publication이다. Development profiler frame publication과 startup failure 종료 정책도 Host 책임이다. RuntimeFrame 함수만 읽어서는 전체 Player frame의 종료·표시 순서를 알 수 없다.

Editor 책임

Editor는 play mode/input controller와 selection/preview 상태를 관리한다. 편집 분기는 native GameLogic 시간 0과 animation preview delta를 구분한다. “편집 중 어떤 시스템도 안 돈다”는 설명은 틀리다.

실행 중에는 Editor 훅을 더한 후 같은 RuntimeFrame을 사용한다. scene structure transaction과 render/presentation의 안전 구간은 Editor Host가 보장한다. play 요청을 넣은 자리에서 Entity 목록을 곧바로 교체하지 않는다.

Editor의 audio catalog refresh·preview는 simulation과 별도다. UI/asset 편집·render demand·screen extent 변경도 Host 영역이다. 이 페이지는 Editor 전체 UI event loop나 모든 render pass의 제출 순서를 한 장의 simulation 순서로 축약하지 않는다.

파괴·이송·비동기 작업

Scene::EndFramePass는 AI 결과를 회수/폐기하고 FlushPendingDestroy 뒤 실제 component/entity 제거를 진행한다. SceneManager는 공유 GCCE domain에서 frame boundary collection을 수행한다. destroy mark, lifecycle cleanup, graph edge 제거, collection은 같은 사건이 아니다.

animation worker는 Update 안에서 join된다. AI worker는 불변 visibility snapshot만 계산하며 owner가 registration/tree revision을 확인한다. Scene load는 결과 future가 ready가 되기 전 owner blocking wait 대신 pump가 필요하다. DDOL 이송은 scene handle을 바꿀 수 있으나 별도 script object identity와 공유 domain을 유지한다.

이 페이지가 보장하지 않는 것

frame order를 읽은 결과이며 fps·latency·GPU 실행·무누수·플랫폼별 동작을 실행 검증한 문서가 아니다. 고정 물리 accumulator는 네트워크 fixed simulation tick이나 C# OnSimulationTick 구현을 의미하지 않는다. rendering/backend 상세는 해당 렌더 문서, 스크립트 수명은 ScriptCore 계약, spatial/UI resolve는 Transform 계약을 따른다.
