렌더러 이식 결정의 현행 해설

기준: master 493536e300e274cbf59989cdd62b20310c8ae64f의 소스와 실제 호출 배선. 이번 개정에서는 빌드·테스트·GPU 실행을 하지 않았다. 구현 존재와 실행 수용을 구분한다.

과거 이식 기록을 읽는 기준

이 경로는 DX11→DX12 이식의 상세 기록으로 사용되었다. 지금은 당시 임시 경계와 현행 계약을 구분하기 위한 해설이다. 오래된 pixel sample 수·selftest 통과 수·임시 DX11 wrapper·CB/CE barrier 설계를 현재 제품 지원으로 재사용하지 않는다. 현재 GPU 실행 결과는 이번 감사에서 확인하지 않았다.

남아 있는 RHI 설계 원칙

상위 pass는 중립 IRenderDeviceServices·RHIEncoder·resource/format/state 타입을 사용하고 native device·descriptor·command 구현은 backend 경계에 둔다. 중립 인터페이스를 DX12 전용 헤더 안에 놓아 Vulkan 소비를 막지 않는다. 실제 소비자가 요구하는 작은 수직 슬라이스로 API를 추가하고 선언만 넓혀 두 backend 지원이라고 부르지 않는다.

DX12DeviceResources와 VulkanRenderServices의 구현 존재는 픽셀 동등성을 뜻하지 않는다. resource create→upload→binding→command→completion의 실제 caller와 실패 경로를 확인한다. 단일 graphics completion scalar를 임의 multi-queue fence처럼 비교하지 않는다.

스레드와 소유권의 변화

Editor/Player는 불변 frame packet을 발행한다. renderer는 이를 소비해 view별 graph·display·history를 소유한다. UI/GT의 scene 구조 변경 보호와 renderer의 GPU 수명은 다른 동기화 문제다. 삭제된 전역 camera container나 옛 CommandBuild barrier를 새 기능의 전제로 복원하지 않는다.

parallel recording은 독립 callback이 sealed 입력을 읽는 범위에서만 허용한다. GPU 의존성은 graph usage가 소유한다. queue admission과 completion, abort와 rejected submission을 구분하며 callback 종료가 GPU 완료는 아니다. shutdown은 진행 중인 소비자·GPU 소유자를 먼저 정리한 뒤 scene/device 자원을 해제해야 한다.

패스·PSO·조립의 변화

PSO cache와 shader schema는 실제 format·layout·permutation을 정확히 식별해야 한다. 과거 고정 GBuffer/Deferred 패스 목록은 METEOR stage 조립으로 바뀌었다. SceneHost가 geometry·surface·HDR를 소유하고 SceneSurfaceTargets는 생성/clear에 제한된다. LivePipelineDesc는 지속 조립, EnhancedRenderGraph는 프레임 실행이며 선언 순서를 GPU 실행 순서로 고정하지 않는다.

옛 SpriteFont/DirectXTK UI 이식 계획도 현재 SDF font atlas·UIRenderProxy 경로의 기능 설명이 아니다. source와 실제 draw caller를 다시 확인해야 한다.

이식 완료를 판정하는 방법

중립 선언 수나 backend 외부 native include 수만으로 완료하지 않는다. 같은 sealed 입력의 두 backend resource·binding·attachment를 비교하고 unsupported를 명시한다. Debug validation과 Release 측정, capture frame과 normal frame을 분리한다. 자산 부재로 실행하지 못한 경로를 기계적 1:1 이식이라는 이유로 픽셀 통과 처리하지 않는다.

당시 임시 bridge·진단·측정 이력은 저장소 이력에서 찾을 수 있다. 현행 확장 기준은 RenderPipelineFlow.md, RenderGraphDependencySchedulingPlan.md와 RhiGpuMemoryLifetimeDesign.md이며 이 문서는 오래된 완료율을 유지하는 원장이 아니다.
