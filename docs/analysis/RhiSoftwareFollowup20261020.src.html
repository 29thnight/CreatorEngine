전체 대조·링크 정리 원장

현행 계약과 이 문서의 적용 범위

  • 제품 live graph는 명시적 버전과 dependency order를 사용한다. 선언 metadata 재사용과 dependency recording은 현재 구현 기반이다.
  • 소프트웨어 RHI의 frozen recording은 독립 target의 병렬 native 번역과 조기 sealed-batch handoff를 지원한다. 직렬 전용 번역·별도 C# SRP 저작 전환을 후속 필수 작업으로 두지 않는다.
  • queue/alias/hazard·reader join·retirement를 보존하고 실제 overlap·fallback·whole-frame 비용으로 RG8 채택을 판정한다.

이 문서는 연구/운영/표현 가이드 성격이므로, 아래 파일은 관련 엔진 경계의 근거다. 문서의 제안 전체가 구현됐다는 증거로 해석하지 않는다.

이전 근거의 유효 범위

기존 세부 계약은 위 현행 구현과 모순되지 않는 범위에서 유지한다. 과거 수치·실행 통과·해시·장치 조건은 당시 기록이다. 로컬 산출물이 사라진 항목은 링크 대신 경로와 미보존 상태를 표시하며, 현재 master의 재실행 통과로 승격하지 않는다.

구현

  1. 기록 작업 그래프 재사용. RHI topology 변환 배열과 fallback handle 배열을 thread-local 저장소로 유지한다. scheduler는 노드 수·predecessor가 정확히 같은 완료된 enki 그래프를 원자적 슬롯에서 인수한다. 최대 8개, 각 4096노드·16384 dependency까지만 보관한다. 마지막 callback 참조가 해제되면 사용자 캡처와 실패 상태를 비우고 게시한다. 다음 제출은 실패 비트와 진단 시간을 초기화한다. scheduler admission·shutdown 잠금은 기존대로 동작한다.
  2. 입력 밀봉의 임시 트리 제거. geometry identity 검사, temporal 중복 검사와 이전 draw 조회를 정렬된 연속 배열로 바꿨다. 배열 용량은 유지하며 매 호출 map/set 노드를 생성하지 않는다. 이전 draw 포인터는 함수 종료 시 비운다. 이전 순서의 첫 동일 key를 선택하는 규칙, 정확한 mesh 신원, view/reset/topology/pose 조건을 유지한다. fallback bone 배열도 재사용한다.
  3. segment·budget·encoder 재사용. 프레임마다 지역 recorder를 만드는 제품 경로에서도 전역 저장소 풀을 이용한다. target별 segment 배열의 활성 prefix만 처리하며 recorder에서 batch로 소유권을 이동한다. 마지막 CPU 번역·취소 소비가 끝나면 초기화하고 원자적 슬롯으로 반환한다. 최대 8개·객체/배열 용량 합계 16MiB다. 명령 블록은 기존 비-pmr RenderArenaPool을 별도로 사용한다. 재사용 encoder는 현재 validator를 다시 연결한다.
  4. 논리적 패스 상태와 네이티브 캐시 분리. frozen software 번역 풀에서 첫 segment는 전체 native cache를 초기화한다. 이후 segment는 논리적 pipeline 바인딩을 비우고 알려진 root signature·descriptor heaps·PSO 캐시를 유지한다. 같은 PSO의 중복 설정을 생략한다. 각 패스는 유효 pipeline을 직접 바인딩해야 Draw/Dispatch할 수 있다. 일반 native callback과 native list reset은 전체 캐시를 초기화한다.

소유권 이전은 acquire exchange/release CAS를 사용한다. 원자적 슬롯의 포인터 및 크기 atomic은 is_always_lock_free로 검사한다. 새 pmr 사용과 프레임마다 생성하는 지역 컨테이너는 추가하지 않았다.
