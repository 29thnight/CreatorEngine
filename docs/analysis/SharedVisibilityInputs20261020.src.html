b7ccc2b1a 기준으로 shared 입력 생성 평균은 **0.09636→0.09200ms(-4.52%)**다. 최종 Game CPU p50은 13.46990ms이며 120 FPS의 8.33333ms 예산을 5.13657ms 초과한다. 120 FPS 목표는 미달이다. 최종 코드는 shared 경로의 조립 scratch와 메타데이터 소유만 변경한다.

최종 구현

PrepareMeshlets → PrepareInternal → Frame::DeclareMeshletBatch → BuildShared → ReserveUploadBatch/CreateBindings → SharedBatch::Dispatch 경로에서, BuildShared는 최대 8뷰·4096개 bin을 합친다. candidate의 view/bin/job offset, 5행 world/bounds, projection/history, 출력 UAV 및 geometry/topology SRV를 구성한다.

  • Shared 조립은 BufferPool::UploadScratch 대신 기존 ce::RenderArenaPool의 독점 lease로 descriptor 배열을 구성한다. 이 풀은 8개 CAS 반환 슬롯과 최대 16MiB retained raw block을 사용하며 pmr을 사용하지 않는다. 중첩 선언도 별도 lease를 받는다. 함수 종료 시 CPU 조립용 아레나를 즉시 반환한다.
  • HZB owner와 밀봉 입력 owner는 고정 8칸 배열이다. 진단용 count vector와 복사를 없애고 보유한 MeshletInputs::bins에서 값을 읽는다. MeshletInputs에는 Frame 역참조가 없어 순환 소유가 없다. Frame·graph callback·upload retirement가 GPU 입력과 batch 수명을 유지한다.
  • Batch 객체는 renderer allocator로 만든다. batch 객체와 lease control block의 할당은 남으며 raw block을 재사용한다. Shared descriptor scratch의 mutex 획득과 vector proxy/capacity 관리가 제거됐다.
  • Shared GPU 입력의 6개 업로드 요청과 6개 descriptor table 생성, job/bin 배치, shader와 dispatch는 기존 계약을 사용한다. 단일 뷰 업로드 및 DX12 리소스 해소는 기존 구현이다.

뷰별 candidate/bin vector, 선언 scratch mutex, buffer/readback pool mutex와 매 배치 descriptor 생성 비용은 남는다. 이번 변경이 엔진 전체의 할당·잠금을 제거하지는 않는다.

검증 중 제외한 변경

초기 실험에는 단일 뷰의 history projection 업로드 통합과 DX12 descriptor 리소스 포인터 재사용이 포함됐다. 추가 LOD 검증에서 픽셀 깊이 회귀가 발생했다. 변경 전 엔진 3개 소스와 실행 파일을 baseline-build에 별도 보관해 같은 검사로 비교했다. 기준 엔진은 32프레임·7212픽셀·header 224개를 통과했다. 전체 실험은 actual 0.194015/expected 0.249719, DX12 변경을 제외한 visibility 실험도 actual 0.248759/expected 0.249719로 실패했다.

단일 뷰 변경을 원복하고 shared 조립만 남긴 shared-isolated는 전체 검사를 통과했다. 단일 뷰 업로드 확장과 DX12 포인터 재사용은 최종 변경에서 제외했다. 실패 결과를 보존하며 성능 수용 근거로 사용하지 않는다.

초기 회귀 도구에는 별도의 잘못된 기대값도 있었다. 현재 master shader는 GeometryPrepareMeshlet에서 LOD 선택·residency를 통과한 meshlet만 큐에 게시하지만 검사는 전체 입력이 게시돼야 한다고 요구했다. 첫 진단은 입력 13, 게시·완료 6, 오류 0, partition 208/208, 잔여 작업/lease 0이었다. master 원문 비교는 assertion-origin.txt에 보관했다.

검사는 게시 수가 입력 상한 이내이며 완료 수와 정확히 같아야 하고, 게시 0/비0에 맞춰 working wave가 0/비0인지 확인하도록 수정했다. 오류 0, partition 전수 처리, head/tail 회계, 빈 슬롯, 작업·lease 0, 독립 partition 계산 및 픽셀 검사를 유지했다. 거절 partition의 범위와 0 < publishedJobs < sealedJobs도 검사한다. 이 수정 뒤 발견된 픽셀 회귀를 기준 엔진과 비교해 위와 같이 제거했다.
