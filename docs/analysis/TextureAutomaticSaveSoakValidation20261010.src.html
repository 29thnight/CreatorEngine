방법과 수용 경계

격리된 Tiny4/SavedFixture 프로젝트에서 실제 Inspector 숫자0→2 입력의 저장 대기를 관찰하고 정상 저장·재임포트가 끝난 뒤 연속 검증을 시작했다. 이후 입력은 실제 UI 반복이 아니라 같은 QueueAutomaticTextureSettings API의 자동 반복이다. 실제 Editor 프레임 루프·자산 서비스·watcher·cook/publication을 유지한 채 실행한다.

회차마다0→2를 연속 queue해 최신 설정으로 병합하고 다음 네 경우를 순환한다.

  1. 정상 저장: 최종 maxDimension2 및 오류 없음.
  2. 외부 유효 설정1: 대기 편집 거부·외부 bytes 유지 후 baseline 복원/새 자동 저장2.
  3. metadata 삭제: 대기 편집 거부·재생성 금지 후 baseline 복원/새 자동 저장2.
  4. metadata 손상: 대기 편집 거부·손상 bytes 유지 후 baseline 복원/새 자동 저장2.

네 경우 모두 일반400ms 대기와 명시적 FlushAutomaticSaves 경로를 번갈아 거친다. 명시적 flush 반복은 매회 실제 종료/창 닫기를 반복하는 검증이 아니다. 매 회차 원본 PNG·저장 씬을 대조하고 다음 회차와 최종 종료 전에 TextureImportReady를 기다린다. 각 단계30초·전체15분 timeout을 둔다. 연속 구간은300초 이상이며 중간 회차를 완료하고 정상 metadata 상태에서 끝낸다.

끝에서 object.describe UnsavedT0Texture가 성공하는지 확인하고, 실제 창 종료 뒤 exit0·Finalize·DX12 pending0/0/0·PNG/GUID/저장 씬/runtime 및 검증 입력 hash를 대조한다. verify-texture-auto-ui-soak.ps1은 receipt와 종료 후 상태를 판정하며 UI 입력을 생성하지 않는다. 제품 저장 구현은 이번 검증에서 변경하지 않았다.

남는 경계
