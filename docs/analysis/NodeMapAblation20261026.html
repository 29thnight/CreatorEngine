분석

노드 맵 중복 탐색·키 삭제 경로 분리 계측

삽입 위치 탐색 재사용은 생성·삽입·파괴 종합 시간에서 약 2.6~4.1% 개선을 보였다. 키 삭제의 다음 반복자 탐색 제거는 이번 측정에서 뚜렷한 시간 이득을 입증하지 못했다. 두 변경을 합쳐도 STL 수용 기준에는 도달하지 않았다. 앞서 지적한 두 중복 작업만으로 전체 성능 미달을 설명할 수 없다는 결과다.

§00

실험 구성

엔진 정본 Engine/Containers/modules/node_hash_map.ixx를 입력으로 실험용 named module을 자동 생성했다. 공통 배열·할당자·해시는 엔진의 Creator.Containers를 직접 import한다. 실험용 구현은 외부 CreatorContainers/experiments/20261026-node-map-ablation에 있으며 정본으로 사용하지 않는다. 원본 위치와 해시, 생성기 및 생성 결과를 함께 보존했다.

변형변경
canonical변경 없는 엔진 정본
baseline실험용 기준 구현, 두 변경 꺼짐
reuse중복 키 검사에서 찾은 삽입 위치 재사용
erase키 삭제 시 사용하지 않는 다음 반복자 탐색 생략
bothreuse와 erase 결합

reuse는 tombstone을 발견해도 중복 키 검사를 끝까지 수행한다. 재해시 또는 tombstone 정리가 필요하면 새 인덱스에서 삽입 위치를 다시 찾는다. 인덱스 준비와 값 생성이 모두 성공한 뒤 발행하는 기존 예외 보장을 유지한다. erase는 키 기반 삭제만 바꾸며 다음 반복자를 반환해야 하는 반복자 삭제는 유지한다.

MSVC 19.50.35730.0 x64 Release에서 5개 변형을 하나의 실행 파일에 넣었다. 64·4,096·65,536개 키와 생성·성공 조회·실패 조회·삭제 후 재삽입의 12조건을 각각 3개 독립 프로세스에서 실행했다. 총 180조건, 각 측정의 양쪽 15개 원시 샘플을 모두 유지했다. 배치는 기존 노드 맵 검사와 동일한 30ms 목표이며 각 컨테이너를 독립 보정한다. 변형 순서와 두 번째 반복의 A/B 순서를 뒤집었다. CPU4 측정 스레드와 기존 CPU5 SMT helper를 사용했고 수집 중에는 빌드하지 않았다.

충돌·재해시 후 참조 안정성·복사 실패·할당 실패·tombstone 뒤 중복 키 회귀를 네 실험 조합 모두에서 검사했다. 일반 검사 4/4와 AddressSanitizer 검사 4/4가 통과했다. 작업 횟수 카운터는 별도 실행 파일에서만 켜고 시간 측정 변형에서는 컴파일 시 제거했다.

§01

변경별 시간 효과

양수는 실험용 baseline보다 빨라진 비율이다. 각 조건의 독립 프로세스 3개에서 얻은 키당 시간 중앙값을 사용했다. 생성 조건은 reserve·삽입·파괴를 모두 포함하므로 순수 삽입 시간으로 해석하지 않는다.

별표 조건은 키 삭제 경로를 실행하지 않으므로 해당 차이를 삭제 최적화의 효과로 해석하면 안 된다. 이 수치들은 프로세스·코드 생성·배치 상태 차이가 만드는 대조 오차의 크기도 보여준다. 정본과 실험용 baseline의 조건별 키당 시간 중앙값 차이는 전체 12조건에서 0.78% 이내였다. 다만 65,536개 생성의 개별 반복 차이는 이보다 컸다.

4,096개 삭제 후 재삽입에서 탐색 재사용의 같은 반복끼리 비교한 개선율은 1.924.06%였고, 키 삭제 분리는 0.120.64%였다. 삭제 분리의 작은 이득은 정본·실험용 기준 구현의 차이와 비교해 확실한 속도 개선으로 단정하지 않는다. 두 변경의 개선율을 단순 합산할 수도 없다.

§02

실제 제거된 작업

카운터의 삽입 조건은 reserve 후부터 세며 최종 파괴는 포함하지 않는다. 삭제 후 재삽입 조건은 이미 채운 맵에서 각 키를 한 번 삭제하고 다시 삽입한다. 다음은 4,096개 키의 결과다.

추가 삽입 위치 탐색은 실제로 사라졌다. 삭제 분리도 반복자 확인을 약 60% 줄였지만 시간 이득은 작았다. 슬롯 확인 횟수 감소율을 실행 시간 개선율로 환산하면 안 된다. 노드 할당·해제 횟수는 그대로이며, 이번 실험만으로 할당·해제가 잔여 시간에서 차지하는 비중을 확정할 수 없다.

§03

수용 판정과 한계

STL 대비 비율 ≤ 1.10 및 양쪽 편차 x[13]/x[1] ≤ 1.30을 각 반복에 적용하면 canonical 18/36, baseline 17/36, reuse 18/36, erase 18/36, both 18/36이다. 따라서 두 변경 모두 현재 맵의 전체 성능 수용을 달성하지 못했다.

4,096개에서 both의 STL 대비 비율 중앙값은 생성 1.148, 삭제 후 재삽입 1.180이었다. 생성 조건은 STL 쪽 편차도 약 1.5까지 커서 미달 원인을 중앙값 하나로만 판단하지 않는다. 실패 조회 경로는 두 변경으로 바뀌지 않는다. 다음 비용 분리는 노드 할당·해제, 인덱스 초기화 및 실패 조회의 탐색 비용을 대상으로 해야 한다. 엔진의 노드 맵 구현에는 이번 실험 변경을 적용하지 않았다.

§04

증거

외부 CreatorContainers/results에 다음 자료를 보존했다.

  • 20261026-node-map-ablation1-ablation.json: 180조건, 원시 샘플 재검산, 입력·바이너리 해시.
  • 20261026-node-map-ablation1-effects.json: 조건별 중앙값, 개선율, 반복 간 범위, 수용 결과.
  • 20261026-node-map-ablation1-<variant>-<run>.csv: 15개 원시 샘플과 요약.
  • 20261026-node-map-ablation1-snapshot: 당시 입력과 동일 실행 파일.
  • 20261026-node-map-ablation1-guard-guard.json: helper의 전체 수집 구간 생존·정상 종료.
  • node-ablation-counts.csv: 시간 측정과 분리한 작업 횟수.
  • node-ablation-correctness.log, node-ablation-asan-correctness.log: 네 조합의 회귀 검사.

생성기는 정본을 읽어 실험용 모듈을 다시 만들며, 외부 주 구현은 계속 엔진 정본을 참조한다. CE_NODE_MAP_ABLATION 옵션은 기본 OFF다.
