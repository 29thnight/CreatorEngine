# 노드 맵 추가 비용 분리와 성능 수용

노드 할당 묶음화와 제어 바이트 인덱스를 결합해 엔진 정본에 반영했다. 최종 정본 바이너리는 18조건 × 3개 독립 프로세스, 54/54를 통과했다. 모든 반복의 최대 STL 대비 시간 비율은 0.912483이고, custom 최대 편차는 1.104160, STL 최대 편차는 1.133654였다. 이전 실험에서 결합 구현은 45/45, 같은 측정 조건의 기존 구현은 21/45였다.

## 추가로 분리한 비용

기존 구조의 삽입 위치 재탐색 제거는 약 2.6~4.1% 개선에 그쳤고, 키 삭제의 다음 반복자 탐색 제거는 뚜렷한 시간 이득을 입증하지 못했다. 이번에는 아래 네 구성을 같은 실행 파일로 비교했다.

| 구성 | 노드 저장 | 인덱스 |
| --- | --- | --- |
| baseline | 노드별 할당·해제 | 기존 포인터+전체 해시 슬롯 |
| pool | 기존 맵에 진단용 노드 풀 allocator 적용 | 기존 인덱스 |
| index | 노드별 할당·해제 유지 | 작은 제어 바이트 인덱스 |
| combined | 맵 소유 노드 풀 | 작은 제어 바이트 인덱스 |

원인 분리 예비 측정은 기존 30ms 교대 프로토콜로 구성별 한 프로세스, 15조건과 양쪽 15개 원시 샘플을 수집했다. 다음은 4,096개 키의 키당 시간(ns)이며 순수 함수 하나의 비용 비중을 뜻하지 않는다.

| 조건 | baseline | pool | index | combined |
| --- | ---: | ---: | ---: | ---: |
| 생성·예약·삽입·파괴 | 89.33 | 33.50 | 84.12 | 22.86 |
| 성공 조회 | 9.38 | 8.83 | 6.90 | 7.70 |
| 실패 조회 | 13.57 | 13.55 | 9.40 | 10.89 |
| 삭제 후 재삽입 | 98.96 | 39.65 | 89.05 | 32.29 |
| 빈 맵 예약·정리 | 3.45 | 3.01 | 0.07 | 0.07 |

노드 풀만으로 실패 조회가 해결되지 않았고, 인덱스만 바꾸면 생성·재삽입의 개별 할당 비용이 남았다. 결합해야 두 경로의 미달을 함께 해소할 수 있었다. 진단용 pool allocator의 상태 관리 비용도 pool 열에 포함된다. 정본은 그 진단 allocator를 사용하지 않고 맵이 직접 풀을 소유한다. 작은 차이나 비가산적인 결과를 순수 할당 비용의 정확한 백분율로 해석하지 않는다.

## 실제 할당과 초기화 구조

별도 카운터 실행에서 4,096개 키의 생성 시 backing 할당은 기존 4,097회에서 65회로 줄었다. 이후 한 번의 전체 삭제·재삽입에서는 기존 4,096회였던 backing 할당과 해제가 모두 0회가 됐다. 값의 소멸은 삭제 즉시 수행하고, 저장소만 재사용한다. 삭제한 원소의 참조는 즉시 무효다.

인덱스 요청 바이트는 149,872에서 73,728로 줄었다. 기존 인덱스는 16바이트 슬롯을 dynamic_array의 기하 성장으로 할당해, 논리 용량 8,192보다 큰 backing 용량 9,367을 사용했다. 새 인덱스는 포인터와 1바이트 제어 영역을 한 블록에 정확히 할당한다. 초기에는 제어 영역만 0으로 만들며 비어 있는 포인터 영역은 읽지 않는다. 이 수치는 allocator에 요청한 바이트이며 프로세스 working set이나 OS heap 부가 비용을 포함하지 않는다.

실패 조회는 제어 바이트로 빈 슬롯과 해시 지문을 확인한 뒤 필요한 경우에만 노드 키를 읽는다. 삽입 위치는 중복 검사에서 재사용하고, 재해시할 때만 새 위치를 다시 찾는다. load factor 한계는 기존과 같고 삽입마다 반복 계산하던 성장 한계는 설정·재해시 시 갱신한다.

## 소유권과 예외 보장

노드는 재해시로 이동하지 않아 참조와 값 주소가 유지된다. 작은 값의 풀 블록은 64개 셀로 구성하며 값 크기에 따라 16개 또는 1개로 줄인다. 슬롯 재사용은 먼저 비어 있는 셀을 사용하므로 풀은 최고 동시 사용량에 맞춰 성장한다. 삭제 후 메모리는 맵에 남아 재사용되며 `clear()`와 소멸에서 반환한다. 즉시 노드별 반환이 필요한 byte allocator 정책은 여섯 번째 템플릿 인수 `PoolNodes=false`로 선택할 수 있다.

인덱스와 새 풀 블록은 값 생성이 성공한 뒤 발행한다. 할당 실패, 값 생성 실패, 재사용 셀의 생성 실패, 블록 경계 할당 실패, 재해시 중 hash 예외에서 기존 원소·용량·주소와 할당 상태를 검사했다. 128바이트 정렬 값, 복사·이동, tombstone 뒤 중복 키, 낮은 load factor, clear 후 재사용, 즉시 반환 정책도 회귀 검사에 포함했다. load factor 0.875에서 삭제 흔적으로 빈 슬롯이 없어지는 경계도 추가했다. 조회와 삽입 탐색을 용량 이내로 제한해 종료시키고 이후 성장 및 참조 안정성을 검사한다.

MSVC 엄격 경고 검사에서는 즉시 반환 옵션의 `if constexpr` 분기를 명확한 `else`로 나눴다. 패딩이 필요한 정렬 클래스에는 해당 선언 범위에서만 C4324를 처리했다. 함께 드러난 0비트 bitset의 checked 연산은 크기 0에서 곧바로 예외를 던지는 별도 constexpr 분기로 정리했다.

## 측정 조건과 판정

기존 교대 30ms 진단에서는 STL 생성 시간의 편차가 약 1.5로 반복 관측됐다. 최종 검사는 기존 전체 모듈 수용에서 사용하던 100ms 독립 배치, 측면별 1초 워밍업, 측면별 자기 프로세스 heap 최적화와 grouped 수집을 적용했다. 이 제어 묶음 중 하나만을 단독 원인으로 확정하지 않는다. 같은 프로토콜에서 기존 구현은 21/45, 결합 실험은 45/45여서 프로토콜 변경만으로 기존 구현이 통과한 것은 아니다.

최종 소비자는 `import Creator.Containers;`를 사용하며 구현 헤더나 실험용 맵을 포함하지 않는다. uint64 키·값에서 64·4,096·65,536개 키, 기존 네 연산에 예약·미예약 성장까지 18조건을 세 독립 프로세스에서 측정한다. 두 번째 반복은 컨테이너 수집 순서를 뒤집는다. 모든 15개 원시 샘플을 보존하고, 각 반복에서 비율 ≤ 1.10 및 양쪽 편차 x[13]/x[1] ≤ 1.30을 요구한다. CPU4 측정과 한시적인 CPU5 helper를 사용하고 빌드와 기능 검사를 종료한 뒤 수집한다.

일반 named-module 기능 검사 13/13, AddressSanitizer 13/13, Linux Clang 18 ThreadSanitizer 11개 실행 검사가 통과했다. 엔진 MSVC 모듈 프로젝트도 빌드했다. 이번 성능 수용은 위 노드 맵 조건의 범위다. 문자열 등 다른 키의 성능, 전체 컨테이너 82조건 재수용, 남은 엔진 STL 사용처 교체와 최신 전체 에디터 실행을 대신하지 않는다.

## 증거 위치

외부 `CreatorContainers/results`에 원시 자료와 당시 소스·바이너리를 보존한다.

- `20261026-node-opt-screen1-*`: 할당·인덱스 개별 대조군 60조건과 입력 스냅샷.
- `node-opt-cost-counts.csv`: 할당 요청 횟수·바이트 및 해제 카운터.
- `20261026-node-opt-controlled1-*`: 기존/결합 구현의 같은 통제 프로토콜 90조건.
- `20261027-node-map-final3-*`: 최종 정본 바이너리의 54조건, 입력 해시, 영수증과 스냅샷.
- `node-map-bounded-driver.log`, `node-map-bounded-asan-driver.log`, `node-map-bounded-tsan-driver.log`: 최종 기능·메모리·이식성 검사.

엔진 빌드 로그는 `Build/container-node-map-bounded-contracts.log`다. 운영 구현 정본은 계속 `Engine/Containers`이며 실험 디렉토리는 기본 빌드에서 제외한다. 과거 실험을 재생할 때는 기록된 정본 스냅샷을 사용하도록 생성기에 epoch 검사를 추가했다.
