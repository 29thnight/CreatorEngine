UTF-16 기본 문자열과 ImGui 입력 통합

표·제목에 적힌 상태7곳
완료·통과 7

2026-10-27 후속 최적화에서 기존 수용 기준을 유지해 57/57을 통과했다. UTF-8 2KB 추가 두 건도 해소했다. 원인 분리·수정·최종 재수용. 아래의 55/57은 초기 통합 당시 기록이다.

구현·기능·실제 IME·Editor Debug 실행 검증은 통과했다. 초기 통합 성능은 55/57이며 UTF-16 기본 문자열 조건은 18/18이다. UTF-8 2KB 재사용 추가 두 건이 미달이므로 전체 성능 수용 완료로 판정하지 않는다.

Engine/Containers/modules/string.ixx가 구현 정본이다. ce::string과 ce::string_view의 코드 단위는 char16_t이며, basic_string<Allocator>도 UTF-16이다. 기존 바이트 문자열은 utf8_string, utf8_string_view, basic_utf8_string<Allocator>로 명시했다. 생성 헤더는 동기화 도구의 산출물이며 외부 테스트 솔루션은 이 엔진 내부 구현을 직접 빌드한다.

§01

인코딩과 소유권 계약

  • 문자열 길이·인덱스·부분 문자열은 코드 단위 기준이다. UTF-16 코드 단위 2개가 하나의 보충 평면 문자를 나타낼 수 있다. 일반 배열식 변경은 코드 단위 연산이며 글자소 편집 API가 아니다.
  • UTF-8 표현은 ImGui의 char* API와 연결하기 위해 char 바이트를 사용한다. 로캘·ACP 변환을 사용하지 않는다. wchar_t의 플랫폼별 크기를 UTF-16 타입의 전제로 삼지 않는다.
  • to_utf8과 to_utf16은 전체 입력을 검증한 뒤 결과를 변경한다. 잘못된 서로게이트, 잘린 시퀀스, 잘못된 연속 바이트, 과잉 인코딩, 서로게이트 스칼라, U+10FFFF 초과를 거부하고 첫 오류의 코드 단위/바이트 위치를 반환한다. 잘못된 입력이나 할당 실패는 목적 문자열의 기존 내용을 보존한다.
  • 입력·목적 저장소가 겹치면 임시 소유 문자열에서 변환 후 교환한다. 일반 변환은 내장 NUL을 보존한다. ImGui 편집 API는 C 문자열 경계 때문에 내장 NUL을 명시적으로 거부한다.
  • 캐시는 UTF-16 원본 스냅샷과 UTF-8 결과를 모두 소유한다. 호출자 버퍼의 주소나 수명을 캐시 키로 신뢰하지 않는다. 같은 내용의 적중과 확보한 용량 안의 변경은 할당하지 않는다. 내용 비교 비용은 문자열 길이에 비례한다.
  • 캐시·입력 상태는 위젯별로 유지하며 ImGui 스레드에서 사용한다. 동시 접근용 컨테이너가 아니다. 확보 용량은 재사용하고 객체 소멸 때 반환한다.

§02

ImGui API와 실제 사용처

Editor/ImGuiHelper/Utf16Text.h에 editor::text::TextUnformatted, InputText, InputTextWithHint, InputTextMultiline을 추가했다. 모듈 또는 ContainerAPI.h로 컨테이너 API를 먼저 공급한다.

ce::string value(u"한글 \U0001F680");
ce::utf8_conversion_cache display;
ce::utf16_input_state editing;
// display와 editing은 매 프레임 생성하지 않고 위젯 수명 동안 보관한다.
editor::text::TextUnformatted(value.view(), display);
auto result = editor::text::InputText("##name", value, editing);

레이블과 힌트는 ImGui의 UTF-8 식별자/표시 규약을 유지한다. UTF-16 값은 소유된 UTF-8 편집 버퍼로 변환한다. resize 콜백은 버퍼 성장과 주소 갱신을 담당하고, 편집 결과는 검증 후 UTF-16 원본으로 확정한다. 편집 중 외부 값이 바뀌면 conflict를 보고하고 외부 값을 덮어쓰지 않는다. 포커스를 잃은 뒤 외부 값으로 재동기화하며, 외부 값이 기존 확정값으로 돌아오면 충돌을 해제한다.

콜백 플래그와 EnterReturnsTrue는 반환값 의미가 다른 별도 확장 API가 필요하므로 현재 명시적으로 거부한다. Release에서도 오류를 반환한다. 작업공간 이름 대화 상자를 이 UTF-16 입력 경로로 전환했다. 파일명 검증·저장은 UTF-8 경계에서 기존 로직을 계속 사용한다. 기존 파일 형식을 인코딩 변경으로 재해석하지 않는다. 식별자 atom과 기존 바이트 키 맵도 UTF-8 저장을 유지한다.

§04

실제 한글 IME

단순한 AddInputCharacterUTF16 호출을 실제 IME 통과로 간주하지 않았다. 엔진이 사용하는 ImGui 1.92.8 라이브러리, Win32 backend와 같은 입력 어댑터를 연결한 실제 D3D11 창에서 키를 입력했다. 해당 창의 한국어 IME 컨텍스트를 열고 g k s r m f Return으로 한글을 조합·확정했다. Windows 전역 설정이나 설치 언어 팩을 변경하지 않았다.

관측한 조합은 314E → D558 → D55C, 3131 → ADF8 → AE00이고 각 음절의 GCS_RESULTSTR을 확인했다. 최종 소유 문자열은 D55C AE00, 길이 2 코드 단위였다. 조합 중 미확정 문자열은 OS/ImGui가 유지하고, UTF-16 원본에는 확정된 입력을 반영한다. 최종 바이너리로 다시 수행한 20261027-unicode-ime-locked.log와 바이너리·소스 해시를 보존했다.

이 결과는 어댑터의 실제 Windows IME 경로 검증이다. Editor 작업공간 대화 상자를 UI로 열어 같은 입력을 반복한 결과로 확대하지 않는다. Editor 자체에서는 모듈 문자열·변환·입력 상태를 명령 프로브로 실행하고 작업공간 입력창 배선을 빌드했다. 기존 엔진의 한국어/보충 평면 폰트 fallback 설정도 유지한다.

§05

성능 비교 방법과 원인 분리

C++23 Release 소비자가 import Creator.Containers;로 정본 모듈을 사용한다. MSVC 19.50.35730.0의 std::u16string 및 std::string과 각각 같은 코드 단위·내용을 비교한다. 엔진 기능 빌드는 기존 도구 체인 요구에 따라 MSVC 19.51을 사용한다.

조건은 UTF-16·UTF-8 각각 5/64/2,048 코드 단위의 생성·재사용 추가 12개, ASCII+이모지 및 한글+이모지의 양방향 변환 4개, 캐시 적중/변경 2개, 입력 확정 1개로 총 19개다. 변환은 같은 엄격한 변환기로 출력 저장소만 ce/STL로 바꿔 비교한다. STL 자체 변환 알고리즘 대비 성능이라는 뜻이 아니다. 캐시도 STL 측에 같은 소유 스냅샷·내용 비교·변환 재사용을 적용한다. 입력 수치는 확정 처리이며 ImGui 레이아웃·GPU 렌더링 시간 비교가 아니다.

기존과 같이 각 측면 1초 워밍업, 100ms 독립 배치 15개, 측면별 자기 프로세스 heap 최적화, CPU4 고정과 한시적인 CPU5 helper를 사용한다. 세 독립 프로세스 중 두 번째는 측면 순서를 바꾼다. 모든 원시 샘플을 보존하고 각 프로세스·각 조건에 시간 중앙값 비율 ≤ 1.10, 양쪽 편차 x[13]/x[1] ≤ 1.30을 요구한다. 빌드·기능 검사를 종료하고 소스·바이너리 해시를 고정해 수집한다.

최초 구현은 34/57이었다. UTF-16 생성에서 임시 객체를 거쳐 할당·이동하는 경로를 제거한 진단 변형은 약 17~29% 개선됐다. 짧은 고정 폭 복사는 단순 직접 생성 대비 추가 이득을 입증하지 못해 채택하지 않았다. 추가 경로는 용량이 충분할 때 성장·별칭 검사를 건너뛰고, 성장 처리를 별도 함수로 분리했다. 겹치는 데이터의 복사는 계속 memmove로 보장한다.

분리 실험에서 성장 경로의 분리는 강제 인라인보다 유리했다. 적합 용량 경로만 바꾼 대조군에 비해 5/64 코드 단위 추가에서 약 19~25% 개선됐다. 이후 정본 재측정은 53/57이었으며, UTF-8 생성의 인라인 결정과 한 번의 4KB 추가 미달이 남았다. UTF-8 초기화 인라인을 보완했다. 순수 memmove와 네 주소 조합의 대조군에서는 차이가 약 4% 이내였으므로, 이전 18% 미달의 원인을 주소만으로 확정하지 않았다. 마지막 판정은 이 진단 수치가 아니라 아래 정본 바이너리 결과를 사용한다.

최초 수집 스크립트에는 helper 래퍼의 태그 변수 가림으로 CSV 이름에 -guard가 붙는 집계 오류가 있었다. 세 원시 CSV를 그대로 보존해 별도 회수 집계했으며, 수집 조건과 바이너리는 바뀌지 않았다. 후속 실행에서는 변수 이름을 고쳐 자동 판정을 수행했다.

§06

SIMD 대조군은 채택하지 않았다. 4KB UTF-16 추가에서 STL의 약 1.69배였고, 2KB UTF-8 추가도 약 1.60배였다. 이 복사본은 외부 진단 디렉토리에만 남기며 엔진 구현에 포함하지 않는다.

동일한 std::string끼리 버퍼만 달리한 네 쌍에서도 빠른 쪽 대비 느린 쪽이 약 19~29% 차이를 보였다. 같은 버퍼 쌍에 컨테이너 없이 memmove만 수행해도 차이가 관측됐다. 실제 객체 코드에서 ce와 STL의 해당 경로는 모두 CRT memmove를 호출한다. 버퍼 배치 영향을 구현 자체의 비용으로 곧바로 해석할 수 없지만, 이 대조군만으로 앞선 61% 미달 전체의 원인을 확정하지 않는다. 단일 버퍼 조건을 여러 버퍼 평균으로 바꿔 수용을 선언하지 않았으며, 이 항목의 원인 분리·성능 수용은 남겨 둔다.

§07

증거와 재현

외부 CreatorContainers는 엔진 내부 정본을 참조한다. 진단용 복사본은 CE_UNICODE_ABLATION=ON에서만 빌드하며 기본값은 OFF다. 일반 모듈 검사와 성능 소비자는 정본을 import한다.

외부 CreatorContainers/results의 주요 파일:

  • 20261027-unicode-final1-{1,2,3}.csv, 같은 이름의 .stderr: 모든 원시 샘플과 컴파일러·일부 버퍼 배치 정보.
  • 20261027-unicode-final1-verdict.json, -inputs.json, -snapshot/, -guard-guard.json: 최종 판정, 수집 당시 입력·바이너리, helper 수명 영수증.
  • 20261027-unicode-diag1-guard-{1,2,3}.csv, -recovered-summary.json: 최초 34/57과 집계 오류 회수 자료.
  • 20261027-unicode-ablation1.csv, -inlining1.csv, -ctor1.csv: 생성·적합 용량 경로·인라인 결정의 분리 측정.
  • 20261027-unicode-opt1-verdict.json: 중간 정본 53/57.
  • 20261027-unicode-addresses1.csv, -bulk1.csv, -address-self1.csv: 주소·복사 및 채택하지 않은 SIMD 대조군.
  • unicode-final1-disassembly.txt: 실제 소비자 객체의 호출 경로.
  • unicode-locked-normal-driver.log, unicode-locked-asan-driver.log, unicode-locked-linux-driver.log: 최종 기능 검사.
  • unicode-locked-build.log: 성능/ImGui 소비자와 Windows·독립 헤더 컴파일.
  • 20261027-unicode-ime-locked.log, -hashes.json: 최종 바이너리의 실제 Windows IME 조합·확정.

엔진 빌드는 Build/utf16-editor-locked-debug.log, 마지막 입력창 변경의 증분 빌드는 Build/utf16-editor-final-incremental.log다. 실행 증거는 Build/Verification/ContainerMigration/Utf16Debug1/acceptance.json과 results.jsonl이며 두 프로브의 utf16Strings=true를 요구한다. 수집 이후에는 외부 진단 타깃 등록만 추가했고 정본 구현·성능 소비자·바이너리는 바꾸지 않았다.

Windows/MSVC 문자열의 위 범위만 측정했다. Linux는 기능·ThreadSanitizer 검사이며 성능 수용이 아니다. macOS 성능, 최신 전체 82조건 및 PPL 큐 재수용, 기존 엔진 STL 문자열 전체 전환 완료를 이 결과로 대신하지 않는다.
