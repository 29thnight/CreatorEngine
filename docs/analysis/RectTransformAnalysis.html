RectTransform 좌표와 레이아웃 읽기

RectTransform의 저작 값, 파생 rect, Canvas와 화면 좌표 변환을 현재 구현 기준으로 설명한다.

기준: master 493536e300e274cbf59989cdd62b20310c8ae64f. 현재 소스와 호출부를 대조해 다시 썼다. 이번 개정에서는 빌드·테스트·제품 실행을 수행하지 않았다.

좌표와 저작 값축별 계산Canvas root와 배율dirty와 순회 소유권확인할 조합과 한계

좌표와 저작 값

anchorMin/anchorMax와 pivot은 y-down이다. (0,0)은 좌상단, (1,1)은 우하단이다. anchoredPosition은 부모 anchor reference에서 자신의 pivot까지 local offset이다. worldRect는 중심 원점 layout pixel 좌표이고 screen position은 좌상단 원점 pixel 좌표다.

저장하는 값은 anchor, anchoredPosition, sizeDelta, pivot이다. worldRect와 layoutScale/dirty는 derived cache이며 reflgen ignore다. 구 파일의 worldRect가 있다고 그것을 화면 크기 정본으로 쓰지 않는다.

축별 계산

size = parentSize × (anchorMax − anchorMin) + sizeDelta × scale

anchorReference = anchorMin + (anchorMax − anchorMin) × pivot

worldPivot = parentOrigin + parentSize × anchorReference + anchoredPosition × scale

rectMin = worldPivot − size × pivot

point anchor와 stretch anchor는 같은 식을 사용한다. GetAnchoredPosition은 world pivot을 반환하지 않는다. Get/SetWorldPivotPosition과 Get/SetScreenPosition을 목적에 맞게 선택한다. anchor/pivot setter는 world pivot 보존을 위해 offset을 역산한다.

Canvas root와 배율

screen Canvas는 GetScreenRootRect가 준 (−width/2,−height/2,width,height)를 DriveAsCanvasRoot로 받는다. 자식 offset과 sizeDelta에 Canvas scale을 곱하고 parent rect는 이미 pixel 단위다. 같은 배율을 두 번 적용하지 않는다.

Canvas의 ScaleWithScreenSize는 reference resolution과 MatchWidthOrHeight의 log-space 보간을 사용한다. ConstantPixelSize는 ScaleFactor를 사용한다. World Canvas는 sizeDelta/pivot의 local rect를 DriveAsWorldCanvasRoot로 만들고 spatial Transform을 수정하지 않는다.

dirty와 순회 소유권

UpdateLayout은 자신의 rect만 계산하고 실제 변경 여부를 반환한다. child recursion은 Scene driver가 맡는다. setter는 MarkDirty로 UI domain을 게시하고 부모 rect 변경은 driver가 자식에 전파한다. spatial transform이 변하지 않았다고 UI resolve를 생략하면 resize가 누락된다.

SetAnchorsPivotKeepWorld와 SetParentKeepWorldPosition은 현재 world rect를 새 parent/anchor/pivot으로 역산한다. parent 변경 자체는 canonical Scene hierarchy 검증을 거쳐야 한다. screen pixel 입력과 중심 layout 좌표를 UIButton 경계에서 일관되게 변환한다.

확인할 조합과 한계

point/stretch anchor, 비중앙 pivot, width/height match, resize, root/nested Canvas, world/camera/overlay, reparent keep-world, Save/Reload를 따로 확인한다. image/text 크기와 pointer hit 결과가 같은 rect를 소비하는지도 검증해야 한다. 이 개정에서는 시각·입력 시험을 수행하지 않았다.

UIManager 전체 제거와 새 input router는 별도 미래 작업이며 좌표 수식이 맞는 것만으로 UI 재설계 완료가 되지 않는다. 현재 텍스트와 snapshot 구현은 UI 경계 문서를 따른다.
