SceneHost는 opaque와 blended 표면의 컬링을 메시릿 단위로 정의하고, FirstCullStage는 준비된 cameraDepthMeshlets를 바로 선언한다. GPU의 범용 GeometryCullCS가 존재한다는 것만으로 이 scene 경로에 인스턴스 컬링이 들어 있다고 볼 수 없다. 실제 메시릿 커널은 정점을 복원하고 필요한 경우 skinning까지 수행하여 경계를 만든 뒤 가시성을 검사한다. [C2] [C3] [C4] [C6]

이 구조에서는 큰 오브젝트 전체가 화면 밖이거나 가려진 경우에도 하위 메시릿을 열거하고 일부 복원 비용을 낼 수 있다. 인스턴스 또는 적절한 공간 묶음의 보수적 경계를 먼저 검사하여 생존한 묶음만 ring의 하위 작업으로 펼치는 방안이 가장 명확한 전단계 확장이다. 이 비용 절감 가능성은 코드에서 도출한 추론이며 아직 측정된 개선량은 아니다. [C3] [C4] [C29]

구현할 때는 현재 pose에 대한 보수적 bounds, 카메라와 각 light-space의 독립 판정, history 무효화, 첫 단계 탈락의 현재 깊이 복구를 유지해야 한다. 인스턴스가 전부 제거된 경우의 간접 인자와 빈 목록도 유효해야 한다. 현재 경계 계산이 비싸다는 이유만으로 bind-pose bounds를 변형 메시의 확정적인 제거 조건으로 쓰면 안 된다.

4.2 가시 프리미티브를 위한 변환 결과 재사용이 없다

LXSceneReconstruct는 가시성 ID에서 삼각형을 찾아 세 정점을 다시 가져오고, 월드·클립 변환을 한 뒤 픽셀 위치에서 보간값을 푼다. Temporal fragment도 현재 정점과 이전 포즈·월드를 이용한다. 압축 직접 경로에서는 이 과정에 압축 해제와 bone skinning이 포함될 수 있다. 해상도·재질 소비 횟수·변형 비용이 커질수록 같은 프리미티브에 대한 반복 계산이 늘어날 수 있다. [C5] [C6]

현재 quad 안의 완전한 record/primitive ID 중복 제거는 있다. 그러나 helper lane의 미분값을 유지하려고 선택된 ID에 대해 각 lane이 자기 픽셀 중심에서 복원·평가한다. 또한 object-space pose 준비는 화면에서 실제 살아남은 프리미티브의 현재·이전 clip 결과를 보관하는 캐시와 수명·키·소비 지점이 다르다. direct cluster에서는 pose 출력이 전체 변환 정점 캐시가 아니라 bone palette 업로드다. 따라서 기존 기능을 “가시 프리미티브 변환 사전 계산 완료”라고 분류할 수 없다. [C5] [C6] [C46]

후속 설계는 Visibility 이후에 유효 ID를 모으고, 중복 범위와 출력 키를 정의한 뒤, 필요한 현재·이전 위치와 방향 정보를 한 번 계산하여 SurfaceResolve·Temporal이 읽도록 만드는 것이다. 전역 정점 중복 제거부터 시작할 필요는 없다. 중복 제거 비용·임시 메모리·추가 읽기 대역폭이 줄어드는 계산보다 작아야 한다. 실제 포맷과 캐시 범위는 현재 압축 오차, motion 정밀도, 작은 삼각형 비율로 정한다.

4.3 머티리얼 분류는 이미 있으나 묶는 단위가 다르다

GPU의 count·prefix scan·scatter와 indirect args 생성은 실제 구현이다. CPU가 확정하는 bucket key는 cooked program 전체 신원, double-sided 상태, geometry descriptor page다. geometry page는64항목이며, 타일은8×8 영역의 record별 패킷으로 표현한다. 그래서 같은 shader라도 descriptor page 또는 record가 달라지면 작업이 갈라질 수 있다. [C7] [C8] [C9]

현재 타일 커널은 group shared 배열로 같은 record를 제거한다. 같은 bucket에 속한 서로 다른 record를 wave별로 묶어 atomic을 합산하는 처리는 이 타일 경로에 없다. 반면 별도의 meshlet 패킷 경로에는 전체 visible count를 한 번에 예약하는 처리가 있다. 최적화 대상을 타일 count/scatter에 한정해 판단해야 한다. [C7] [C8] [C45]

따라서 “GPU 머티리얼 정렬을 새로 구현”하는 작업은 중복이다. 우선 같은8×8 타일에 서로 다른 record가 얼마나 겹치는지, page 때문에 같은 프로그램이 얼마나 분리되는지, 유효 픽셀 대비 실제 fragment·helper 평가가 몇 번 발생하는지 측정해야 한다. 픽셀 mask, shader 중심 묶음, descriptor 접근 방식의 변경은 이 비용이 큰 경우의 후보이며 더 작은 타일이 언제나 유리한 것은 아니다.

4.4 그림자는 기능 부재보다 가림 입력과 래스터 경로의 차이가 크다

현재 그림자는3개 cascade를 사용한다. 캐시는 mobility 플래그가 아니라 opaque이면서 bone이 없는 caster에 적용한다. world와 light projection 등이 캐시 키에 참여하므로 rigid 물체·광원이 움직여도 무조건 재사용되는 캐시가 아니다. 첫 occluder에는 이 캐시의 복사본과 비캐시 대상의 first-list 래스터가 함께 들어간다. 최종 단계는 현재 light-space HZB로 복구하고 캐시와 최종 목록의 깊이를 합친다. [C10] [C11]

Shadow.Occluder의 입력은 기하, static depth, shadow first lists다. 이 그래프에는 camera depth를 light space에 투영하는 생산자나 이전 ray-hit 위치를 받는 자원 간선이 없다. 일반 temporal reprojection이나 SSGI history가 있다는 사실은 해당 그림자 입력을 대신하지 않는다. 현재 SSGI는 화면 깊이 기반의 trace·resolve·합성 경로이며, 별도의 RT hit-position history를 그림자에 넘기지 않는다. [C12] [C13] [C14]

그림자 패킷의 최종 실행은 DispatchMeshIndirect와 HW shadow mesh/coverage shader다. 카메라의 SW meshlet raster 경로가 그림자까지 자동 적용되는 구조도 아니다. 이 차이의 우선순위는 caster 수, cascade 해상도, 광원 움직임, 캐시 적중률, 작은 삼각형 비율에 따라 달라진다. [C30] [C31] [C32]

카메라 깊이를 추가하면 전단계 가림을 빨리 얻을 가능성이 있지만, 현재 카메라와 그림자의 독립성에 새로운 의존성을 만들 수도 있다. offscreen receiver·caster, 광원 회전, 급격한 카메라 이동에서 안전한 복구가 필요하다. ray-hit 보강은 사용할 ray-hit 생산자와 완료된 history 수명 계약을 먼저 확보하는 후속 작업이다. 현재 파이프라인에 RT 전체를 급히 넣는 것을 이 비교의 필수 선행 조건으로 두지 않는다.

4.5 async compute와 aliasing을 한 번에 사용할 수 없다

DX12 adapter에는 실제 compute 큐와 큐별 profiler 생성이 있고, RenderGraph에는 측정 기반 배치와 transient aliasing이 있다. 다만 기본 실행 모드는0이며 owned queue 모드1·2는 aliasing을 거부한다. mode2를 요청해도 적격 작업·측정·의존성 조건이 충족되지 않으면 effective mode1로 기록된다. [C15] [C16] [C17] [C18]

큐 비용 모델의 handoff와 minimum gain은 보정된 실측값이 아니며 predictionCalibrated는 false 상태다. 따라서 “compute로 옮기면 중첩된다”거나 “aliasing과 동시에 메모리를 줄였다”는 결론은 현재 근거보다 강하다. 가시 프리미티브 precompute를 추가할 경우에는 먼저 단일 큐에서 순수 손익을 확인하고, 그다음 queue-local timing과 전체 프레임으로 중첩 효과를 평가하는 순서가 적절하다. [C19] [C15]

1. 해결하는 문제와 구현 범위

기준 코드에서는 메시릿마다 정점을 복원한 뒤 경계를 계산한다. 인스턴스 전체가 제거될 수 있어도 그 메시릿 작업이 GPU ring에 게시되고, 같은 LOD 그룹에 대한 요구 비트도 여러 메시릿이 반복 갱신한다. 또한 SurfaceResolve와 Temporal은 화면에 남은 같은 삼각형의 변환을 반복한다. 그림자의 첫 컬링은 light-space history를 사용할 수 있지만 현재 카메라 깊이를 받는 입력 계약은 없다.

이 PR은 다음 세 부분을 구현한다.

작업 변경 후 동작 기본 상태 직접 줄이려는 비용
1A. 인스턴스 조기 판정 기존 Reset에서 현재 포즈의 보수적 경계를 계산하고, Cull이 하위 메시릿을 ring에 게시하기 전에 거절한다. direct/object-space의 유효 경계에 적용. 경계가 없으면 기존 메시릿 판정으로 진행. 제거되는 인스턴스의 ring job, 메시릿 decode/skinning, 반복 그룹 feedback atomic
1B. 가시 프리미티브 캐시 GPU material packet에서 보이는 삼각형의 현재 표면·clip 및 이전 object-space 위치를 계산하고 SurfaceResolve/Temporal이 재사용한다. 명시적 opt-in, 기본 꺼짐. 같은 가시 삼각형의 반복 변환

3. 인스턴스 조기 판정의 코드 계약

불변 경계와 현재 포즈

MeshSurfaceInput::SealInstanceBounds()는 정적 partition을 봉인할 때 cooked meshlet sphere들의 합집합을 만든다. QMC2 위치 오차와 구면 검증의 여유를 포함하고, double 누적 후 float 변환은 바깥쪽으로 반올림한다. 이 값은 불변 입력 소유자에게 저장되므로 warm frame에서 메시릿 descriptor를 다시 순회하지 않는다. 스트리밍의 전체 입력과 각 chunk도 같은 봉인 과정을 사용한다.

GPU Reset은 현재 bone palette의 각 본이 그 경계를 변환한 AABB를 합친다. 정규화된 비음수 skin 가중치의 변형 위치는 이 합집합 안에 들어간다. 모든 가중치가 0인 기존 정점 동작을 위해 bind pose 경계도 포함한다. 현재 world 변환까지 적용한 뒤 frustum 판정을 저장한다. shear·reflection을 포함한 affine 변환은 interval 계산과 바깥쪽 반올림으로 보수적으로 처리한다. 수치가 유효하지 않거나 overflow이면 기존 메시릿 경로로 통과시킨다. bind-pose 경계만으로 움직이는 skinned geometry를 제거하지 않는다.

CPU가 coarse 경계를 제공하는 대상은 UsesDirectClusters() && IsObjectSpace()다. compatibility와 경계가 없는 입력은 통과한다. 이는 스키닝의 coarse LOD를 새로 생성한다는 뜻이 아니다. Reset의 현재 pose 읽기는 RenderGraph의 명시적 read dependency에 추가됐다.

기존 GPU 작업 배분에 삽입

별도 coarse dispatch를 추가하지 않는다. 기존 Reset의 bin당 64개 lane에서 경계를 만들고, persistent Cull이 비어 있지 않은 source partition을 처음 얻을 때 coarse 결과를 검사한다. 거절된 partition은 메시릿 descriptor를 decode하거나 ring job을 게시하기 전에 종료된다. producer lease는 기존 종료 경로에서 반납한다.

frustum 계산은 bin당 한 번이다. HZB 검사는 기존 16개 논리 partition 중 비어 있지 않은 partition마다 최대 한 번 실행한다. 인스턴스 survivor 목록 자체를 먼저 compaction한 완전한 별도 front stage는 아니며, 거절된 bin도 초기 partition claim 비용은 남는다. Reset의 bone 경계 합집합과 1,792 byte의 고정 groupshared scratch 비용도 추가된다. 이 범위를 과장해 모든 Cull 비용이 사라진다고 해석하지 않는다.

첫 단계의 메시릿 survivor가 하나라도 있으면 recovery의 coarse HZB 거절은 건너뛴다. 개별 메시릿에서도 기존 first-stage classification을 유지한다. 새 경계로 이미 살아남은 기하가 최종 목록에서 사라지는 것을 막기 위한 계약이다.

MeteorGeometryPosition()은 위치만 필요한 소비자의 계약을 명시하고 full MeteorGeometryPoint()와 실제 decode/skinning 결과를 비교했다. 컴파일러가 기존 미사용 속성 계산을 이미 제거할 수 있으므로 이 helper 자체의 속도 향상을 주장하지 않는다.

4. 가시 프리미티브 캐시

자원과 생산자

ScenePrimitiveCacheFrame은 현재 frame의 scene records, material packets, descriptor recording과 graph epoch를 봉인한다. ClearPrimitiveCache는 key만 초기화한다. PopulatePrimitiveCache는 기존 8×8 record/tile 패킷과 각 geometry page를 사용해 간접 dispatch하고, 실제 visibility에 나타난 primitive address를 bounded hash에 게시한다. CPU가 가시 primitive 목록을 새로 만들지 않는다.

전역 visibility address가 key이므로 서로 다른 record의 동일 primitive index가 섞이지 않는다. 고정 16,384개 slot과 최대 8번의 linear probe를 사용한다. 네 개 인접 pixel의 중복 CAS는 64-lane 고정 groupshared scratch로 줄인다. subgroup 크기나 vendor 전용 WaveMatch 확장을 가정하지 않는다. producer의 packet/record는 작업 그룹 전체에서 동일하므로 geometry descriptor index도 동일하며 불필요한 NonUniform 표시를 하지 않는다. 소비자의 서로 다른 record 접근은 기존 NonUniform 계약을 유지한다. hash에 들어가지 못한 primitive는 소비자의 기존 decode로 처리한다. cache miss가 렌더링 누락으로 변환되지 않는다.

key를 먼저 CAS하는 생산자와 pixel 소비자는 같은 dispatch 안에서 동작하지 않는다. Clear → Populate의 UAV 경계와 Populate → Surface/Temporal의 명시적 SRV dependency가 data 게시를 완성한다. Populate의 다른 producer는 선점된 key의 data를 읽지 않는다.

정밀도와 소비자

한 primitive에 현재 월드 표면의 세 정점, 현재 raster clip, 이전 object-space 위치를 full float로 저장한다. 기존 homogeneous barycentric 복원, near-plane 처리, quad helper 미분값 계산과 Temporal의 이전 위치 보간 후 world/projection 적용 순서를 유지한다. REAC의 vertex당 16-byte 포맷과 동일하지 않다. 임의의 half/packed 정밀도를 도입해 영상·motion 오차를 늘리지 않는 초기 구현이며, 저장 형식 축소는 native 화질·대역폭 비교 이후의 별도 작업이다.

기본 LXSceneGBufferPS와 LXSceneTemporalPS는 cache 사용 여부를 compile-time false로 전달한다. opt-in은 별도 cooked LXSceneCachedGBufferPS와 LXSceneCachedTemporalPS를 선택한다. 상수 material fixture의 DXIL을 기준 master와 대조해 기본 entry의 t174/t175 및 추가 cache resource/query가 제거됨을 확인했다. 전체 정규화 IR은 wrapper의 출력 합류 등으로 동일하지 않으며, 실제 시간 동등성은 미측정이다. cache Temporal은 lookup 결과를 복원과 이전 위치 경로에 함께 넘겨 같은 pixel의 중복 hash 탐색을 피한다. 캐시 PSO는 봉인된 generation과 기존 PSO id를 확인해 재사용하며, 프레임의 Draw에 준비된 handle을 게시한다.

5. 현재 카메라 깊이를 사용하는 그림자 예측

설정은 SceneHostBudget::m_shadowDepthPrediction 또는 CREATOR_METEOR_SHADOW_CAMERA_PREDICTION=1이며 기본값은 꺼짐이다. 입력 표면이 없어 camera HZB를 만들 수 없는 뷰는 기존 경로를 유지한다. 고정 char 배열로 설정을 읽어 프레임별 동적 문자열/컨테이너를 만들지 않는다.

그래프 의존성과 신원

활성화할 때 camera first만 먼저 선언한다. Camera Occluder가 실제 current-depth HZB를 만든 뒤, 세 shadow first를 METEOR.Shared.ShadowCameraPrediction 묶음으로 선언한다. 기존 네 뷰 shared first를 그대로 유지한 채 거기에 camera HZB read를 붙이면 스스로 자기 생산자를 기다리는 cycle이 생기므로, 활성화된 경로에서만 묶음을 나눈다. 기본 경로의 기존 shared 묶음은 유지한다.

frustum과 LOD는 light projection/extent를 유지하고, 예측 HZB의 투영·크기만 camera ViewKey에서 받는다. 해당 키는 같은 device, upload recording, descriptor version, frame, scene epoch의 현재 카메라를 가리켜야 한다. ShadowFirst가 받은 camera depth는 실제 occluder depth의 동일 RG handle/version이어야 한다.

Pyramid::RequireCurrentView()는 ViewKey가 같더라도 retained history reader를 거부한다. 일반 DeclareWithOcclusion/DeclareOcclusionBatch에는 prediction frame을 넣을 수 없다. 같은 graph/epoch와 같은 생산자의 재선언만 허용하며, 다른 depth producer로 바꾸는 요청은 거부한다.

정확성 보존과 미구현 범위

현재 camera clip volume 안에 경계 전체가 들어온 경우만 예측 HZB로 거절한다. 부분적으로 밖에 있거나 near/far/W 또는 수치가 불확실하면 통과한다. 이는 offscreen caster를 camera visibility만 보고 제거하지 않기 위한 조건이다.

예측은 첫 shadow 목록에만 적용한다. 첫 survivor는 최종 복구에서 유지되고, 첫 거절 대상은 현재 실제 light-space occluder HZB로 다시 검사한다. static shadow cache와 최종 light-space depth/history에 camera depth를 복사하지 않는다. 카메라와 광원에서 반대 가시성인 경우까지 포함해 이 복구 계약을 검증한다.

이 구현은 camera-space HZB를 직접 읽는 prediction-only 경로다. REAC의 카메라 깊이를 64×64 light-space atlas에 재투영하는 생산자, 이전 ray-hit position의 주입, 그림자 software rasterizer는 추가하지 않았다. ray-hit 생산자나 history 수명 계약이 없는 상태에서 이름만 붙인 자원을 만들어 완료로 세지 않는다. 새 camera → shadow dependency가 병렬성을 줄일 가능성도 전체 GPU schedule에서 측정해야 한다.

6. 할당, 소유권과 컨벤션

새 엔진 멤버는 m_ 접두사, 새 상수는 kPascalCase, 지역 변수는 camelCase를 사용한다. 새 코드의 제어문은 중괄호와 Allman 배치를 사용하고, C++ 변경 구간은 저장소 .clang-format에 맞춘다. Slang은 HLSL formatter가 entry/loop attribute를 잘못 결합하는 경우가 있어 기존의 attribute 별도 행과 함수 배치를 보존하고 수동 대조했다. 기존 코드의 광범위한 포맷 변경은 하지 않는다.

핫패스의 작업 목록을 지역 vector/map으로 새로 만드는 코드는 추가하지 않는다. 고정 정보는 std::array와 GPU groupshared 배열을 사용한다. Shared HZB descriptor 조립의 기존 지역 vector는 8×16 고정 배열로 교체했다. local instance bounds는 정적 입력 owner에 저장하며, 캐시의 declaration uses/normalization scratch는 resources owner가 재사용한다. GPU cache buffers는 기존 TransientBufferPool의 제출·완료 수명에 따라 회수한다. opt-in cold PSO 준비와 프레임 소유자 객체 자체는 할당이 존재하므로 전체 시스템의 무할당을 주장하지 않는다.

원자적 갱신 횟수, 유지 메모리와 추가 dependency도 비용이다. 빈 목록, overflow, stale recording, graph reset, 실패 후 소유권과 descriptor page 경계를 성능과 함께 확인한다.

7. 검증과 재현

정확한 실행 결과, source SHA-256, compiler/validator 신원과 baseline countercheck는 verification.json 및 같은 디렉터리의 보고서에 기록한다. 원문에서 추출한 생산 함수를 가짜로 재구현한 뒤 통과시키지 않도록, Slang include closure를 고정해 실제 compiler에 전달하고 실행 전후 source 변경을 확인한다.

현재 환경에서 수행할 수 있는 검사

  • 실제 Slang의 bounds helper → C++를 독립 double corner/plane/skin oracle와 비교.
  • 실제 position-only/full-surface decoder의 bitwise 위치 비교와 독립 packet/skin oracle 비교.
  • 실제 single/shared/recovery HZB wrapper → C++에서 camera/light 반대 투영, 전체 footprint, odd extent, first-survivor 보존을 확인. coverage 또는 recovery를 의도적으로 제거한 변이는 실패해야 함.
  • 실제 cache header/입장 조건/바인딩 코드의 portable fixture에서 할당·실패·retained ownership·stale epoch를 확인. 이 fixture의 device/encoder 경계는 대역이며 실제 RHI build가 아님.
  • 실제 셰이더 변형의 DXIL 생성과 dxv 검증, SPIR-V 생성과 spirv-val 검증. 현재 RHI 옵션과 capability를 추가한 진단 모드의 결과를 따로 기록.
  • git diff --check, runtime/editor include boundary, 변경 구간 포맷, native probe assertion의 정적 대조.

Slang 2026.14, DXC 1.9.2607, SPIRV-Tools 2026.4를 사용했다. 도구의 출처·checksum은 검증 근거에 보존한다. C++ oracle는 -fno-fast-math -ffp-contract=off를 사용한다. Slang의 C++ 출력이 HLSL precise를 그대로 남기는 경우 host keyword adapter를 적용하며 그 사실을 기록한다. ASan/UBSan과 LeakSanitizer는 구분한다. sandbox에서 /proc task 접근이 막혀 LeakSanitizer를 실행할 수 없는 경우 leak 검증을 통과한 것으로 세지 않는다.

아직 수행하지 못한 검사

이 환경에는 Windows/MSVC 전체 엔진 빌드와 실제 GPU가 없다. native Debug/Release 빌드, DX12 GPU validation, native Vulkan, 새 영상·shadow·motion 결과, 실제 frame 성능의 A/B 측정은 미실행이다. 작성된 native probe의 성공 marker를 실행 결과로 기재하지 않는다.

추가한 coarse native probe는 normal/partial-wave의 16개 case로 empty/tail/skewed/4096 bins, 완전히 거절되는 partition, 기존 visible-ID/indirect/ring 종료 oracle를 검사하도록 했다. 기존 48개 dynamic ring case도 유지한다. 이 fixture의 경계는 compatibility/unskinned 입력에 수동으로 제공하므로 cooked CPU bounds 생산자와 GPU bone reduction을 end-to-end로 검증하는 범위는 아니다.

shadow native probe에는 8개 prediction case와 missing depth 및 RG version·epoch 거부, retained-history 거부를 추가했다. 현재 CPU oracle의 성공과 native probe 미실행을 별도로 기록한다. cache의 전용 --primitive-cache-only mode는 기존 visibility reconstruction 32 frames와 temporal bucket 12 frames에 실제 SceneHostBudget::m_primitiveCache=true를 전달하도록 작성했다. Clear/Populate의 존재, packet 생성 및 Resolve와의 실행 순서, cache 두 버전의 Pixel SRV read를 compiled graph에서 확인한 뒤 기존 독립 pixel/motion oracle를 수행한다. 이 44 frames는 아직 실행된 결과가 아니다. live renderer 환경변수만으로 native probe의 기본 budget이 바뀐다고 가정하지 않는다.

현재 RHI SPIR-V 옵션으로 baseline의 일부 subgroup capability 오류가 재현된다. 해당 오류를 없애려고 장치의 supportedOperations/stages 검증 없이 capability만 선언하지 않는다. 진단용 capability/profile로 컴파일돼도 생산 Vulkan 수용은 아니다. 기존 baseline에도 있는 오류와 이 PR의 새 오류는 비교 근거로 구분한다. include boundary 검사도 전체 통과가 아니다. 기준 master의 1,785개 source/project 파일 미러와 현재 코드에서 동일한 27개 상향 include 및 70개 물리 경계 부채가 보고됐으며, 추가 위반은 0건이다. allowlist를 수정하거나 기존 실패를 통과로 표시하지 않았다.
