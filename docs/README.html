§01

2026-10-20 master 구현 대조

기준: 27de3f5a02aadde7456aab680db3184c36ee735e. 대시보드는 변경하지 않는다. 아래 현행 대조와 소스 선언이 이전 시점의 구조·미구현 표기보다 우선한다.

전체 대조·링크 정리 원장

현행 계약과 이 문서의 적용 범위

  • Editor/Player Host와 build/cook·manifest/pak·bootstrap을 분리한다. runtime 소비와 Editor authoring writer를 같은 책임으로 합치지 않는다.
  • 로컬 package 생성은 Launcher/MSI·서명 update/rollback·clean VM 제품 수용의 증거가 아니다.
  • 구 SRP 및 C# pipeline 저작 전환 제안은 취소됐다. 필요한 Pass는 현재 C++ 계약으로 작성하며, 별도 저작 체계는 실제 요구가 생기면 새 미래 계획으로 검토한다. 아래 원래 제안은 활성 계획이 아니다.

이전 근거의 유효 범위

기존 세부 계약은 위 현행 구현과 모순되지 않는 범위에서 유지한다. 과거 수치·실행 통과·해시·장치 조건은 당시 기록이다. 로컬 산출물이 사라진 항목은 링크 대신 경로와 미보존 상태를 표시하며, 현재 master의 재실행 통과로 승격하지 않는다.

세부 계약·원래 분석과 당시 측정 기록

엔지니어링 문서 트리. 루트에 흩어져 있던 30개 문서를 2026-08-17에 여기로 옮겼다.

  • TechnicalGuide.md — 커밋된 master 기준의 기술설명서. 엔진 구조·소유권·렌더링·콘텐츠·스크립팅·빌드 흐름과 구현·검증 경계를 설명한다.

  • CONTRIBUTING.md · CODE_OF_CONDUCT.md — 기여 절차와 참여 기준.

  • RefactoringPlanDashboard.html — 전체 리팩터링 페이즈 색인. 진행 상태·의존 관계·슬라이스 단위를 한 눈에 본다. 여기서 시작하는 것이 빠르다.

§07

문서를 추가할 때

  • 계획이면 plans/. 슬라이스와 완료 기준, 판정 수치를 반드시 넣는다.
  • 계획이 종료·대체되면 plans/archive/로 이동하고 보관 색인·내부 상대 링크·대시보드를 함께 갱신한다. 보류·차단·미래 계획은 종료로 처리하지 않는다.
  • 결정이면 design/. 채택뿐 아니라 기각한 대안과 그 근거를 함께 적는다 — 이 저장소는 같은 후보를 반복해서 재검토하는 비용이 컸다.
  • 측정이면 analysis/. 측정 시점을 명시하고 이후 갱신하지 않는다.
  • 어느 쪽이든 틀린 것으로 드러난 판단은 지우지 말고 정정 이력으로 남긴다. 이 저장소의 관례이며, 실제로 그 기록이 재실수를 막았다.
