identity는 소유권이 아니다

AssetLink<T>는 기대 종류와 논리 GUID를 보관한다. 링크를 만들거나 복사해도 요청·상주·파일 IO가 자동으로 시작되지 않는다. AssetRequest는 별도 consumer의 요청 상태와 결과 수명을 갖는다. 복사된 request는 같은 consumer를 공유하지만 별도로 요청하면 같은 작업에 합류하더라도 취소 대상은 다르다.

logical identity, exact generation, native handle의 slot generation을 혼용하지 않는다. descriptor가 캡처한 자식 backing은 resolver의 최신 값으로 다시 바꾸지 않는다.

CPU payload와 artifact backing

AssetDepot는 live weak cache, retained strong owner와 inflight 작업을 구분한다. CPU Ready는 typed descriptor/payload가 준비됐다는 의미이며 GPU upload나 fence 완료가 아니다. 취소는 subscriber의 관심을 취소하며 공유 작업 전체를 죽이지 않는다.

ArtifactByteSource는 캡처한 backing을 소유한다. path가 같다는 이유만으로 새 파일을 다시 열어 old generation으로 취급하지 않는다. immutable PAK/loose source의 capture 실패는 조용한 최신 source fallback으로 바꾸지 않는다.

Scene 객체의 추적 수명

SceneManager의 gc::domain과 root_ref가 Scene을 붙잡는다. Scene→Entity와 Entity→Component는 trace_ref이며 Component→Entity는 weak_ref다. Destroy는 논리 제거이고 실제 회수는 owner의 안전한 collection 경계다. DontDestroyOnLoad 이동도 같은 domain에서 root를 유지하는 transfer로 처리한다.

own::shared_owner 같은 native handle은 GCCE graph edge나 managed C# 객체를 대신하지 않는다. 종류마다 누가 마지막 사용을 끝내는지 명시해야 한다.

RHI handle과 finite generation

RHITextureHandle/RHIBufferHandle은 32bit id이며 0이 invalid다. 상위 16bit generation, 하위 16bit slot+1 구조로 stale slot 재사용을 구분한다. IsValid는 0 여부 검사이지 해당 device에서 지금 resolve된다는 보장이 아니다.

generation은 유한하여 wrap이 가능하다. 따라서 handle만 장기 보관하는 것을 영구적인 stale 방지나 ownership으로 문서화하지 않는다. 실제 device table·recording·retirement 수명을 함께 지켜야 한다.

GPU 최종 사용과 해제

RHICompletionRetireQueue는 유효한 completion 값에 도달한 payload만 Collect한다. 0은 완료 증명 없는 quarantine으로 device teardown Drain까지 남는다. 논리 retired bytes는 실제 OS/device free bytes와 같지 않다.

display sink의 consumer lease는 producer 완료와 별도로 마지막 presentation/SDK GPU 사용까지 유지된다. acquisition과 producer 재사용은 공통 lifetime 경계에서 직렬화한다. Present 반환이나 shared pointer 감소만으로 재사용할 수 없다. completionLost는 slot을 다시 쓰지 못하게 한다.

DLL과 managed 경계

Tools/runtime/HostAbi.h는 scalar 정보와 static borrowed 문자열, borrowed argv를 전달한다. engine object·allocation·exception을 이 C ABI로 넘기지 않는다. content ABI는 additive 별도 정보 구조이고 host/script API version과 다른 축이다.

C++ owning template을 외부 SDK나 managed ABI에 그대로 노출하는 일반 계약은 없다. managed bridge는 typed 값과 명시적인 handle을 사용하며 호출 thread와 lifetime을 별도 검토한다.

남은 요구와 오류 처리

전역 UnloadUnusedAssets 호출 한 번으로 scene·CPU cache·GPU allocation을 모두 회수하는 모델은 없다. caller 관심 취소, owner publication 거부, logical eviction, completed GPU release를 나눠 오류를 보고해야 한다.

모든 backend·device-loss 조합의 안전성은 실행 증거가 필요하다. AssetDepot, display lease, GCCE 객체 수명을 각각의 정본으로 사용한다.
