1. 목표와 적용 범위

RDG 실행 콜백은 백엔드 중립 소프트웨어 명령을 기록한다. 번역 계층이 이를 네이티브 command list/buffer에 기록하고 기존 RHI 제출 소유자가 큐에 제출한다. RDG 선언, 의존성 분석, 패스 컬링, 배리어 계획, 구조 재사용은 유지한다. 전체 패스 콜백을 RHI 스레드로 옮겨 실행하는 방식은 사용하지 않는다.

이 작업은 고정 2프레임 지연 정책을 도입하지 않는다. GT publication, RT recording, RHI translation, native submission, GPU completion, presentation은 각각 다른 사건이다. 프레임 publication 하나에서 여러 뷰 제출이 만들어질 수 있으므로 제출 수를 프레임 지연으로 환산하지 않는다. 기존 최신 입력 병합과 in-flight 제한은 별도 정책으로 유지한다.

제품 전환 범위는 DX12와 Vulkan의 기존 제품 소비 경로다. DX12부터 직렬 번역을 수용하고 Vulkan 어댑터를 구현한 뒤 각 백엔드별 검증을 수행한다. Vulkan 미지원 명령을 성공으로 처리하거나 DX12 검증을 Vulkan 수용으로 확대하지 않는다. 성능 목표는 CreatorRobot Debug 120 FPS이지만, 명령 기록과 번역의 추가 비용이 있으므로 목표 달성을 이 설계의 결과로 가정하지 않는다.

4. 공개 API 계약

아래는 선언 계약이다. 기존 프로젝트의 include/forward declaration 및 소유권 도구에 맞춘 헤더 분할은 구현 단계에서 수행한다. API 이름과 반환 의미는 유지한다.

4.1 기록 세션

struct RHISoftwareRecordingDesc
{
    RHIQueueIdentity queue;
    uint32_t targetCount{ 0 };
    uint64_t maxCommandBytes{ 0 };
    uint64_t maxPayloadBytes{ 0 };
};

class RHISoftwareRecorder final
{
public:
    bool BeginRecording(const RHISoftwareRecordingDesc& desc, std::string& outError);
    RHIEncoder& AcquireEncoder(uint32_t target);
    bool FinishRecording(std::span<const uint32_t> targetOrder,
        const RHISoftwareBatchDesc& desc, RHISoftwareBatch& outBatch,
        std::string& outError);
    void CancelRecording();
    RHICommandRecordingStats GetRecordingStats() const;
};
  • BeginRecording는 비활성 세션에서만 성공한다. targetCount와 두 예산은 0보다 커야 한다. 이 호출로 네이티브 allocator/list를 reset하거나 upload prefix를 제출하지 않는다.
  • 초기 recorder는 총 예산을 target 수로 균등 분할하고 나머지 byte를 앞 target부터 배정한다. 같은 target의 여러 pass segment는 예산을 공유한다. 다른 target끼리는 명령별 공용 atomic 카운터를 갱신하지 않는다. target별로 독점 기록한 뒤 owner가 합류하여 통계를 합산한다. 두 예산이 target 수보다 작으면 시작을 거부한다.
  • AcquireEncoder는 활성 세션의 유효 target에서만 호출한다. 새 pass/slice 상태를 시작하며 같은 target에 동시에 두 writer가 접근하면 계약 위반이다. worker 번호는 물리 스레드 번호가 아니다. 범위 오류는 기존 엔진 assertion 계약으로 진단하고 해당 세션을 실패시킨다.
  • target당 opcode 순서는 기록 순서다. 서로 다른 target은 독립적으로 기록할 수 있다. FinishRecording 전에 모든 writer가 합류해야 한다. 이전 encoder 참조는 다음 acquire 또는 finish/cancel 이후 사용할 수 없다.
  • FinishRecording은 출력이 비어 있고 targetOrder가 유효하며 중복이 없을 때만 성공한다. 비어 있지 않은 target을 누락하면 실패한다. 빈 target은 제출 목록에서 제외할 수 있다. 의존성은 RDG compiled execution 계획에서 복사하며 임의의 target 완료 순서를 실행 순서로 사용하지 않는다.
  • 실패하면 부분 batch를 출력하지 않는다. CancelRecording은 합류 이후에만 호출하며, 아직 네이티브로 실행되지 않은 payload를 정확히 한 번 해제한다.

4.2 소프트웨어 목록과 batch

RHISoftwareCommandList의 엔진 내부 API는 GetCommandCount(), GetCommandBytes(), GetPayloadBytes(), IsSealed()이다. 명령 추가는 friend인 RHISoftwareEncoder에만 허용하며 임의 lambda를 등록하는 공개 API는 제공하지 않는다.

RHISoftwareBatchDesc에는 frameId, sourceEngineFrame, sourceEngineFrameAvailable, renderViewId, backendGeneration, displayToken, uploadRecordingId, descriptorVersion, queue, 조건부 captureContext, lifetimeToken을 둔다. queue는 기존 RHIQueueIdentity이며 device incarnation을 함께 검증한다. GPU query의 실제 fence/submission 번호는 native admission에서 연결한다. CPU 프레임과 capture provenance는 기록 시 동결한다.

RHISoftwareBatch 공개 API는 IsValid(), GetState(), GetDesc(), GetRecordingId(), GetTargetCount(), GetRecordingStats()다. GetDesc()는 const 참조를 반환하며 이동·파괴 이후 보관할 수 없다. 외부 상태 변경 setter는 두지 않는다. recorder, translator, submission owner만 상태를 전이한다.

4.3 번역

enum class RHICommandTranslationMode : uint8_t
{
    Serial,
    Parallel

struct RHICommandTranslationOptions
{
    RHICommandTranslationMode mode{ RHICommandTranslationMode::Serial };

class IRHICommandTranslator
{

Translate는 호출 직후 입력을 소비한다. 실패해도 재제출·재번역할 수 없다. 출력은 성공 시에만 유효하며 번역 실패는 GPU 제출 성공을 뜻하지 않는다. RHITranslatedBatch는 이동 전용 tagged container로 기존 단일 풀 RHIRecordedBatch 또는 독립 큐 IRHIQueueCommandBatch와 번역 통계를 소유한다. 태그 이름은 RHITranslatedBatchKind::ParallelPool과 OwnedQueue다. 독립 큐 batch는 기존 인터페이스가 요구하는 shared ownership을 유지하되 wrapper의 제출 권한은 단일 소유한다.

RHITranslatedBatch에는 GetKind(), IsValid(), GetTranslationStats()만 공개한다. 내부 native payload 접근·소비는 제출 소유자에 한정한다. software batch를 native batch인 것처럼 기존 enqueue에 넘기는 형변환은 금지한다.

초기 RHICommandTranslator는 준비된 native pool, IRenderDeviceServices, 실제 대상 RHIQueueIdentity를 생성자에서 받는다. DX12CommandTranslator와 VulkanCommandTranslator는 typed pool/resources 어댑터다. 직렬 번역은 batch에 저장한 upload/descriptor 버전과 현재 준비 버전이 다르면 거부한다. 비동기 버전 lease가 구현되기 전에는 이 검사를 제거하거나 현재 버전으로 바꿔 실행하지 않는다.

IRHISoftwareCommandValidator::Validate(type, arguments, argumentBytes, state)는 bool 명령의 사전 검증 API다. RHISoftwareEncoderState의 boundPipeline/bindPoint는 해당 encoder의 성공한 SetPipeline 기록을 반영한다. 여러 target의 pipeline 상태를 validator 내부 mutable 전역 값으로 공유하지 않는다.

4.4 제출 진입점

RHISubmissionThread에 다음 API를 추가한다.

bool EnqueueSoftwareBatch(const void* owner,
    RHISoftwareBatch&& batch,
    const RHICommandTranslationOptions& options,
    RHISubmissionTicket& outTicket, std::string& outError);

반환 false는 큐 admission 거부이며 ticket은 유효하지 않다. 입력 소유권은 성공할 때만 큐로 이동한다. 이 규칙은 입력을 항상 소비하는 Translate와 다르다. 큐 예산·owner generation·backend generation을 먼저 검사하고 이동한다. 반환 true는 작업을 받았다는 뜻이며 번역이나 native 제출의 성공이 아니다.

RHI 소유자는 등록된 디바이스의 translator를 사용한다. producer가 translator raw pointer나 참조를 lambda에 캡처하지 않는다. backend 등록 수명은 owner drain까지 보장한다. RHI 스레드 내부에서 기존 공개 enqueue를 다시 호출하고 ticket을 기다리는 재진입은 금지한다. native batch 제출용 private helper SubmitTranslatedBatch를 호출한다.

RHISubmissionTicket의 완료는 CPU native 제출 결과를 뜻하도록 유지한다. 번역 완료 시 ticket을 성공 처리하지 않는다. GPU 완료는 기존 RHICompletionPoint 또는 큐별 RHITimelinePoint로 판단한다. 아직 발행되지 않은 timeline value를 외부 queue wait의 유효 ready point로 노출하지 않는다.

직렬 번역의 native 수용 검사는 중간 API EnqueueTranslatedBatch(owner, completionSource, translatedBatch, outTicket, outError)를 사용한다. 이 함수는 이미 native 기록을 마친 ParallelPool 결과를 기존 EnqueueRecordedBatch에 넘긴다. 소프트웨어 기록을 RHI 스레드에서 번역하는 EnqueueSoftwareBatch와 구분하며, 이 중간 API의 사용을 비동기 전환 완료로 판정하지 않는다.

4.5 독립 큐 어댑터

RHISoftwareQueueRecorder는 기존 Record, BeginRecording, GetWorkerCount, DeviceServices, ExecuteSubmission 시그니처를 구현한다. 여기서 GetWorkerCount는 software target 수다. IRHIQueueRecording::Finish는 소프트웨어 payload를 담은 RHISoftwareQueueCommandBatch final : public IRHIQueueCommandBatch를 생성한다. 실제 native queue 소비 지점이 이 payload를 번역하여 기존 native batch로 대체한다.

RHISoftwareQueueCommandBatch는 기존 batch 인터페이스의 GetQueueIdentity()와 GetRecordingId()를 구현한다. 실제 실행 진입점은 batch가 아니라 IRHICommandQueue::Submit이다. 이 경계를 감싸는 RHISoftwareCommandQueue final : public IRHICommandQueue를 RHISoftwareQueueRecorder.h/.cpp에 함께 추가한다. GetIdentity, Signal, Wait, Submit, CollectCompleted, GetPendingBatchCount의 기존 서명을 유지한다. 생성은 RHISoftwareQueueFactory final : public IRHICommandQueueFactory로 감싸고 QueryQueueCapabilities/CreateQueue를 위임한다. native queue와 software queue의 논리 identity는 동일하며 새 GPU 큐를 만들지 않는다.

software queue의 Submit은 제출 소유자에서 software payload를 번역하고 native queue에 제출한 뒤 발행된 timeline point를 반환한다. ExecuteSubmission은 이 전체 transaction을 소유자에게 한 번 전달하고 CPU admission 결과까지 반환하되 GPU 완료는 기다리지 않는다. 기존 Submit의 동기 반환 계약을 유지하기 위해 이 경로는 번역 전에 가짜 issued point를 반환하지 않는다. 비동기 EnqueueSoftwareBatch의 ticket 경로와 구별한다. 동일 software queue에서 pending translation을 건너뛰고 후속 Wait/Signal/Submit이 실행되지 않도록 transaction 순서를 직렬화한다.

native 명령이 없는 소프트웨어 batch를 네이티브 완료 상태로 위장하지 않는다. cross-queue wait/signal, queue family ownership은 compiled queue 계획을 보존한다. CollectCompleted/GetPendingBatchCount는 wrapper가 소유한 admission과 native retirement의 일관된 집계를 제공하고 같은 batch를 두 번 세지 않는다.

5. 명령 목록과 인자 소유권

초기 내부 명령은 RHISoftwareCommandList::Command의 type/next/replay/payload와 typed payload로 구성한다. payload는 trivially destructible로 제한하고 명령별 소멸 콜백을 두지 않는다. 재배치하지 않는 target arena block에 저장하므로 header와 복사한 span의 주소를 유지한다. alignment와 byte 예산을 확인하고 크기 덧셈·배열 크기 곱셈이 overflow하기 전에 거부한다. payload는 저장소가 직접 만들고 외부 offset을 받지 않는다. 이 레이아웃은 프로세스 내부 전용이며 파일 직렬화 ABI가 아니다.

RHISoftwareCommandType은 아래 기존 API 이름과 동일한 열거자를 가진다. 각 opcode 구현은 양 백엔드가 아니라 현재 RHIEncoder 전체 인터페이스를 기준으로 coverage 검사한다.

6. 반환값과 오류 계약

bool-returning encoder API의 true는 입력 검증 및 software 기록 수락이다. false면 명령 추가와 encoder 상태 변화가 모두 없어야 하며 기존 fallback 호출이 안전해야 한다. capability, offset/alignment, argument size, pipeline/queue 지원 여부처럼 기록 전에 판단 가능한 조건은 즉시 검사한다.

void API의 할당·검증 실패는 recording session에 sticky failure로 저장한다. 이후 명령을 성공으로 처리하지 않고 FinishRecording이 실패한다. 일부 유효 명령만 골라 제출하지 않는다. 네이티브 resource 생성 실패나 device loss처럼 번역 때 드러나는 오류는 batch 실패이며, 기록 당시 bool 결과를 소급 변경하지 않는다.

RHICommandFailure 필드는 stage, recordingId, targetIndex, commandIndex, commandType, backendGeneration, message다. stage enum은 Recording, Admission, Translation, Submission, Retirement다. 아직 opcode가 없는 실패에는 index sentinel을 쓴다. GPU 실행 여부를 알 수 없는 native 실패는 별도 executionUncertain 플래그로 기록하고 자원을 quarantine한다. 재시도로 같은 draw를 중복 실행하지 않는다.

기존 GetComputeDispatchCount()는 software encoder에서 UINT64_MAX를 반환한다. 기존 native count를 논리 기록 수로 바꾸지 않는다. 논리 개수는 RHICommandRecordingStats::computeDispatchCommands, 실제 emit 수는 RHICommandTranslationStats::nativeComputeDispatches로 분리하고 소비처를 명시적으로 이관한다.

7. 상태와 스레드 소유권

RHISoftwareBatchState: Empty, Sealed, Queued, Translating, Translated, Failed, Cancelled. recorder의 활성 writer는 batch 밖의 Recording 상태다. 번역 입력이 소비된 후 software batch 객체는 비며 native 완료 상태는 RHITranslatedBatch와 기존 native batch가 소유한다. Translated는 진단 이력이며 software 객체를 GPU 완료까지 보관해야 한다는 의미가 아니다.

8. 업로드와 자원 준비 경계

자원 생성, map, descriptor 생성, CPU 데이터 채움, PSO 준비는 초기 단계에서 기존 준비 서비스에 남긴다. 소프트웨어 encoder는 이 작업을 임의로 지연시키지 않는다. 기존 IRHIParallelCommandPool::Prepare의 upload prefix 제출과 upload/descriptor version 시작은 다음처럼 분해한다.

  1. CPU 준비 단계 PrepareRecordingResources: 필요한 lease/version을 얻고 CPU 채움을 끝낸다.
  2. 번역/제출 소유자 SubmitUploadPrefix: prefix를 정확히 한 번 실행하고 같은 큐 순서 또는 명시적 timeline dependency를 확보한다.
  3. 본문 번역 및 native 제출: 고정된 version만 참조한다.

두 이름은 backend 내부 helper다. prefix를 이미 제출했다면 이후 본문 번역 실패를 '프레임의 GPU 작업이 전혀 실행되지 않음'으로 기록하지 않는다. prefix 자원도 완료점까지 보존한다. 준비 서비스가 RHI 스레드에서만 허용되는 경우에는 선행 작업 dependency로 분리하며 recording worker가 RHI ticket을 잡고 순환 대기하지 않게 한다.

9. 프로파일러와 타임라인

기존 IRHIGpuProfiler::BeginPass/EndPass는 유지한다. software 경로에서는 query slot과 이름·GpuPassTimingIdentity를 기록 시 예약하고 BeginGpuPass/EndGpuPass를 추가한다. ResolveGpuQueries는 마지막 query 쓰기 이후의 native 위치에 emit한다. DX12Encoder dynamic_cast 성공에 의존하는 경로는 profiler backend adapter로 분리한다. query 공간 부족은 명시적 timing-unavailable로 표시하며 draw 실패와 구별한다.

신규 CPU 스코프 이름은 RHISoftwareRecord, RHISoftwareSeal, RHISoftwareAdmissionWait, RHICommandTranslate, RHICommandTranslateJoin, RHINativeSubmit, RHIBatchRetire로 고정한다. 기존 RenderGraphDeclare, compile, scene prepare 스코프를 포함해 겹침을 보존한다. command별 CPU 스코프는 기본 OFF이며 동일 계측 조건 비교에서만 활성화한다.

모든 이벤트에 recordingId, sourceEngineFrame availability, frameId, viewId, queue identity, targetIndex, backend generation을 연결한다. CPU record/translate/submit 시간, ETW Running/Ready/Waiting, GPU timestamp, Present를 별도 lane으로 표시한다. trace에 정보가 없으면 unknown으로 표시하고 Running으로 추정하지 않는다. 프레임 지연은 publication/record/submit/present의 동일 provenance 매칭으로 측정한다.

10. backpressure와 종료

큐 entry 제한, 소프트웨어 arena byte 제한, GPU in-flight slot 제한을 함께 적용한다. 소프트웨어 큐와 기존 네이티브 큐에 각각 최대 용량을 추가해 총 지연을 두 배로 늘리지 않는다. admission부터 retirement까지 공유되는 제출 credit을 사용하고 CPU arena byte credit은 번역·폐기 완료 시 별도로 반환한다. 제출 credit은 GPU 완료 또는 미제출 확정 취소 때 반환한다.

현재 구현의 CPU 제한은 RHISubmissionThread::kSoftwareByteCapacity와 owned domain의 RHISoftwareQueueOptions::maxPendingArenaBytes로 각각 선택한 소비 경로에 적용한다. 한 software batch를 두 큐에 중복 접수하지 않는다. 전자는 기존 용량 3 FIFO의 대기 조건이며, 후자는 그래프가 기록을 먼저 모으는 계약 때문에 Finish에서 대기 없이 거절한다. allocatedBytes의 queued/sealed+running 합계를 세고 CPU 저장소 소멸 뒤 반환한다. 기존 backend frame slot·completion retirement가 GPU 자원 수명을 제한한다. 아직 Finish하지 않은 모든 producer 기록의 순간 arena peak나 전체 process RSS 상한을 추가한 것은 아니다.

resize/reload/backend 교체는 이전 generation의 신규 admission을 차단하고, 미번역 batch를 취소하거나 명시적으로 drain한다. 이미 제출한 자원은 GPU 완료까지 보존한다. shutdown은 producer 중지 → recording jobs 합류 → admission 차단 → 번역/제출 drain → GPU retirement → profiler/native pool 해체 순서다. device loss 또는 실행 불명확 실패는 기존 quarantine 정책을 따른다.

11. 병렬 번역

공용 RHICommandTranslationOptions의 기본은 Serial이다. 현재 소프트웨어 제품 선택 경로는 독립 target이 있는 pool/owned recorder에서 Parallel을 사용하되 작은 명령 묶음은 RHI 소유자가 직접 번역한다. minCommandsPerJob는 조정 가능한 측정 파라미터다. 연결부의 256은 master의 기존 정책을 유지한 값이며, 실제 장면에서 최적인 임계값으로 확정하거나 CPU fixture만으로 기본 경로 전환을 승인하지 않는다.

분할 단위는 RDG가 허용한 독립 target/context 경계다. 한 stateful command stream을 임의 명령 번호에서 잘라 상태를 잃지 않는다. 앞 상태가 필요한 target은 명시적 state prologue 또는 동일 context 순차 실행으로 보장한다. native list 완료 순서와 제출 순서는 구별하고 compiled dependency/order를 제출 시 복원한다. 자원/descriptor registry 조회는 번역 중 안전한 immutable snapshot 또는 lease를 사용한다.

번역 job은 기존 엔진 scheduler를 사용한다. 새 thread pool을 추가하지 않는다. target별 predecessor만 기다리고 불필요한 전체 wave barrier를 만들지 않는다. 합류 보조 실행은 scheduler의 허용된 task만 수행하며 thread-affine native 조작을 임의 worker에 넘기지 않는다. queue wait와 GPU fence는 CPU 번역 dependency를 대체하지 않는다.

16. 제품 RT/RHI 실행 경계 — 2026-10-21

이 절이 제품 실행 구조의 기준이다. §15의 선언 branch 실험을 SceneHost 전체로 확대하지 않는다. 의존성 그래프를 여러 작업 그래프로 복제·병합하는 것을 완료 조건으로 삼지 않는다.

  1. RT는 하나의 그래프에 의존성을 선언하고 Compile에서 컬링·실행 순서·배리어 계획을 확정한다.
  2. 살아남은 패스의 software encoder callback을 기존 기록 계획에 따라 병렬 실행한다. GPU 선후 관계와 CPU 기록 작업의 독립성을 구분한다. 기록 callback은 네이티브 목록에 직접 기록하지 않는다.
  3. 기록 writer를 합류하고 compiled order로 software batch를 봉인한다. 자원 표의 핸들 세대·네이티브 참조와 descriptor·upload lease를 고정한다.
  4. RHI 스레드가 backend translation을 수행하거나 번역 worker에 위임하고, 결과 목록을 정해진 순서로 제출한다. 즉시 업로드·복사·query resolve도 pending stream을 통해 RHI 스레드에서 기록·Close·제출한다.

16.1 구현 API

  • DX12DeviceResources::SetDeferredImmediateRecording: 기본 live software RHI 경로의 즉시 명령을 pending 기록으로 전환한다. 프레임 admission 경계에서만 전환한다.
  • GetDeferredImmediateEncoder / SealImmediateSoftware: 즉시 RHI 명령을 software batch로 보관하고 native upload/copy 사이의 기록 순서를 유지한다.
  • RecordImmediateNative / CopyPendingValues: backend 작업과 임시 POD payload를 소유 저장소에 기록한다. 메시·텍스처 upload 및 fog neutral copy, query resolve가 소비한다.
  • SubmitPendingImmediate: RHI 작업을 enqueue한다. 네이티브 allocator/list의 Reset·생성·기록·Close·Execute·Signal은 RHI 스레드가 처리한다.
  • DX12PendingCommands: mimalloc RenderArena lease를 사용한다. 캡처 객체를 먼저 파괴한 뒤 아레나를 반환한다. 명령은 한 번만 실행하고 실행 후 추가 기록을 거부한다.
  • RHISoftwareBatch::ReplaySerial: 즉시 명령의 단일 target software batch를 이미 열린 native encoder로 번역한다.
  • RecordingSnapshot: texture/buffer의 세대·COM 참조·GPU 주소·sparse heap·allocation lease를 고정한다. 번역 중 live handle table의 슬롯 재사용을 따라가지 않는다. snapshot 컨테이너는 독점적으로 회수된 뒤 용량을 재사용한다.
  • Write*View / CopyNativeDescriptors: 병렬 기록 writer가 고정 descriptor 슬롯에 설명과 자원 참조를 저장하고 합류 후 RHI 스레드가 생성한다. 호출마다 동기 RHI 왕복을 하지 않는다.
  • cold 자원 생성의 동기 RHI 서비스는 생성 결과와 작업 전달 결과를 분리한다. 예산·인자에 의한 할당 거절을 submission owner fault로 바꾸지 않는다.

16.2 수명과 대기

기록 producer는 합류까지 입력의 소유권을 유지한다. 봉인된 batch와 pending stream은 CPU 번역 완료만으로 자원을 반환하지 않는다. submission retirement의 GPU completion point가 descriptor·upload·자원 snapshot·명령 payload의 반환을 결정한다. 프레임 슬롯 allocator/list는 해당 슬롯의 CPU ticket과 GPU fence가 끝난 뒤 재사용한다.

현재 CaptureRecordingResources는 RHI 서비스가 descriptor snapshot을 확정할 때 CPU ticket을 기다린다. 이것은 GPU 완료 대기와 별개이며 RHITicketWait와 ETW 상태로 측정한다. 이 경계를 비동기화했다고 표시하지 않는다.

이번 제품 전환 대상은 CreatorRobot이 소비하는 기본 live DX12 software RHI graphics queue 경로다. 별도 owned-queue 실험 경로는 기존 queue recorder/translator를 사용하고 새 deferred immediate 모드를 켜지 않는다. native 직접 기록 대조 경로는 CREATOR_RHI_DEFERRED_BACKEND=0으로 선택한다. 기본값은 1이다.
