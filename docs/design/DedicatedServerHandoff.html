현재 코드와 인계 목표

상세 계약과 작업 항목 읽기

현재 Engine/SceneRuntime/RuntimeFrame.cpp의 Runtime::TickSimulationFrame은 Initialization → InputEvents → 관리 PrePhysics → Physics → GameLogic → 관리 PostPhysics를 전달받은 delta로 프레임당 한 번 실행한다. pause이면 Pausing 뒤 반환한다. 고정 tick 누산, tick 시작 입력 적용, tick 완료 observer 호출은 없다.

Engine/RuntimeHost/EngineBootstrap.h의 InitializeRuntime은 렌더 스레드 훅을 등록하고, Run은 WindowsCoreWindow를 생성한다. EngineLaunchConfig.h도 WindowsWindow와 RuntimeSettings를 포함한다. 현재 공통 bootstrap을 그대로 서버 진입점으로 쓰면 윈도우와 렌더 관련 코드가 서버에 들어간다.

Component.cpp::OnPropertyChanged는 이름으로 ProxyDirty를 분류해 렌더 dirty를 발행한다. 이 함수는 범용 복제 변경 스트림을 제공하지 않는다. SceneRuntime.vcxproj는 렌더 include 경로를 가진 static library다. 프로젝트 참조 목록만으로 최종 서버의 렌더 링크 제거를 판정하지 않고 실제 참조 심볼과 최종 링크 산출물로 닫는다.

인계 목표는 담당자가 NetCore / NetReplication / Transport / ServerHost를 소유하고, 엔진 담당자가 제공한 simulation·scene·content 경계만 사용해 서버를 완성하는 것이다. 현재 파일에는 이 설계의 구현을 추가하지 않는다.

계약은 네트워크 wire 계약과 프로세스 내부 engine adapter 계약으로 구분한다. wire에는 EntityHandle·포인터·size_t·STL 객체 메모리 표현을 쓰지 않는다. engine adapter는 simulation thread 안에서 로컬 EntityHandle을 사용할 수 있다. span과 callback context pointer도 프로세스 내부 호출에만 사용하고 wire로 복사하지 않는다. wire gate는 wire schema와 codec을 검사하며 로컬 adapter까지 일괄 금지하지 않는다.

5.1 tick 시작과 완료

OnTickCommitted만으로는 inbound 명령을 물리 전에 적용할 수 없다. N3-b에 다음 두 경계를 함께 제공한다.

  1. OnTickStarting(TickContext): session/scene 구조 변경 반영 뒤, 해당 tick의 gameplay· physics 실행 전 호출한다. bounded 입력을 drain하고 NetId 해석·권한 검사 후 적용한다.
  2. OnTickCommitted(TickContext): 물리 작업 join, 해당 tick의 권한 gameplay와 구조 변경 commit을 마친 뒤 호출한다. 이 경계에서 불변 snapshot을 만든다.

둘 모두 simulation thread에서 동기 호출한다. callback은 I/O 대기나 scene 재진입을 하지 않는다. observer 등록·해제는 tick 밖에서만 허용하며 해제 반환 뒤 callback은 없다. 네트워크 상태는 완료 tick 값만 공개한다.

프레임 축 Initialization/InputEvents와 기존 관리 PrePhysics/PostPhysics/GameLogic을 tick마다 반복하지 않는다. 권한 gameplay·root motion·AI·충돌 사건을 고정 축으로 옮길 소비자 목록을 N3-b에서 확정한다. GameLogic은 표시 데이터 갱신을 포함하므로 전체 함수를 누산 루프에 넣지 않는다. OnSimulationTick은 생명주기 enum에 추가하지 않고 ClrHost 전용 진입점으로 배선한다.

tick rate·최대 catch-up 횟수·frame delta 상한은 세션 시작 설정으로 고정한다. 서버는 실행하지 않은 tick을 완료 처리하지 않는다. 누적 지연은 backlog와 overrun으로 계수하고 tick budget 소진 시 다음 host 반복에서 계속 실행한다. pause는 simulation tick을 멈추지만 transport poll·disconnect·종료 처리는 계속 실행한다. 새 세션은 epoch를 바꾸고 이전 명령·snapshot·baseline을 무효화한다.

5.2 엔티티 수명

Scene::AllocateSlot/ReleaseSlot은 슬롯 경계다. snapshot 공개 가능한 spawn 완료 경계와 같다고 취급하지 않는다. 다음 의미를 엔진이 보장해야 한다.

통지 시점 데이터
Bound 초기 component/state 적용과 spawn commit 뒤 local handle, local lifetime token, prefab asset identity
Rebound DDOL/scene transfer의 새 handle 확정 뒤 lifetime token, old/new handle
Unbound 최종 파괴 시 resolve가 닫히는 commit lifetime token, old handle, destroy 사유

이송 중 슬롯 해제를 최종 despawn으로 전달하지 않는다. detach와 attach 사이에는 resolve 실패 상태를 유지하고 동일 lifetime token으로 Rebind한다. 기존 NetId는 유지한다. 실패한 이송의 최종 파괴는 Unbound 한 번으로 끝낸다. raw Entity*를 identity로 보관하지 않는다. local lifetime token 발급과 transfer 상관관계는 엔진 소유, NetId 발급은 서버 담당 소유다.

5.3 쓰기 변경

OnComponentFieldWritten(local handle, component identity, field key, source, revision)을 게임 스레드 commit 경계에서 발행한다. engine field key는 wire NetFieldId와 분리하고 복제 schema adapter가 변환한다. 렌더 ProxyDirty를 네트워크 dirty로 해석하지 않는다.

Inspector/Undo·직렬화 load·native setter·managed setter·physics writeback·animation writeback 경로별로 호출 지점을 확인한다. virtual OnPropertyChanged override의 base 호출 유무에 관측이 좌우되지 않도록 공통 writer가 통지를 소유한다. 직접 필드 쓰기는 writer 경계로 옮기거나 명시적 component revision 갱신을 붙인다. 같은 tick의 반복 쓰기는 component/field 단위로 합친다. 초기 spawn state는 full snapshot에 포함한다. 클라이언트 수신 적용 source는 echo 재발행을 막되 서버 권한 상태 변경은 기록한다.

큐와 소유권

버퍼와 스레드 계약

상세 계약과 작업 항목 읽기

network thread와 simulation thread 사이에는 각각 하나의 명령/상태 소비자를 둔다. producer가 하나면 bounded SPSC, 여러 producer가 필요한 경로만 bounded MPSC를 쓴다. 큐 메모리와 payload pool은 시작 시 예약하고 tick마다 임시 vector를 만들지 않는다. pool slot은 index와 generation을 가진 lease로 전달하고 소비 종료 시 반환한다.

통로 포화 처리 반드시 보존할 정보
입력 상태 peer/input sequence별 최신값과 중복 window 정책 마지막 적용 sequence, stale/duplicate/drop 수
reliable 명령·spawn/despawn·사건 bounded pending → backpressure → peer 종료 적용 전까지 payload 소유권과 사건 순서
상태 snapshot 미소비 최신 상태로 교체 superseded 수, tick/epoch, 독립 reliable 사건 stream

상태가 spawn보다 먼저 도착하면 아직 알려지지 않은 object 상태를 bounded 보류하거나 폐기한다. reliable spawn 적용과 baseline 확보 뒤 복제를 재개한다. 서로 다른 lane의 전송 순서만으로 spawn-before-state를 보장하지 않는다. delta baseline은 수신측 적용 확인된 tick만 사용한다. baseline 유실은 full snapshot으로 복구한다. latest-wins 교체로 사라진 snapshot을 baseline으로 삼지 않는다.

Headless host

서버 host와 content 경계

상세 계약과 작업 항목 읽기

엔진 담당자는 window/presentation 초기화를 Runtime services 초기화에서 분리한다. ServerLaunchConfig는 content root, scene/prefab manifest, tick 설정, log 경로만 소유하고 WindowsWindowDesc나 render backend를 요구하지 않는다.

공통 bootstrap은 diagnostics·jobs·scene·physics·managed runtime의 시작/종료를 제공한다. 서버 담당자는 console host, monotonic clock 기반 deadline 대기, transport poll, graceful stop 요청, 실행 옵션·종료 코드를 구현한다.

content loader는 cooked scene/prefab 식별자와 결과 코드만 받는다. 서버 패키지는 게임플레이·충돌·script에 필요한 자산을 포함하고 GPU upload·material 생성 없이 읽힌다. authoring Document를 보관하는 경로를 서버 load가 타지 않도록 분리한다. managed gameplay assembly의 presentation 의존도 같은 기준으로 제거한다.

종료 순서는 새 입력 차단 → transport poll/send 중단 및 thread join → 남은 명령·snapshot drain/discard 계수와 lease 반환 → observer 해제 → replication/registry 해제 → Scene/managed/physics 해제 → jobs/diagnostics 해제다. 서버 simulation이 멈춘 후에도 살아 있는 network callback을 남기지 않는다.

담당자에게 전달할 묶음은 계약 헤더, schema/ID/tombstone manifest, 엔진 adapter 예제, 경계 회귀 명령, cooked 테스트 scene, 위 게이트 결과, 모듈별 파일 소유권 표다. 계약 변경 요청에는 영향 소비자·wire compatibility·회귀 변경을 함께 적는다. 새 wire ID와 tombstone 변경은 정본 NetworkFrameworkPlan에 기록한다.

현재 완료된 산출물은 이 설계 문서다. 계약 헤더 구현·엔진 확장점 배선·빌드·실행 게이트는 위 순서대로 수행할 후속 작업이다.
