생명주기 이전과 현재 실행 소유자

옛 델리게이트·virtual tick 재설계 문서의 링크를 유지하는 현재 구현 안내다.

기준: master 493536e300e274cbf59989cdd62b20310c8ae64f. 현재 소스와 호출부를 대조해 다시 썼다. 이번 개정에서는 빌드·테스트·제품 실행을 수행하지 않았다.

여섯 단계와 활성 축tick은 전용 시스템에서파괴와 이송Task와 후속 요구

여섯 단계와 활성 축

ScenePhase는 Detached, Attached, InScene, Simulating이다. component는 OnInitialized, OnAddedToScene, OnBeginSimulation과 역방향 OnEndSimulation, OnRemovingFromScene, OnUninitializing을 받는다. OnEnable/OnDisable은 존재·scene membership·simulation과 별도 축이다.

네이티브 ScriptComponent가 같은 번호의 ScriptLifecyclePhase를 managed registry로 전달한다. managed membership add/remove는 자체 lifecycle driver가 아니다. opening 단계의 호출과 성공을 구분해 실패한 단계의 cleanup을 잘못 짝짓지 않는다.

tick은 전용 시스템에서

Component virtual Update/LateUpdate/FixedUpdate와 SystemSchedule의 세 tick 목록은 현재 실행 정본이 아니다. native Animator/UI/Camera/Sound 등은 전용 시스템 배열을 사용한다. LifecycleRegistry의 override mask는 initialization/scene/simulation/enable 관련 훅을 선택하는 데 남아 있다.

관리 스크립트는 frame당 PrePhysics/PostPhysics를 받는다. 실제 물리의 60Hz catch-up과 관리 fixed tick은 별개다. 전체 순서는 FrameLifecycle에 있다.

파괴와 이송

순회 중에는 destroy mark를 남기고 Scene::EndFramePass에서 pending cleanup과 구조 제거를 수행한다. 실제 메모리는 GCCE domain의 root/trace 관계와 안전한 collection 경계로 관리된다. raw pointer 반환은 소유권 이전이 아니다.

DDOL 이동은 initialize를 다시 하지 않으므로 시스템 등록은 AddedToScene/RemovingFromScene에 연결해야 한다. 새 Scene handle을 재해석하고 script object의 별도 전역 identity를 유지한다.

Task와 후속 요구

OnSimulate는 Begin 성공 뒤 시작하며 Scope 취소가 End보다 먼저다. Delay와 continuation drain, cleanup 예외 격리는 현행 Task 계약에 정리했다. 일반 effect executor와 PrSM은 미래 범위다.

과거 재설계 단계별 PASS는 현재 실행 결과가 아니다. 이번 갱신에서는 hook 순서·소유 구조를 소스로 확인했고 제품 재진입/파괴/재로드 시험은 실행하지 않았다.
