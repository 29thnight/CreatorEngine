C++ 스크립트 이전 이후의 ScriptCore 계약

옛 ModuleBehavior→CoreCLR 문서 링크를 보존하며 현재의 공개 API와 미구현 요구를 구분한다.

기준: master 493536e300e274cbf59989cdd62b20310c8ae64f. 현재 소스와 호출부를 대조해 다시 썼다. 이번 개정에서는 빌드·테스트·제품 실행을 수행하지 않았다.

현재 모델생명주기와 tick값 핸들과 wrapper직렬화와 생성기reload 수명AOT에 대한 정확한 범위옛 데이터 처리확인한 것과 실행하지 않은 것계속 유지하는 경계스크립트 추가 절차현재 참고 문서

현재 모델

사용자 스크립트는 CreatorEngine.Component를 상속한다. native ScriptComponent는 owner/lifecycle/managed instance를 연결하고 ScriptCore.Generators가 등록·field access·named callback을 생성한다. net10.0 CoreCLR hosting이며 dynamic C++ ModuleBehavior가 현재 게임 저작 경로인 것은 아니다.

생명주기와 tick

OnInitialized→OnAddedToScene→OnBeginSimulation과 역순 cleanup을 사용한다. enable은 별도이며 OnSimulate Task는 Begin 성공 뒤 시작한다. PrePhysics/PostPhysics는 frame 축이다. 옛 Awake/Start/OnDestroy/Update 이름의 bridge가 있다고 가정하지 않는다.

값 핸들과 wrapper

Entity는 ObjectHandle의 비소유 값이며 IsAlive로 검증한다. native EntityHandle의 scene-scoped 세대와 script registry 세대는 별개다. GetComponent는 managed script와 native wrapper를 구분한다. physics/character wrapper는 component instance identity도 캡처한다. Transform 부재는 null/HasTransform으로 처리한다.

직렬화와 생성기

SerializeField와 generator가 관리 field descriptor/접근자를 만든다. native reflgen은 C++ 저작 서술의 다른 시스템이다. field type, 등록명, native table layout, reload 복원은 함께 검증한다. 일반 CLR reflection에 모든 직렬화와 callback을 맡기는 표면이 아니다.

reload 수명

ScriptAssemblyLoader/ScriptFactory/ScriptRegistry가 collectible context와 instance를 관리한다. Scope를 취소하고 registry·delegate·pending continuation을 정리해야 옛 assembly 참조를 놓을 수 있다. scene unload에서 전체 managed registry를 무조건 clear하면 DDOL script/tree를 잃는다. orphan sweep과 assembly reload clear를 구별한다.

AOT에 대한 정확한 범위

generator의 직접 callback dispatch와 trim analyzer는 AOT 준비 재료다. 현재 csproj의 IsTrimmable/EnableTrimAnalyzer가 NativeAOT Player 출하를 증명하지 않는다. hostfxr/CoreCLR 경로가 현재 실행 경로다.

옛 데이터 처리

ComponentFactory는 옛 ModuleBehavior 노드에 InvalidScriptComponent를 붙여 scene 로드를 계속한다. 원본 C++ script가 자동으로 C#으로 변환되거나 동작을 복구하지 않는다. 새 Component로 교체하고 field·lifecycle·asset reference 의미를 명시적으로 옮겨야 한다.

확인한 것과 실행하지 않은 것

현재 source의 class·함수표·host 호출·생명주기 연결을 확인했다. build, hot reload, Editor Play, cooked Player, trimming/AOT 검증은 이번에 실행하지 않았다. 과거 이행 규모나 속도 배수는 현재 기능 보장으로 재사용하지 않는다.

계속 유지하는 경계

게임 스레드에서 native state를 resolve하고 cross-thread 값 계산과 Scene mutation을 분리한다. Scope cleanup과 단계 성공 계약을 유지한다. fixed OnSimulationTick, typed input-action value, 효과 기록/PrSM은 별도 계획이며 이미 구현된 API처럼 사용하지 않는다.

스크립트 추가 절차

partial Component 클래스를 만들고 필요한 SerializeField와 훅을 선언한다. managed build에서 generator 출력을 확인하고 native table version/size가 host와 일치하는지 확인한다. Editor에서 attach→save/reload→Play/Stop→assembly reload를 점검한다. 임의 포인터를 field에 저장하거나 IsAlive 대신 이름을 수명 검사로 쓰지 않는다.

현재 참고 문서

public surface와 한계는 ScriptCore 계약, async 실패는 Task 안정화 계약, 물리는 물리 API, 오디오는 오디오 운영 계약을 따른다.
