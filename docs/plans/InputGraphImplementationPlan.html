01

전환 결정과 완료 범위

CreatorEngine의 공개 입력 API와 실행 경로를 InputGraph → InputSession → InputFrame 계약으로 교체한다. 시간 정보가 있는 장치 기록과 소유권 변경 기록을 순서대로 평가하고, 사용자별 상태에서 생성한 불변 결과를 C++와 C#이 함께 소비한다.

개발은 검증 가능한 작은 단위로 진행한다. 운영 전환은 새 자산·cook·런타임·에디터·C# 소비자를 갖춘 하나의 배포 단위로 수행한다. 구 런타임과 새 런타임의 동시 운영이나 실행 중 legacy fallback은 두지 않는다.

이 계획에서 고정하는 결정

  1. 정의와 상태 분리 — InputGraph와 실행 정의는 불변이다. 장치 할당, 활성 계층, Hold·Tap·Chord 상태는 InputSession이 소유한다.
  2. 이력 우선 — 한 틱의 press·release·반복 press를 모두 보존한다. 조회와 이벤트 구독은 같은 InputFrame에서 나온다.
  3. 하나의 소유권 규칙 — UI와 게임은 서로의 큐를 경쟁해서 빼지 않는다. 중앙 라우팅 계약 아래 별도 평가 상태와 소비 경계를 사용한다.
  4. CPU용 작은 실행 데이터 — LX 입력 도메인은 준비된 배열과 상태 머신 정의로 컴파일한다. 범용 VM이나 런타임 문자열 호출은 도입하지 않는다.
  5. 안전한 전환 — 포커스·계층·장치·자산 변경은 취소와 중립 복귀를 포함한다. 과거에 봉인한 결과를 뒤늦게 고치지 않는다.

출시 필수 범위

키보드·마우스·게임패드, Button·Float·Vector2, 유지 값과 delta 값, Press·Hold·Tap·Chord, 우선순위와 독점 계층, 리바인딩, 로컬 다중 사용자, LX 입력 저작과 C# 타입 안전 접근, C++·C# 조회와 구독, 에디터·cook·진단·오프라인 변환을 모두 포함한다. 이 항목들은 후속 과제로 미루지 않는다.

범위 밖

새 범용 그래프 VM, 자체 할당기, 모든 입력의 job/future화, 게임플레이 규칙, 네트워크 예측·롤백과 물리 결정성, RHI 추상화 변경은 포함하지 않는다. 터치와 특정 Xbox 하드웨어 어댑터는 기존 구현 여부를 확인한 뒤 capability 단위로 추가한다. 일반 게임패드 계약과 GameInput 사용만으로 해당 하드웨어 지원을 보장하지 않는다.

02

현재 근거와 구현해야 할 차이

아래의 확인 사실은 제공된 소스 검토와 고정 커밋의 링크에 근거한다. 계획 계약은 이번 작업에서 새로 구현하고 검증할 내용이다. 이전 제안에서 지적한 실행 경로는 INP0에서 호출자와 자산까지 대조한 뒤 삭제 목록을 확정한다.

구분기준에서 확인된 내용구현 조치
확인 사실LXNodeDefinitionRegistry와 공통 그래프·핀 모델이 있다. 도메인별 정의 등록 기반을 재사용할 수 있다.input 도메인 노드 등록·검증·CPU 컴파일러를 추가한다. 기존 LX 실행기가 입력을 이미 지원한다고 가정하지 않는다.
확인 사실LX 핀 타입은 고정 enum이며 기존 Vector 표현은 3성분이다. 숫자 enum 값과 variant 순번이 저장된다.Vector2·Button·이벤트 의미의 저장 계약을 명시하고 기존 숫자 ID를 보존한다. 검증·핀 위젯·archive·호환성 테스트를 함께 수정한다.
설계 근거LX 설계는 공통 저작과 도메인별 실행의 책임을 분리한다.편집 노드 객체를 매 틱 해석하지 않는다. 입력 도메인은 CPU 평가 계획과 세션 상태 레이아웃을 만든다.
정적 소스 근거InputActionManager는 map을 소유·삭제하고 PlayerInput은 null일 때만 찾은 raw ActionMap*을 캐시한다. 재로드 뒤 dangling 위험은 정적 분석상의 추론이다.AssetDepot lease와 안전 핸들로 수명을 연결한다. 실제 재로드/UAF 재현은 별도 검증한다.
정적 소스 근거ActionMap의 float 처리 경로에 빈 구간이 있고 파싱·Vec2 접근에는 타입/성분 계약 차이가 지적됐다.Button·Float·Vector2를 명시 스키마로 검증하고 불명확 legacy 타입은 변환 오류로 남긴다.
정적 소스 근거InputManager에서 GameInput 누적 위치와 client 좌표 사용, delta reset 경계가 혼재한다.PointerPosition과 MouseDelta의 공간·단위·소진 시점을 분리하고 실측 trace로 회귀 검증한다.
정적 소스 근거기존 입력 평가와 script queue flush가 물리 이후에 놓인 경로가 검토됐다. pause의 조기 반환과 UI 입력 callback 적재는 미전달 위험이 있다.게임 결과를 PrePhysics 전에 봉인·dispatch하고 UI는 고정 틱 밖에서 별도 소비한다. 미전달 증상은 런타임 검증 전 추론이다.
계획 계약입력 수집의 FG/GT 대기 독립성, 시각 기반 틱 배정, UI 비동기 소유권, AssetDepot lease, NativeAOT 접근자기존 동작으로 주장하지 않는다. 추적 기록·테스트·수명 검증을 통과해야 새 계약으로 확정한다.

LX 근거: LXNodeDefinition.h · LXGraph.h · LatticeNodeSystem.md
입력 정적 검토 근거: InputActionManager.cpp · PlayerInput.cpp · ActionMap.cpp · InputManager.cpp · RuntimeFrame.cpp
증상은 실행 확인이 아닌 정적 분석의 위험 해석이다. ScriptSurfacePlan의 W3도 typed value/query와 실제 소비자 회귀 검증을 남은 작업으로 기록한다.

착수 시 반드시 만드는 조사 산출물

  • 공개 헤더·C# 바인딩·컴포넌트·에디터·cook·런타임의 입력 의존 목록과 담당 소비자
  • 모든 inputmap의 신호 타입, 바인딩, 콜백 대상, 이름 기반 참조 및 타입 결정 근거
  • 장치 수집 스레드, GameInput reading 보존 한계, 큐 생산자 수, ImGui 접근 위치와 현재 취소 동작
  • raw 입력 사용처의 목적 분류: 게임 신호로 이전 / UI 문자·IME 유지 / 플랫폼 전용 기능 유지 / 삭제
  • 배포 자산·생성 코드·스크립트 ABI를 묶는 버전 표와 되돌릴 이전 전체 아티팩트

경로가 확인되지 않은 구현 파일명은 이 문서에서 새로 만들지 않는다. 작업 단위는 책임과 산출물로 정의하고 INP0 조사에서 실제 모듈 경로에 연결한다.

03

전체 구조와 소유권

공유 자산에는 안정 ID, 값 타입, 바인딩, 값 변환, 판정 설정, 계층 정책만 둔다. 세션은 AssetDepot 자산 소유권 계약에 맞는 lease로 실행 정의의 수명을 유지하고, 장면 컴포넌트는 세대 검증을 포함한 안전한 핸들로 세션을 참조하도록 한다. 이름 변경·재로드 후에도 raw pointer가 남는 구조를 허용하지 않는다.

실행 상태는 세션과 평가 도메인별로 분리한다. control 값, 판정 타이머, chord 진행, 충돌 승자, 중립 대기, 장치 할당 epoch와 사용자 override도 세션별 상태다. 같은 정의를 공유하는 두 사용자나 게임/UI의 Hold 타이머는 서로 영향을 주지 않는다. 세션 상태의 쓰기는 지정 소유 스레드 하나에서만 수행한다. 다른 스레드는 명령과 기록을 전달한다.

입력 플랫폼 경계는 장치 기록 수집·시각 변환·capability·출력 명령만 담당한다. RHI나 렌더 API를 입력 계층의 의존성으로 추가하지 않는다. 수집이 GT/렌더 정체와 분리되려면 실제 독립 수집 경로나 native callback·장치 이력 접근을 확보해야 한다. 기록 보존은 유한하며 장시간 정체 시 gap 복구가 필요하다. 단일 생산자가 확인된 경계에만 SPSC를 적용하고, 다중 생산자는 단일 병합 지점 또는 기존 검증 큐를 사용한다.

04

공개 API와 값 계약

아래는 공개 API 제안이다. 서명과 레이아웃을 고정하는 작업은 INP0·INP3에서 수행하며, 예시 이름은 실행 가능한 구현 코드가 아니다.

공개 이름역할과 소유권사용 규칙
InputGraphLX로 저작하는 정식 입력 자산안정 신호·계층·바인딩 ID를 갖는다. 표시 이름과 정체성을 분리한다.
InputSignal<T>정의에 속한 타입 고정 신호 식별자Move: Vector2, Jump: Button, AimStrength: Float. 잘못된 타입 조회는 생성 시 또는 컴파일 시 검출한다.
InputBinding장치 control과 신호를 연결하는 정의source·processor·interaction·combine 정책과 stable ID를 가진다. 사용자 override의 대상이 된다.
InputLayer활성화·우선순위·소유권의 단위상속 계층이나 LX 화면 정리 그룹이 아니다. Gameplay·Menu·Vehicle을 세션별로 활성화한다.
InputSession사용자별 장치·계층·판정 상태 소유자생성/종료·장치 할당·계층 변경 요청·리바인딩을 제공한다. 변경은 명시된 입력 경계에서 적용한다.
InputFrame평가 한 번의 읽기 전용 상태와 사건session·domain·tick/sequence·정의 세대·시간 범위·누락 플래그를 포함한다. 게임 틱과 UI sequence를 혼동하지 않는다.
SignalEvent<T>순서가 보존된 신호 전이stable signal ID·종류·값·원시/유효 시각·순번·사용자·취소 사유를 갖는다.

신호의 정체성과 계층 소유

신호 정체성은 graph asset GUID와 signal GUID의 쌍이다. InputSignal<T>는 공유 live value가 아닌 불변 typed key이고, 실제 값은 특정 세션과 프레임에서 읽는다. 한 signal ID의 타입은 불변이며 타입 변경은 새 signal ID를 요구한다. 각 신호는 정확히 하나의 InputLayer에 속한다. v1은 계층 사이의 stateful 의존을 거부한다. 컴파일된 인덱스·포인터는 영속 ID로 저장하지 않는다.

타입과 축 의미

  • Button은 눌림의 논리 상태와 전이를 나타낸다. 아날로그 source는 명시된 press/release threshold와 hysteresis로 Button에 변환한다.
  • Float와 Vector2는 각각 스칼라와 2성분 값이다. 유지형 값은 다음 변경까지 유지하고, delta는 귀속된 평가 구간에서만 합산한 뒤 다음 결과에서 0으로 시작한다.
  • PointerPosition은 위치 값, MouseDelta는 delta다. 좌표 공간·단위·감도 적용 순서를 자산에 기록한다. Vector2라는 이유만으로 두 의미를 암묵적으로 섞지 않는다.
  • 대체 바인딩의 합산·최댓값·최근 입력 선택은 명시 설정이다. 동률은 고정 stable binding ID 순으로 해결한다. 클램프·정규화 여부와 deadzone 앞뒤 순서를 저장한다.

조회와 이벤트의 일치

상태 슬롯은 최종 값·held·해당 구간에 press/release가 있었는지를 제공한다. press와 release가 같은 구간이면 두 플래그가 모두 true이고 최종 held는 false일 수 있다. 반복 횟수와 순서는 이벤트 목록에 보존한다. 조회는 입력을 소진하지 않는다. 게임플레이 명령 생성 담당을 하나로 정해 조회자 수만큼 Jump가 실행되지 않게 한다.

05

LX 입력 도메인과 CPU 준비

저작 노드와 제한된 그래프

장치 노드 Key·MouseDelta·PointerPosition·GamepadAxis·GamepadButton, 값 노드 Axis2D·Deadzone·Normalize·Scale·Invert, 판정 노드 Press·Hold·Tap·Chord, 결합 노드 우선 선택·최댓값·합산, 타입별 신호 출력을 제공한다. 복합 조건의 enable/gate 의미도 명시해 우측 마우스 버튼과 MouseDelta로 Look을 정의할 수 있어야 한다.

InputLayer·포커스·장치 분리 안전 정책은 공통 런타임이 적용한다. 그래프마다 안전 노드를 복제하지 않는다. Hold·Tap의 기억은 세션 FSM 슬롯에 두며 그래프 feedback cycle로 표현하지 않는다. Chord의 신호 의존성은 정방향 DAG로 제한한다.

준비 파이프라인

  1. 정규화 — LX 문서에서 입력 스키마를 정규화한다. layout 데이터는 실행 의미에서 제외한다.
  2. 검증 — ID 중복, 핀 타입·값 의미, source capability, 유효하지 않은 수치, output 누락, 계층 충돌, dependency cycle을 진단한다.
  3. 계획 생성 — control → binding 조회표, 값 처리의 위상 순서, interaction 정의, 상태 슬롯 인덱스, 출력 슬롯, 충돌 후보표를 만든다.
  4. 배치 준비 — 실행 배열·상태 크기·생성 접근자 manifest·semantic hash를 고정한다. 편집 노드의 포인터나 표시 이름 lookup은 핫패스에 남기지 않는다.
  5. 게시 — 완성된 정의만 AssetDepot에서 lease로 제공한다. 검증 실패는 현재 유효 정의를 훼손하지 않으며 새 게시를 차단한다.

Vector2와 직렬화 안전 확장

기존 numeric enum 값과 variant index를 중간 삽입으로 이동시키지 않는다. 신규 값은 끝에 명시된 안정 ID로 추가하고, variant의 기존 대안 순서도 보존한다. 새 archive 버전은 wire type tag를 명시적으로 기록하며 구버전은 검증된 매핑 테이블로 읽는다. 미지원 tag·차원·버전은 실패시킨다.

핀 연결 검증, 기본값 편집 위젯, 복사/붙여넣기, undo/redo, archive read/write, 노드 등록, cook, C# 타입 매핑을 함께 수정한다. Button/Event 메타데이터가 값 핀과 실행 흐름 핀을 혼동하지 않도록 도메인 규칙을 정한다. 기존 Vector3 파일 round-trip과 혼합 자산 회귀 테스트를 전환 gate로 둔다.

편집 세대와 의미 세대

노드 위치·색·접기 상태 변경은 layout revision만 증가시킨다. 실행 의미 hash·접근자·cook을 다시 만들지 않는다. Hold 시간·바인딩·타입·정책 변경은 새 semantic generation을 준비하고 입력 경계에서 원자 교체한다. 기본 교체 정책은 영향받는 신호 취소와 중립 복귀 후 재무장이다.

06

기록 순서와 틱 시간 배정

장치 시각은 세션 시작 시 엔진 단조 시계로 정규화한다. 벽시계·렌더 프레임 번호를 사용하지 않는다. 기록에는 source timestamp, 정규화 시각, 수신 시각, 전역 수신 순번, 장치 세대, 기록 종류를 보관한다. 순번은 병합 지점에서 부여하며 같은 시각의 tie-break다.

시계 계약

시뮬레이션 시간은 단조 실시간 구간별로 누적한다. 구간 k의 시작 실시간을 Rk, 누적 시뮬레이션 시간을 Sk, 고정된 timeScale을 ak라 하면 S(t) = Sk + ak × (t − Rk)이다. pause 구간은 ak=0이다. 곱셈·경계 비교는 정수/고정 정밀도 또는 유리수 변환으로 정의하고 반올림 규칙을 테스트한다. 플랫폼 부동소수 오차로 경계가 바뀌지 않게 한다.

고정 간격 Δ의 틱 n은 ((n−1)Δ, nΔ]을 소비한다. 시작 시각의 입력은 첫 미실행 틱에 포함한다. 시각 t의 예정 틱은 S(t)를 이 규칙으로 매핑하며, 해당 틱이 이미 봉인됐으면 다음 미실행 틱에 귀속한다. 원래 시각·예정 틱·실제 틱과 지연 사유를 모두 남긴다. 아직 경계 밖인 기록은 보관한다.

timeScale 변경은 미리 확정된 구간 경계에서만 시작한다. 이미 실행한 시간 매핑은 바꾸지 않는다. 누적 시간 자체를 버리는 catch-up 제한이 필요하면 clock discontinuity 기록을 만들고 pause와 같은 취소·재동기화 계약을 적용한다. 조용히 이벤트 시간만 당기지 않는다.

정책과 이벤트의 단일 순서

선택된 입력·장치·계층·포커스·소유권 기록을 유효 시각, 전역 순번 순으로 처리한다. 늦게 수신한 기록의 유효 시각은 이미 확정된 처리 frontier보다 앞설 수 없다. 이미 봉인된 틱이나 외부에 보낸 결과를 되돌리지 않는다. 각 장치 이벤트는 그 시점까지 처리된 정책으로 해석한다. 최신 컨텍스트 하나를 과거 배치 전체에 적용하지 않는다.

PT 정책은 수신 후 첫 미봉인 입력 경계에서 commit한다. 경계에 앞선 원시 기록은 기존 commit 정책으로 먼저 처리하고, commit 이후 기록부터 새 정책으로 해석한다. UI 세대는 stale update를 버리는 기준이며 과거 입력이 올바르게 분류됐다는 증거가 아니다. source time·ingress 순번·effective boundary·정책 세대·late reason을 각각 기록한다. 뒤늦은 UI capture는 다음 경계에서 진행 중 신호를 취소하지만 이미 분류·봉인한 입력의 소급 소비가 아니다.

타이머와 입력이 만나는 경계

게임 Hold·Tap·Chord 기본 시간은 활성 시뮬레이션 시간, UI는 단조 실시간이다. 한 평가 구간 안에서도 입력 시각과 예정 타이머 만료 시각을 병합해 FSM을 진행한다. 동시각이면 입력·정책 기록을 순번대로 처리한 뒤 만료를 처리한다. 기본 Tap은 threshold 이하 해제에 성공하고, Hold는 threshold에서 여전히 눌려 있을 때 수행한다. 같은 구간의 짧은 누름을 최종 상태만 보고 누락시키지 않는다.

늦은 기록의 판정 시계: Hold·Tap·Chord의 시작과 deadline은 clamp한 유효 시각을 해당 도메인 시계로 변환해 계산한다. clamp 뒤에는 원 source timestamp를 경과 시간 계산에 다시 사용하지 않는다. 늦은 press가 들어오자마자 원래 발생 시각을 근거로 Hold가 완료되는 동작은 금지한다. press/release가 같은 frontier로 clamp되면 순번은 유지하고 판정 경과는 0이다. 이 시간 압축은 late 진단에 드러내며 과거 실제 누름 시간을 복구했다고 해석하지 않는다.

pause와 복귀

pause 진입은 게임 신호를 Cancel하고 게임용 delta를 비운다. 정지 중 수집과 UI 처리는 계속하지만 게임 판정이나 게임 이벤트 backlog는 축적하지 않는다. 재개 시 현재 장치 상태를 재동기화하고 눌린 control은 중립을 확인할 때까지 재무장하지 않는다. pause·timeScale 기록 자체도 replay에 포함한다.

07

게임 UI와 PT 경계

소유권과 상태 분리

세션의 중앙 소유권 규칙은 사용자 할당, 활성 계층, 장치/control 단위 claim, UI capture 세대를 관리한다. 정책 commit은 공통 라우팅 시간선에서 한 번 수행하고 그 경계를 게임 시계와 UI 시계에 각각 매핑한다. 중앙 라우팅은 각 기록에 그 시점의 policy/claim epoch와 수신 대상 결정을 붙여 불변으로 남긴다. 게임/UI 평가기는 같은 코어를 쓰되 별도 FSM·delta 누적·frontier를 갖는다. 기록 로그에서 각자 cursor로 읽으며 서로 먼저 pop하는 큐를 사용하지 않는다. UI가 먼저 처리해도 뒤늦게 따라잡는 게임 cursor는 각 기록의 당시 epoch와 수신 대상을 사용한다. 최신 UI claim이나 공유 mutable policy로 과거 기록을 다시 분류하지 않는다. 새로운 claim·취소 결정은 뒤따르는 공통 기록으로 게시하며 이미 분류한 기록은 고치지 않는다. 늦은 소비자가 유지 한계를 넘으면 gap 복구를 수행한다.

게임 평가기는 매 fixed tick의 PrePhysics 전에 InputFrame을 봉인한다. UI 평가는 고정 틱이 0회인 업데이트에서도 실행한다. GT가 UI 실행을 담당한다면 pause 루프에서도 해당 경로를 펌프해야 한다. 이 보장은 GT가 실행 중이라는 전제다. GT 자체가 멈추면 그 스레드의 UI 평가도 멈추며 별도 UI 실행 스레드가 있다고 가정하지 않는다. ImGui 접근은 PT에만 있고 GT는 세대가 있는 정책 기록과 입력 결과만 다룬다. 입력 이벤트마다 PT 응답을 기다리는 동기 round-trip은 금지한다.

충돌 정책 세 가지

  • press 시점 독점 — 상위 계층이 candidate를 받는 순간 claim한다. Hold가 성립하기 전 하위 계층에 최초 press가 새지 않는다. 기본 메뉴·modal 정책이다.
  • 판정 성립 시 소비 — 성립 이전의 하위 이벤트는 이미 전달될 수 있다. 뒤늦게 없었던 것으로 만들지 않으며 이 특성을 에디터에 표시한다.
  • 통과 — 여러 계층이 관측한다. 게임 명령 중복 방지는 소비자 책임과 명시된 command owner로 해결한다.

비동기 경계의 현실적인 보장

UI가 capture를 획득하면 처리 가능한 가장 빠른 다음 입력 경계에서 게임의 진행 중 신호를 취소한다. 이미 봉인한 게임 틱의 press는 소급 삭제하지 않는다. 메뉴 열기를 게임 코드가 요청하는 경우에는 같은 중앙 정책 요청을 즉시 제출해 PT 관측만 기다리지 않는다. 메뉴를 여는 그 press 자체를 하위 게임에 전달하지 않아야 한다면, 해당 press를 게시하기 전에 엔진 명령 경로에서 소유권을 예약해야 한다. 나중에 도착한 ImGui capture 정보만으로 이 보장을 만들 수 없다. PT 정체·GT 정체·큐 지연의 최악 지연은 추적하고 acceptance에서 검증한다. 지연이 짧다는 이유로 동시성이나 결정성을 주장하지 않는다.

상태 전이와 취소 재무장

신호는 Idle·Started·Performed·Completed·Canceled 전이를 표현하되 현재 값과 이벤트 발생을 구분한다. Performed는 판정 성공, Completed는 정상 종료, Canceled는 소유권·수명·장치·누락 때문에 중단된 결과다. 취소를 release에 의한 정상 성공으로 바꾸지 않는다.

재무장 규칙

디지털 control은 release, 아날로그 축은 release threshold 이하의 중립 영역, chord는 참여 control 전체의 중립으로 재무장한다. 유지 값은 차단 해제 시 기본 0에서 시작한다. 즉시 이어받기가 필요한 축은 명시 정책과 별도 테스트가 있어야 하며 버튼/charge에 암묵 적용하지 않는다.

취소 시점에는 같은 신호에 대해 한 번의 Canceled 이벤트와 reason을 만든다. Canceled와 Completed를 함께 발생시키지 않는다. Hold·Tap의 성공 조건이 충족되기 전에 소유권을 잃으면 Performed를 만들지 않는다. 다중 바인딩 신호에서 일부 장치만 사라진 경우 남은 기여로 계속할지 전체 취소할지는 신호 정책에 고정하며 기본은 영향받은 interaction 취소 후 재계산이다.

판정별 필수 의미

  • Press는 press edge에서 수행한다. OS key repeat는 별도 반복 설정 없이는 새 press로 해석하지 않는다.
  • Hold는 정해진 시간과 조건을 충족할 때 한 번 수행한다. 반복 Hold는 명시 옵션과 타이머 이벤트를 사용한다.
  • Tap은 시간 제한 안의 정상 해제에서 수행한다. focus-loss·disconnect·cancel은 Tap 성공이 아니다.
  • Chord는 참여 신호, 동시/순차 조건, 허용 시간 창, claim 범위를 정의한다. 종속 신호의 DAG 위상 순서와 동일시각 규칙을 고정한다.

C++ C# 타입 안전 소비 경계

LX 저작과 스크립트 접근의 연결

LX가 InputGraph의 저작 원본이며 C#과 C++은 그 출력 정의에서 생성된 접근자를 사용한다. 스크립트는 신호 조회·이벤트 구독·계층 변경·장치 할당·리바인딩 요청을 수행한다. 필수 범위는 LX 입력 편집과 이 타입 안전한 스크립트 접근이다.

출력 manifest는 stable ID를 유지하며 빌드마다 이름으로 ID를 다시 계산해 사용자 rebind를 끊지 않는다. 별도 C# graph-authoring DSL은 이 전환의 필수 작업에 추가하지 않는다. 임의 C# 코드를 매 틱 실행하는 scripting hook도 입력 그래프에 두지 않는다. 외부 게임 상태에 따른 허용 여부는 봉인된 입력 이후 게임플레이에서 판단한다.

타입 안전한 소비 API

GameplayInputs.Move는 Vector2 신호, GameplayInputs.Jump는 Button 신호로 생성한다. C++·C#은 세션 핸들과 현재 InputFrame으로 값을 읽고, 전체 이벤트 목록을 순회하거나 타입별 구독을 사용한다. 표시 이름 변경은 stable ID를 유지하되 이전 생성 멤버 사용을 컴파일 오류로 드러낸다. 타입 변경은 새 signal ID를 발급하는 명시 스키마 변경이며 기존 override를 검증 없이 재사용하지 않는다.

NativeAOT 네이티브 경계

생성된 signal ID·타입·offset 표와 접근자를 사용한다. 상태와 순서 있는 이벤트는 명시된 POD batch 레이아웃으로 전달하며 정렬·폭·endianness·Vector2 표현·ABI 버전을 검증한다. runtime reflection, 메서드 이름 문자열 탐색, std::any, hotpath의 임의 스크립트 호출을 기본 경로에서 제거한다.

borrowed frame/batch view는 해당 InputFrame lease가 유효한 문서화된 경계까지만 사용한다. 장기 보관은 명시 복사 API를 사용한다. native pointer를 managed 객체에 무기한 저장하지 않는다. 이벤트 용량 초과를 상태 플래그로 숨기지 않으며 trace와 gap 처리로 드러낸다.

구독 수명과 재진입

구독 토큰은 안전한 대상 객체 ID와 세션/world 세대를 포함한다. 컴포넌트 disable·파괴, world/장면 해제, 세션 종료, C# reload에서 무효화하며 늦은 batch는 세대 검사로 거부한다. 게임 dispatch는 봉인 뒤 세션 소유 스레드에서 gameplay PrePhysics 전에 수행하고 UI dispatch는 해당 UI 평가 경계에서 수행한다. 콜백 중 계층·장치·rebind 변경은 명령으로 모아 다음 입력 경계에 적용한다. dispatch 중 해제는 이후 호출부터 즉시 억제하고 새 구독은 다음 frame부터 시작한다. frame/event sequence로 동일 batch 중복 dispatch를 막는다.

구독은 상태 조회를 소진하지 않으며 구간 안의 여러 Performed 이벤트를 하나로 압축하지 않는다. 구독자 예외는 해당 호출에서 격리·기록하고 나머지 유효 구독의 배달을 계속한다. 선택적 LX 소비 노드는 같은 InputFrame을 읽거나 SignalEvent를 받는다. 입력 재평가나 별도 장치 polling을 하지 않는다.

자산 cook 리바인딩 다중 사용자

정식 자산과 게시

InputGraph를 AssetDepot의 정식 타입으로 등록하고 기존 import·save·cook·dependency·reload 경로에 연결한다. schema version, compiler version, semantic hash, 플랫폼 capability manifest, 생성 API/ABI 버전을 기록한다. cook은 누락된 source·불일치 타입·알 수 없는 node·cycle·미지원 버전을 진단하고 실패한다. shipping 런타임에서 편집 그래프를 조용히 보정하지 않는다.

source graph와 준비된 CPU 실행 데이터는 별도 수명으로 관리한다. 세션이 사용하는 불변 실행 정의는 AssetDepot lease가 유지한다. 새 정의 준비가 실패하면 마지막 유효 정의를 유지하고 오류를 표시한다. 배포 시 정의와 생성 accessor 버전이 맞지 않으면 시작을 차단한다. stale accessor로 잘못된 offset을 읽지 않는다.

리바인딩

  1. 대상 세션·stable binding ID·허용 장치/control·타입·충돌 정책으로 capture를 시작한다.
  2. 전용 입력 소유권으로 후보를 수집한다. 시작 시 이미 눌린 control과 잡음 delta는 후보에서 제외하고 neutral gate를 둔다.
  3. 사용자 확인 전에 타입·중복·충돌을 검증한다. 취소·timeout·장치 분리는 원래 binding을 그대로 유지한다.
  4. 검증된 override를 다음 입력 경계에 원자 적용하고 관련 판정을 취소한다. 원본 InputGraph는 수정하지 않는다.
  5. 사용자별 override에 graph ID·binding ID·schema/version을 저장한다. 제거된 binding은 orphan으로 표시하고 명시 복구/삭제를 제공한다.

다중 사용자와 장치 식별

InputSession은 장치 인스턴스와 연결 세대를 할당받는다. 재연결로 OS index가 바뀌어도 이전 사용자에게 자동 배정할지는 명시 정책으로 처리한다. 기본은 게임패드와 키보드/마우스의 독점 할당이다. 공유 키보드/마우스는 control 분할 또는 공유 정책을 명시해야 한다. 두 사용자가 같은 InputGraph를 써도 값·타이머·claim·override는 독립이다.

장치 변경은 소유권 기록으로 남긴다. 이전 세션의 눌림·delta·구독 이벤트가 새 사용자로 이동하지 않는다. 장치 glyph와 표시 이름은 capability·layout 식별 정보이며 신호 ID가 아니다. 키보드 물리 key 바인딩과 문자 입력은 분리하고 레이아웃 변화의 표시·저장 정책을 명시한다.

입력 이외의 인접 경계

Haptic은 장치 출력 명령 경계로 유지한다. 세션의 할당 장치와 세대를 검증하고 pause·disconnect·세션 종료 시 안전하게 중지한다. 입력 그래프의 값 평가나 InputFrame replay가 진동을 재발행하지 않는다. 문자·IME는 PT의 전용 text composition 경로로 유지하며 조합 문자열을 Button 신호로 변환하지 않는다.

기존 inputmap을 읽어 값 타입·바인딩·계층·상호작용을 InputGraph로 변환한다. asset GUID는 가능한 한 보존하고 신호에 stable ID를 부여한다. 운영 전환 절차

  1. 자산·소비자 목록을 잠그고 모든 필수 기능/acceptance gate를 통과시킨다.
  2. 변환 자산, cook, native binary, C# assembly/accessor, override migrator를 같은 릴리스 버전에 묶는다.
  3. 구 runtime·loader·callback·generated binding·등록 코드·테스트 의존을 삭제하고 clean build로 잔존 여부를 검증한다.
  4. 전체 패키지를 전환하고 초기 진단 기록에서 버전·누락·취소·장치 할당을 확인한다.
  5. 실패하면 이전 전체 아티팩트 버전으로 되돌린다. 새 엔진과 구 입력 runtime을 섞지 않는다. override는 백업본 또는 명시 downgrade 변환을 사용한다.

삭제 검색에서 일치가 남으면 무조건 실패시키지 않고 문서·변환기 입력 정의·승인된 호환 fixture인지 분류한다. 실행 가능한 legacy 의존이 남아 있으면 전환을 차단한다.

병렬화 가능한 경계

INP1과 INP2는 INP0의 record/type 계약을 고정한 뒤 병렬 진행한다. INP4는 schema fixture로 생성기를 먼저 개발할 수 있으나 INP3 결과에 연결해 완료한다. INP5와 INP6도 세션 계약 확정 뒤 병렬 진행할 수 있다. 신규 job system이나 커스텀 allocator를 도입해 이 작업의 선행 조건을 늘리지 않는다.

최소 수직 검증 묶음

처음에는 키보드 Move·Jump → 세션 → 고정 틱 InputFrame → C++/C# 소비를 끝까지 연결한다. 이후 mouse delta·pad·Hold/Tap/Chord·UI·rebind·다중 사용자·cook을 추가한다. 작은 묶음은 개발 순서일 뿐 축소된 출시 범위가 아니다.

핫패스 제약

준비 후 정상 경로에는 문자열 해석·reflection·노드 객체 탐색·그래프 compile을 두지 않는다. 세션과 batch 버퍼는 검증된 크기로 준비하고 증가·초과를 측정한다. 무할당을 요구한다면 실제 계수로 검증하고 비정상 복구 경로와 구분한다. lock-free를 목적 자체로 삼지 않으며 기존 lock·queue·job의 비용을 먼저 측정한다.

설명 가능한 trace

장치 → 사용자 → 계층 → binding → processor → interaction → claim/reject → InputFrame → 소비자까지 stable ID와 시각으로 연결한다. Jump가 안 된 이유를 source 미수신, UI 소유, 비활성 계층, rearm 대기, 타입/판정 실패, 늦은 귀속, gap으로 구분해 보여준다. 릴리스 진단은 필터와 유한 보존량을 갖고 모든 키 입력을 무제한 저장하지 않는다.

재현 보장의 경계

같은 정의·clock/policy 기록·정규화 입력·평가 규칙은 동일한 입력 결과를 재현하는 테스트 대상으로 삼는다. 원시 입력 재생과 확정 InputFrame 재생을 구분한다. 게임 replay/네트워크 경계는 게임플레이가 만든 명령이다. 입력 trace 재현만으로 물리·게임플레이의 결정성, 네트워크 rollback 또는 낮은 지연을 보장하지 않는다.
