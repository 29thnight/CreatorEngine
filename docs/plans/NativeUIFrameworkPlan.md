# 엔진 공통 UI 기반과 자체 편집기 UI 전환 계획

> 2026-10-28 수립 · 미래 계획 FUI · 현재 리팩토링 이후 · 구현 미착수 · 공수 미산정·현재 집계 제외

UTF-16 문자열, 변경 기반 레이아웃·그리기 갱신, 명시적 입력·포커스 소유권을 갖는 엔진 내부 UI 기반을 구축한다. 게임 UI와 편집기 UI는 공통 기반을 사용하되 서로 다른 Context와 수명을 갖는다. 기존 ImGui 편집기는 새 패널의 제품 수용이 끝날 때까지 유지하고, 최종 전환 뒤 직접 의존성을 제거한다.

이 문서는 미래 도입 순서와 완료 계약을 정의한다. 계획 등록은 포크 생성·엔진 코드 수정·기존 문자열 사용처 일괄 전환 또는 현재 PHASE 16·21의 중단을 뜻하지 않는다. PHASE 번호와 인일은 착수 시 다른 계획과 대조해 확정하며, FUI 항목을 현재 진행률의 분모·분자에 넣지 않는다.

## 남은 작업과 완료 판정

- 공통 UI Core의 상태·트리·레이아웃·텍스트·입력·그리기 제출 경계를 설계하고 대표 패널 하나를 실제 엔진에서 수용한다.
- 기존 ImGui와 같은 편집 동작을 비교해 기능·수명·입력·성능 기준을 통과한 패널부터 전환한다. 전체 위젯을 매 프레임 구성하는 호출 방식과 특정 내부 자료구조의 유지 여부는 별도로 결정한다.
- 게임 UI는 PHASE 16의 Scene 소유·등록·렌더 제출 계약을 소비한다. 편집기 위젯마다 Entity·Component를 만들거나 Scene의 GC 수명을 부여하지 않는다.
- 도킹·팝업·멀티윈도·저장/복구·특수 편집기를 마지막까지 수용한 뒤 ImGui 사용처와 제품 배포 의존성을 제거한다. 구조 구현, 실제 GUI 동작, 성능 수용을 각각 판정한다.

## 현재 기준선과 재사용 범위

조사 기준은 2026-10-28의 `master` HEAD `27394992c9e2d31300298ef1f3b06438c9e4b9a7` 및 당시의 미커밋·미추적 작업 트리다. 아래 파일 링크는 현재 소스를 가리키며, 해당 HEAD에 모든 로컬 변경이 커밋돼 있다는 뜻은 아니다. 착수 때 소스 해시와 사용처 수를 다시 고정한다.

| 확인한 기반 | 재사용할 계약 | 완료로 확대하지 않을 범위 |
|---|---|---|
| Scene 레이아웃의 dirty/resolved epoch | 변경 없는 경우 계산 생략, 기존 Transform 좌표·스케일 의미 | 공통 위젯 트리·최소 dirty root 처리 전체 |
| RenderScene의 값 UIDrawSnapshot | live Component를 직접 넘기지 않는 값 조회 방향 | 현재 진단용 복사 API가 최종 UI 렌더 제출 전체라는 판단 |
| EditorWindowRegistry | stable ID, 창 역할·표시 상태와 등록 정책 | 현재 `draw()` 호출의 실행 방식 자체 |
| 공통 편집 트랜잭션·명령 | Undo/Redo·직렬화·선택·Play/Stop 의미 | UI 교체를 이유로 별도 상태 정본을 만드는 것 |
| UTF-16 문자열·UTF-8 변환 캐시·입력 상태 | 기존 문자열 및 어댑터의 소유권·실패 처리 | ImGui 경계 캐시를 새 UI의 필수 중간 표현으로 고정하는 것 |
| 편집기 panel/frame cost·chrome 관측 | 기존 관측 지점과 실제 창 상태의 대조 | CPU 시간만으로 픽셀·입력·전체 프레임 개선 판정 |

주석·문자열을 제외한 당시 문법 검색에서 Editor 56개 파일에 ImGui 호출 지점 4,029개, Lattice 1개 파일에 115개가 있었다. 이는 런타임 호출 횟수·병목·확정 공수가 아니다. 직접 호출 외에 타입·매크로·확장 라이브러리·도킹 저장 형식과 테스트 소비자는 FUI0에서 별도로 조사한다.

## 적용할 구조와 경계

```text
Scene UI components → Scene adapter ┐
                                   ├→ UI Core → immutable draw snapshot → RHI adapter
Editor widgets/commands → Editor adapter ┘
OS window/input/IME → platform adapter → owning UI Context
```

공통화할 것은 알고리즘과 값 계약이다. 게임과 편집기가 포커스·캡처·창·위젯 상태를 하나의 전역 저장소에서 공유하는 구조를 만들지 않는다. 아래 이름과 디렉토리는 제안이며 구현된 API가 아니다.

| 계층 제안 | 소유하는 것 | 허용하지 않는 의존 |
|---|---|---|
| `Engine/UI/Core` | 위젯 식별·슬롯·레이아웃·스타일·클리핑·입력 규칙·텍스트 및 draw 값 계약 | ImGui, Editor, Scene의 구체 Component |
| `Engine/UI/Text` | UTF-16 문서, 문자 경계·조판·측정 캐시·글리프와 폰트 자산 연결 | 위젯별 UTF-8 사본을 정본으로 삼는 것 |
| `Engine/UI/Rendering` | draw snapshot 소비, batching, RHI 자원 pin과 완료 제출 수명 | render thread의 live 위젯/Component 역참조 |
| Scene adapter | Scene·Canvas 등록/해지·좌표 변환·게임 입력 및 저작 연결 | 편집기 창이 Scene 종료와 함께 파괴되는 결합 |
| Editor adapter | 명령·편집 트랜잭션·선택·패널·workspace 연결 | Core가 Editor 전용 저장·명령 정책을 아는 것 |
| Platform adapter | OS 창·DPI·키보드·포인터·IME·클립보드·접근성 연결 | OS 전역 입력 상태를 임의 Context가 덮어쓰기 |

## 구현 위치와 병행 검증 절차

2026-10-28 구현 방식 결정: **엔진 내부 격리 모듈을 정본으로 구현하고, 독립 테스트와 실제 ImGui 패널 비교를 병행한 뒤 수용 기준을 통과한 패널부터 제품 기본 경로로 전환한다.** 외부 라이브러리를 먼저 완성한 다음 엔진에 맞춰 이식하는 순서를 사용하지 않는다. 이 결정은 미래 계획의 실행 방식을 확정하며 구현 착수나 현재 기본 UI 변경을 뜻하지 않는다.

### 엔진 내부 정본과 선택적 연결

구현 정본은 제안한 `Engine/UI` 계층에 둔다. 독립 테스트 실행 파일과 편집기 비교 호스트는 같은 모듈·소스·공개 계약을 참조하며 테스트용 구현 복사본을 만들지 않는다. 별도 실행 파일이나 솔루션은 빌드·실험 경계일 뿐 별도 구현 정본이 아니다.

새 모듈은 명시적으로 선택해 빌드·연결할 수 있도록 격리하고, Core가 기존 ImGui 또는 편집기 셸에 의존하지 않도록 한다. 초기부터 엔진의 컨테이너·할당·문자열·RHI·플랫폼 입력 및 수명 계약을 사용한다. 실험 모듈을 연결하는 것과 기존 패널을 대체해 기본 활성화하는 것은 별도 단계다. 미수용 패널은 기존 ImGui를 기본 경로로 유지한다.

### 세 검증 경로

| 경로 | 검증 대상 | 단독 통과로 주장하지 않을 범위 |
|---|---|---|
| 독립 테스트 실행 파일 | 핸들·소유권·삭제·레이아웃·dirty 전파·문자 경계·가상화·할당과 고의 결함 | 실제 OS IME·엔진 렌더 출력·편집기 기능·전체 성능 수용 |
| 엔진 내 실험 UI 화면 | 실제 RHI·폰트·클립·DPI·창·플랫폼 입력·한글 IME·GPU 자원 수명 | 기존 편집 패널과의 기능 동등성 또는 기본 경로 전환 |
| 실제 편집기 패널 A/B | 같은 모델·명령·Undo/Redo·동작의 기능·입력 지연·CPU/GPU·메모리·전체 프레임 | 측정하지 않은 다른 패널·장면·OS의 수용 |

독립 테스트는 Core 구현과 함께 추가하고, 렌더·입력 연결이 가능한 시점부터 실제 엔진 검증도 함께 진행한다. 독립 테스트만으로 UI 라이브러리 전체를 완성한 뒤 엔진에서 처음 검증하는 순서를 피한다.

### 기준선부터 패널 전환까지

1. FUI0에서 기존 ImGui의 대표 화면·데이터·동작과 빌드/하드웨어·해상도·DPI를 고정한다. 정적 화면, 단일 속성 변경, 대형 목록 스크롤, 연속 텍스트 입력·IME를 포함한다.
2. FUI1~3에서 Context·핸들·수명, 텍스트/레이아웃, RHI 제출, 버튼·스크롤·입력 필드의 작은 수직 구현을 만든다. 도킹과 전체 위젯 카탈로그 완성을 선행시키지 않는다.
3. FUI4의 첫 비교 후보는 기본 속성 패널 일부로 둔다. 숫자·체크박스·UTF-16 이름 입력·접기·스크롤·Undo/Redo를 포함한다. 후보 변경은 FUI0의 대표성·비교 가능성 근거와 함께 기록한다.
4. 기존 ImGui 패널과 신규 패널은 같은 원본 모델·명령·편집 트랜잭션을 사용한다. 경로별로 재현 가능한 동등 상태를 준비하며, 동시에 모델을 수정하거나 입력을 소비하지 못하게 한다. 표준 A/B 측정은 두 경로를 교대로 단독 실행한다. 나란히 표시하는 진단 실행은 성능 판정과 구분한다.
5. 기능·수명·입력·렌더·성능 기준을 모두 통과한 패널만 기본 경로로 승격한다. 각 후속 패널도 동일한 개별 게이트를 통과해야 하며 대표 패널 통과를 전체 전환 허가로 사용하지 않는다.
6. 승격 초기에는 패널별 기존 경로 복귀를 유지하고 복귀 동작도 검증한다. 도킹 셸·멀티윈도·특수 편집기는 후속 단계에서 전환한다. 전체 동등성과 최종 제품 회귀를 수용한 FUI8에서 기존 경로 및 ImGui 의존성을 제거한다.

패널별 수용 기록에는 소스·바이너리·fixture 신원, 두 경로의 기능 결과·원시 계측·실패 내역, 입력/모델 소유자, 기본 경로 상태와 복귀 가능 여부를 남긴다. CPU 단독 마이크로벤치나 독립 테스트 통과를 실제 편집기 패널 전환 판정으로 대신하지 않는다.

## 채택 방향과 대안

| 방안 | 평가와 적용 범위 |
|---|---|
| ImGui를 UTF-16 및 보관형 위젯 시스템으로 완전 개조 | 기존 컨트롤을 활용할 수 있으나 Begin/End·ID stack·동기 반환값·활성 입력·도킹 의미까지 바꾸면 소비자 전환과 upstream 충돌을 함께 관리해야 한다. 주 경로로 채택하지 않는다. |
| 엔진 내부 공통 기반과 자체 편집기 위젯 | 장기 정본으로 채택한다. 자체 컨테이너·할당·핸들·렌더 수명 정책을 적용하고 PHASE 16과 공통 기반을 나눈다. 초기 기능 구축과 제품 동등성 수용 비용은 별도 부담이다. |
| 기존 ImGui를 유지한 단계적 혼용 | 전환기 경로로 채택한다. 기존 셸에서 새 패널을 호스팅하되 입력·포커스·자원 소유자를 명시한다. 영구적인 이중 위젯 체계로 종료하지 않는다. |

Immediate Mode API가 내부 캐시를 금지하는 것은 아니다. 선언형·즉시 호출형 API 중 어느 형태를 제공할지는 Core의 invalidation·수명 계약과 분리한다. Slate는 설계 참고 대상이며 Unreal 소스·컨테이너·수명 모델을 그대로 도입하지 않는다.

Dear ImGui의 MIT 라이선스는 수정·배포를 허용하되 원 저작권·허가문 유지 조건이 있다. 제한적 포크나 코드 재사용이 생기면 출처·버전·패치·고지를 기록한다. 별도 UI 프레임워크를 사용하지 않는다는 범위와 폰트 래스터라이저·조판·OS API 의존성의 범위는 구분한다. 폰트 파싱·Unicode 전체를 새로 구현하는 작업을 암묵적으로 포함하지 않는다.

## 필수 계약

### 소유권과 수명

- Context가 위젯 저장소와 루트를 소유한다. 장기 참조는 Context 신원과 generation을 포함한 핸들로 검증하고, 주소 재사용이 옛 입력·콜백을 새 위젯으로 보내지 못하게 한다.
- 제거 시 입력 캡처·포커스·타이머·구독을 먼저 해제하고 트리에서 분리한다. 메모리 회수와 GPU 자원 해제는 각각의 완료 조건 뒤에 수행한다. 순회·콜백 중 제거는 명시적 지연 큐를 사용한다.
- 소유 콜백은 `ce::owned_func` 또는 `ce::unique_func`의 복사·이동 계약을 따른다. `ce::func_ref`는 동기 호출 범위에만 사용하고 저장하지 않는다. 위젯과 콜백의 상호 강한 소유 사이클을 만들지 않는다.
- 조회·hit test·핸들 해석·워밍된 불변 프레임에서 추가 래퍼/컨테이너 할당을 하지 않는다. 생성·새 글리프·용량 확장은 별도로 계측한다. 해지/삭제 뒤 소유 자원은 정해진 시점에 반환한다.

### 변경과 레이아웃

- hierarchy/layout/paint/text/resource/input 변경 이유와 의존 범위를 분리한다. 최소 dirty root를 처리하고 같은 프레임의 중복 무효화를 합친다. 입력에서 생긴 변경은 명시된 프레임 단계에서 적용한다.
- 캐시는 원본 revision과 폰트·스타일·DPI·viewport·클립·장치/자원 세대를 검증한다. 호출자 임시 버퍼의 주소를 캐시 신원으로 사용하지 않는다.
- 목록·트리는 보이는 행과 명시한 overscan만 구성·배치한다. 전체 데이터의 위젯 생성 또는 매 프레임 내용 비교로 가상화 효과를 없애지 않는다.
- 뷰포트·커서·선택 강조·애니메이션·타임라인은 동적 영역을 선언한다. 정적 형제까지 갱신하지 않으며 최적화 때문에 시간이 진행되는 표현을 멈추지 않는다.

### UTF-16 텍스트와 입력

- 공개 문자열 계약은 `char16_t` 기반 `ce::string`·`ce::string_view`다. 플랫폼별 `wchar_t` 폭을 공통 인코딩으로 삼지 않는다. 파일·클립보드·기존 ImGui 등 외부 경계의 변환 위치와 소유자를 명시한다.
- UTF-16 코드 단위·Unicode scalar·사용자 문자 묶음·glyph 위치를 구분한다. 서로게이트, 결합 문자, 양방향 텍스트, fallback 폰트, 줄바꿈과 선택/검색 위치를 동일한 Text 계약에서 처리한다.
- IME 조합 문자열과 확정 문서를 분리한다. 조합 중 외부 모델 변경·포커스 이동·위젯 제거·Undo/Redo의 확정/취소 규칙을 정의하고 한글 실제 OS IME로 검증한다.
- 혼용 기간에는 포인터·키보드·텍스트·IME 이벤트마다 소비 Context를 한 곳으로 정한다. ImGui와 새 UI가 같은 이벤트를 중복 처리하지 못하게 한다. 새 위젯의 ID는 표시 문자열과 분리한다.

### 렌더와 스레드

- UI 상태 변경과 입력은 Context 소유 스레드가 직렬화한다. 작업 스레드의 조판·메시 계산은 불변 입력과 revision을 사용하고, 오래된 결과는 버린다.
- draw snapshot은 좌표·클립·정렬·글리프/도형 값과 세대 검증 자원 참조를 보유한다. draw data의 프레임 임시 포인터를 다음 프레임에 재사용하지 않는다.
- RHI adapter가 폰트 atlas·텍스처·버퍼를 실제 제출 완료까지 pin한다. 이전 제출 실패·취소·resize·장치 재생성에서도 살아 있는 제출의 자원이 먼저 반환되지 않게 한다.
- CPU 레이아웃/메시 캐시와 렌더 타깃 캐시는 구분한다. geometry 재사용만으로 GPU raster·draw call·Present가 감소했다고 판정하지 않는다.

### 측정과 제안 예산

다음 수치는 **착수 전 확정할 초기 제안**이며 실측 성능·보장치가 아니다. FUI0에서 대표 workload와 측정 해상도를 확인해 동결한다. 이후 실패를 통과시키기 위해 기준을 완화하지 않으며 변경이 필요하면 사유와 재기준선을 남긴다.

| 조건 | 초기 수용 제안 |
|---|---|
| 공통 표본 | 고정 HW/OS·빌드·해상도·DPI·콘텐츠에서 기존/신규 순서 교대 최소 3회. warm 조건은 회당 최소 300프레임, cold 시작은 별도 최소 10회. p50/p95/p99·최악값·메모리·할당·dirty/visible 개수 공개 |
| 정적 예열 패널 | UI CPU 중앙값 기존 대비 20% 이상 감소, p95 증가 없음. 달성하지 못하면 효율성 수용은 보류하고 FUI4에서 원인 재검토 |
| 동적·스크롤·입력 | UI CPU·입력 반영 지연·전체 프레임 p95가 각각 기존의 1.05배 이하. 작은 값의 계측 오차/절대 허용치는 FUI0에서 미리 확정 |
| GPU와 전체 제품 | UI GPU p95 및 전체 프레임 p95가 각각 기존의 1.05배 이하. CPU 캐시 성과와 별도로 draw·upload·Present 대기·최종 화면을 확인 |
| 할당·삭제 | 10,000회 워밍 조회와 300프레임 불변 반복의 UI 관리 할당 증가 0. 제거 후 CPU 소유 객체 잔여 0, GPU는 완료 제출 뒤 소유 pin 잔여 0 |
| 가상화 | 10,000개 항목 fixture에서 구성/배치 위젯 수가 실제 visible+동결한 overscan 한도 이내. 프레임마다 전체 항목의 위젯 생성 금지 |
| 메모리 | live/peak·cache·atlas·retained geometry·렌더 타깃·할당/해제량 공개. FUI0에서 workload별 상한 동결 후 그 이내. CPU 개선만으로 무제한 캐시를 수용하지 않음 |

성능 측정과 GPU validation·ASan·고의 결함 실행은 분리한다. 표본·실패·측정 순서·진단 상태·소스/바이너리 해시를 보존하고, 유리한 패널/표본만 합쳐 전체 통과로 판정하지 않는다. 전체 Editor 성능과 특정 패널 CPU 개선을 구분한다.

## 검증 경계

이번 산출물은 계획 문서와 미래 색인 등록이다. 소스 기준선·계획 소유 경계·상대 링크·생성 HTML을 확인하며 엔진 코드를 변경하지 않는다. 자체 UI·ImGui 포크·성능 우위·다른 OS 입력 수용을 구현 또는 실측 완료로 표시하지 않는다. 기존 컨테이너·문자열·편집기 실행 수용 기록은 각 원래 소스와 바이너리에 한정한다. 향후 FUI0에서 최신 기준선을 확보한 뒤 단계별 제품 산출물로 완료를 판정한다.
