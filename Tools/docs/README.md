# 문서 사이트 빌드와 링크 검사

저장소 루트에서 `npm run build`를 실행한다. 링크 회귀 검사, Vite 빌드, 전체 배포 파일·링크 검사를 순서대로 수행하며 하나라도 실패하면 빌드가 실패한다. 기존 배포본만 다시 검사하려면 `npm run docs:verify`를 사용한다.

Markdown 문서는 `render-markdown-docs.mjs`로 HTML을 생성한다. 별도 `.src.html`이 있는 페이지는 해당 원본과 전용 생성기를 사용한다.

`document-links.mjs`가 문서 링크를 분류한다.

- 사이트 문서는 배포 루트 안의 상대 주소로 연결한다.
- 저장소 소스와 F# 도구 문서는 `document-link-policy.json`의 고정 GitHub 리비전으로 연결한다. 이는 소스 열람 기준이며 과거 측정의 소스 신원을 대체하지 않는다.
- `Build`, `Artifacts`, F# 도구의 `artifacts` 기록은 로컬 경로와 쿼리·앵커를 텍스트로 보존한다. 사이트에 파일이 포함되지 않는다는 점을 표시하며 다운로드 링크를 만들지 않는다.
- 실제로 없는 문서는 검사에서 제외하지 않는다. 배포 루트를 벗어난 링크는 로컬 파일이 존재하더라도 실패한다.

엔진 배선 감사 페이지는 동적으로 생성하는 소스 링크도 고정 리비전을 사용한다. 현재 스냅샷에서 제거된 파일 3개는 감사 원장의 기존 baseline 리비전으로 연결한다. JSON의 관찰값과 파일 해시는 수정하지 않는다.

새 소스 링크를 추가할 때에는 고정 리비전에 파일이 있는지 확인한다. 링크를 맞추기 위해 로컬 검증 기록을 Git이나 배포 디렉터리에 복사하지 않는다.
