# Offline physics schema migration

Run with Python and PyYAML (validated with PyYAML 6.0.3), with the Editor closed.

```powershell
python Tools/regression/migrate-physics-schema.py --project Dynamic_CPP --backup-dir Build/Obj/Phase19M1/Backup
```

Dry-run is the default. `--apply` publishes only after all Scene/Prefab inputs pass preflight. Any diagnostic returns exit 2 and prevents all publication. Each successful publication keeps exact original asset bytes, layer-catalog bytes, SHA-256 pairs and component-to-shape mappings in a ZIP. Partial publication failure restores written assets. Asset `.meta` files are untouched. Converted YAML formatting is canonicalized; documents requiring no conversion remain byte-identical.

The implementation supports Box/Sphere/Capsule compound shapes, explicit static bodies for standalone colliders, and static/dynamic/kinematic Rigidbody conversion. Existing body instance IDs are preserved. Collider instance IDs become ShapeIds; a standalone collider's instance ID also identifies the new body. File/prefab UUIDs remain unchanged. Legacy type UUIDs are replaced by the new Body type UUID and retained in the mapping report. New inertia follows explicit body mass, with prior density recorded as provenance.

Legacy solver limit fields have no new authored equivalent. By default they block conversion. `--reset-legacy-limits` explicitly accepts removal only of exact legacy default values; custom values still block. Locks/velocities absent from old serialization cannot be recovered and are reported as initialized defaults. No runtime fallback is added.

Capsule conversion preserves the old static X-axis/stored half-height and dynamic or kinematic Y-axis/stored height divided by two. Static shapes use a local -90 degree Z rotation to cancel the new API's Y-axis convention. Capsule conversion requires unit scales throughout the asset and zero position/identity rotation offsets; other compositions block publication.

CCT conversion requires `--character-policy` with a reviewed SHA-256 of the old CCT and its collider-free companion Rigidbody. The policy explicitly selects input speed, braking, discarded damping/rotation and carrier retirement. Input and rotation remain external gameplay responsibilities. Limited typed overrides preserve Rigidbody mass/linear damping/gravity and CCT radius/height when their values match the reviewed effective source. Other overrides, mesh, terrain, ragdoll, asset-linked colliders and references to retired components block publication. Reference closure includes other Scene/Prefab assets, and the complete inspected corpus is rechecked before writing. `--baseline-seconds` adds source-hashed CCT unit proposals and unresolved-policy diagnostics to the report; it never authorizes CCT writes. Cooked outputs must be rebuilt; this tool does not edit packages. Current product data must pass native load/cook/product acceptance before M1 is complete.

Explicit recovery bindings can be checked with `validate-physics-geometry-migration-policy.py --project <project> --policy <json>`. Schema 1 requires bindings of authoring/source/geometry/geometryMeta `{path,sha256}`, componentId/componentSha256/supplierSha256 and geometryUUID/geometryRevision/geometryKind. Paths remain inside the project. The validator checks pinned legacy component and one supplier, file hashes, CECG v1 checksum, matching metadata and convex (0) / heightfield (2) identity. It is read-only and reports `identity_bound_native_validation_pending`. It does not prove source-to-shape equivalence, decode every source payload or run SDK cooking; material/pose/scale/cook choices and product acceptance remain required.

Native validation: `verify-physics-geometry-migration-native.ps1 -Configuration Release -GeometrySource <cegeometry>` decodes with the engine codec, cooks via PhysX and imports the cooked blob. It writes a geometry/executable-hashed receipt. Pass one or more `--native-receipt <receipt.json>` to the policy validator to require matching native evidence. This advances only source cook/import status; material/pose/scale, source equivalence, shape conversion and product acceptance remain pending. The offline regression uses synthetic receipts by default; `verify_physics_schema_migration.py --native-receipt <receipt.json>` checks the actual dagger receipt.

Shape conversion is now available through `migrate-physics-schema.py --geometry-policy <json> --native-receipt <receipt>`. Each binding additionally requires `shapePolicy` with localPosition/localRotation/geometryScale, staticFriction/dynamicFriction/restitution and an explicit sourceSelection description. Source pose must match; all owner/ancestor scales must be unit. Mesh accepts reviewed convex material; Terrain requires standalone static solid and identity rotation. Unknown legacy fields, independent disabled shapes and asset links block. Dependency hashes are rechecked before publication. The converter writes shape kind 3/5 and geometry UUID/revision while preserving body/shape identity. Ragdoll and geometry overrides remain unsupported. Python conversion fixtures do not prove model/height source equivalence. Current validation: 112 Python checks with actual dagger native receipt, Release generated convex YAML parser 56 checks. Actual authoring project geometry apply/cook/Player acceptance remains pending.

Static GLB source equivalence can be checked with `verify-physics-glb-geometry-source.py --source <glb> --geometry <cegeometry> --output <receipt.json>`. It uses the bounded static/identity-node extractor, packs the resulting left-handed metre positions as float32 and compares the sorted byte records to the CECG convex input. Animated/transformed/multiple-node inputs remain unsupported. This verifies source points, not the cooked hull topology. A changed point with a recomputed valid CECG checksum is rejected. `build-physics-dagger-player-fixture.ps1 -MigratedScene <creator>` packages a converted Scene while preserving the existing fixture GUID and probe; its receipt records the supplied Scene hash.
