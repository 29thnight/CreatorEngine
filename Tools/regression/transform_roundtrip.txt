# 트랜스폼 값 왕복 시나리오 (SceneGraphRedesignPlan §4 트랙 S — S1-b 선행 게이트)
#
# ── 이 시나리오가 메우는 구멍 ──
#
# 역직렬화기는 모르는 키를 조용히 무시한다. 스키마에서 필드를 옮기면 그 값은
# 에러 하나 없이 사라진다. 그런데 기존 회귀 세트에서 값을 실제로 대조하는 검사는
# UI 전용인 verify-authored-rects 하나뿐이고, prefab_roundtrip은 인스턴스 개수만 센다.
#
# 즉 "트랜스폼 값이 저장·로드를 건너는가"를 재는 자가 없었다. S1-b가 Transform을
# 컴포넌트 블록으로 옮기면서 승격 경로를 한 곳이라도 빠뜨리면 씬 전체의 위치가
# 무너지는데, 그걸 통과시키게 된다.
#
# ── CLI 저작으로 이전 (2026-08-20, 자산·게이트 CLI 이전) ──
#
# 예전에는 저작 자산 Test1.creator(68 노드)를 scene.switch로 열어 그 값을 재료로
# 썼다. 저작 자산은 전부 폐기 대상이므로(§0.05) 그대로 두면 폐기와 함께 이 자가
# 죽는다. 이제 씬을 **CLI로 그 자리에서 저작**한다 — {{AUTHOR_BLOCK}}은 검사
# 스크립트가 생성해 채우는 object.create/parent/transform 명령 묶음이다.
#
# 자산 의존을 끊는 것 말고도 얻는 것이 있다: 값을 **내가 정하므로** 무엇이
# 어긋났는지 바로 읽힌다. 저작 씬의 값 분포는 우연히 단조로울 수 있고(같은 값이
# 반복되면 자리가 뒤바뀌어도 다이제스트가 같다), 그것을 확인할 방법도 없었다.
# 생성 규칙은 오브젝트마다 **서로 다른** 위치·회전·크기를 준다(검사 스크립트 주석).
#
# 경로는 실행 직전에 검사 스크립트가 채운다({{TMP_SCENE}}).
# 절대 경로를 여기 박으면 다른 작업 폴더에서 조용히 실패하고, 그 실패는 종료
# 코드가 아니라 '오브젝트 3개'처럼 엉뚱한 통과로 나타난다(실측: 상대 경로로
# 적었더니 scene.switch가 조용히 실패해 기본 씬을 재고 있었다).
