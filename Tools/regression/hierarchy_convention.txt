# 계층 표기 불변식 시나리오 (SceneGraphRedesignPlan 트랙 E — 루트 규약 통일)
#
# ── 불변식 ──
#
#   자식이 부모의 m_childrenIndices에 실린다  ⟺  자식의 m_parentIndex가 그 부모다
#
# 이 쌍이 어긋나면 순회가 서브트리를 통째로 빠뜨린다 — 순회는 씬 루트의
# childrenIndices에서만 내려가므로 고리 하나가 끊기면 그 아래가 전부 사라진다.
# 에러도 로그도 없이. (뼈 61개가 순회 밖에 있던 결함과 같은 축이다.)
#
# ── CLI 저작으로 이전 + 측정 지점 이원화 (2026-08-20) ──
#
# 예전에는 저작 씬 둘(Test1 68 · FT_Material 15)을 scene.switch로 열어 쟀다.
# 그 방식에는 **구조적인 사각지대**가 있었다:
#
#   저작 씬은 **로드 경로를 타서 이미 정규화된 값**이다. SceneManager의 리맵이
#   두 표기를 특수 처리해 메운다. 그래서 "저장된 자산이 규약을 지키는가"는
#   재지만, **생성 경로가 규약을 지키는가**는 원리적으로 볼 수 없었다.
#
# 실제로 그 사각지대에 결함이 살아 있었다 — Scene::CreateGameObject가 부모
# 미지정일 때 m_parentIndex를 -1로 두고 루트 children에는 넣었다(커밋 2cc6fecf).
# 저작 자산만 재는 동안에는 한 번도 드러나지 않았고, 트랜스폼 왕복 게이트를 CLI
# 저작본으로 옮기다 "저장 전 -1 · 재로드 후 0"이라는 모습으로 잡혔다.
#
# 그래서 이제 **네 지점**에서 잰다 — 깊은 계층과 넓은 계층 각각에 대해:
#
#   ① 갓 만든 직후  ← 생성 경로를 직접 잰다. 위 결함이 사는 자리였다.
#   ② 저장·재로드 후 ← 로드 경로. 예전 게이트가 재던 것과 같은 축이다.
#
# 저작 명령({{DEEP_AUTHOR}}·{{WIDE_AUTHOR}})은 검사 스크립트가 생성해 채운다.
#
# 판정: 네 지점 모두 최상위(-1표기)·쌍불일치·고아·순회미도달이 전부 0.
