# CameraComponent 래퍼 회귀 (W2).
#
# 사용법:
#   CreatorEditor.exe --script ..\..\scripts\camera_script_probe.txt
#   (Tools\regression\verify-camera-script.ps1 이 이 파일을 부른다)
#
# ── 무엇을 재현하는가 ──
#
# 저작 자산에 CameraComponent가 20개 있는데 스크립트에서 만질 길이 없었다.
# 있던 것은 핸들을 받지 않는 전역 질의 셋(Camera_PrimaryExists ·
# GetScreenSize · WorldToScreenPoint)뿐이라 "이 오브젝트의 카메라"라는 축이
# 아예 없었다. W2에서 컴포넌트 축을 열었고 이 시나리오가 그것을 태운다.
#
# ── LightComponent 회귀와 다른 점 ──
#
# 카메라에는 dirty 축이 없다. 렌더 프록시를 쓰지 않고(Scene.cpp의 프록시 Kind
# 열거에 Camera가 없다) 매 프레임 CaptureFrameSnapshot으로 읽히므로, 값을
# 넣으면 다음 프레임에 그대로 반영된다. 그래서 프로브의 자기 판정이 게이트의
# 전부이고, light.proxy 같은 누계 관측이 필요 없다.
#
# 대상은 에디터가 코드로 만드는 기본 씬의 "Main Camera"다(EditorMain.cpp의
# newSceneCreatedEvent). 저작 씬을 열지 않는 이유는 light_script_probe.txt에
# 적어 뒀다 — --script 헤드리스는 렌더 프레임이 거의 돌지 않는다.

# 기본 씬이 서고 카메라가 등록될 때까지 기다린다.
wait 60

# 이름에 공백이 있지만 따옴표로 묶지 않는다 — script.add는 마지막 토큰을
# 타입으로 보고 그 앞 전체를 이름으로 쓴다(따옴표를 쓰면 그것까지 이름에 들어간다).
script.add Main Camera CameraScriptProbe
wait 10

# 프로브의 OnInitialized는 재생에서 온다(2026-09-05 — 편집 모드에서는 훅이 오지 않는다).
play
wait 20

script.invoke CameraScriptProbe Results
log.flush
quit
